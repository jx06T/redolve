# 公式渲染與短錯因

日期：2026-11-03。新增共用顯示與提示詞規則，不需要 migration 或模型配置變更。

## 顯示格式

- 題文、選項、答案、已採用錯因、訂正重點、重作歷史、報告、題目引用與追問共用 `RichText`。編輯欄位仍保留原始文字。
- Markdown 支援段落、強調、清單與表格；行內公式採 `$...$`，獨立公式採 `$$...$$`。相容已有的 `\(...\)`／`\[...\]` 分隔符，程式碼內容保留字面文字，不猜測或改寫未加標記的純文字公式。
- 使用 react-markdown、remark-math、remark-gfm 與 rehype-katex。依賴與 KaTeX 字型從本地建置提供，不使用公式 CDN；正式 Service Worker 會預快取引擎、樣式與字型。
- 渲染器按需載入並 memo，純文字不進 Markdown 管線。過長的獨立公式、表格可在內容內水平捲動。公式含錯誤時保留可讀來源，不讓整頁崩潰。
- 不解析原始 HTML、不載入 Markdown 外部圖片；KaTeX 維持 `trust: false` 並限制巨集展開與尺寸。文字連結另開頁面，報告引用繼續由 app 依題目 ID 渲染。
- 格式處理只發生在顯示階段，不修改題目版本、答案或歷史判分依據。

## AI 錯因格式

上傳辨識與訂正整理共用 `worker/services/ai/learningPromptRules.ts`，與模型分離：

- 每項一個具體知識點或遺漏步驟，通常 8～24 個中文字，必要術語可較長。
- 使用能在同考點其他題沿用的短語，例如「不熟悉內積分配律」「忽略參數範圍限制」「不熟悉半角公式」。這些是格式範例，不是預設分類或固定選項。
- 不包含本題數字、選項、長篇依據與推導，不只寫「粗心」「觀念不清」。相近錯因合併，有依據才提出；資料不足可留空。
- 錯因仍由使用者勾選同意，詳細訂正內容留在訂正重點。報告標題也採簡短考點／錯因，完整依據與建議放在解釋。
- 題幹不重複 options，識別用的選項 ID／label 與引用 ID 不加格式。數學內容存於題文、選項 text 與答案 text，遵守 JSON 反斜線跳脫。
- 訂正提示版本為 `correction-v3`。舊的已確認資料不自動改寫或批次重新呼叫 AI，後續手動整理才使用新規則。

瀏覽器使用模擬資料驗證 1280／390px 題文、五個公式選項、複選、自動判分、答案顯示、報告展開／收起、表格與獨立公式。這些是渲染與操作驗證，不是新提示詞的真實題庫辨識準確率評測。
