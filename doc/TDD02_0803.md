## 1. 系統概述 (System Overview)

Redolve 是一款專為 iPad + Apple Pencil 深度最佳化的 Serverless PWA 錯題本系統。主打「心流式刷題（無縫滾動）」、「雙手協同手勢」與「AI 自動化標籤」。系統全面採用 Cloudflare 邊緣運算生態系，並導入標準 SaaS 多使用者驗證架構，實現跨裝置安全存取與資料完全隔離。

### 1.1 核心技術堆疊 (Tech Stack)

| 層級 | 技術選型 | 說明 / 備註 |
| :--- | :--- | :--- |
| **前端 (Frontend)** | React 18, Vite (SPA), TypeScript, Tailwind CSS, Zustand, `@tanstack/react-virtual` | 效能優化與虛擬列表 |
| **繪圖引擎 (Canvas)** | HTML5 原生 `<canvas>` + `perfect-freehand` | 支援向量點位 + 局部擦除遮罩 |
| **離線快取 (PWA Storage)** | Service Worker + IndexedDB | 離線筆跡佇列與無感自動背景同步 |
| **後端 API (Backend)** | Cloudflare Workers (Hono Framework) | Edge Runtime |
| **資料庫與儲存** | Cloudflare D1 (SQLite) + Cloudflare R2 | 關聯式資料與物件儲存 |
| **課綱快取 (Taxonomy Cache)** | Cloudflare KV | 快取課綱分類樹，減少 D1 查詢 |
| **身分驗證 (Auth)** | better-auth (Google OAuth) + 自建 API Key Middleware | 雙軌驗證機制 |
| **AI 整合 (AI)** | Google Gemini 2.5 / 3.5 Flash API (透過 AIService 抽象層) | Structured Outputs 視覺辨識 |

## 2. 身分驗證與安全架構 (Auth & Security)

### 2.1 雙軌驗證機制 (Dual Auth Architecture)

系統採用**雙軌驗證機制**，以服務不同的客戶端需求：

1. **PWA 網頁端 (人類操作)**：透過 Google OAuth 登入。前端依賴 Session / HTTP-only Cookies 進行驗證，確保 iPad Safari 上的存取安全。
2. **iOS 捷徑端 (機器自動化)**：使用靜態 API Key。使用者在 PWA 後台生成一組專屬 API Key，並填入 iOS 捷徑的 HTTP Header (`Authorization: Bearer <API_KEY>`) 中。
3. **資料隔離 (Multi-tenant Isolation)**：所有對 D1 資料庫的 CRUD 操作，皆須透過 Hono Middleware 攔截並解譯出 `user_id`，所有 SQL 查詢強制附加 `WHERE user_id = ?` 條件。
4. **唯讀分享 Token (Share Token Security)**：產生的分享連結採用加密短 Token `/share/:token`，獨立處理存取權限 (允許/隱藏筆跡、有效期限)，無需暴露內部 `/api/problems/:id` 端點即可實現同學免登入安全檢視。

### 2.2 API Key 安全強化 (v2.0.0 新增)

> **變更動機**：v1.0.0 的 `api_keys.key` 欄位明文儲存 Key 字串。若 D1 備份外洩，所有 Key 即全數暴露。

**採用策略：DB 層 Hash 儲存**

- 生成時以 bcrypt / argon2id 雜湊，**明文 Key 僅在生成當下顯示一次**，之後永不可再取得。
- 資料庫僅存 `key_hash` 與供顯示用的 `key_prefix`（`rdv_xxxxxxxx****`）。
- 認證時取出該使用者所有 Hash 逐一比對（每用戶 Key 數量極少，效能可接受）。

```typescript
// Worker: 生成 API Key
const rawKey = `rdv_${crypto.randomUUID().replace(/-/g, '')}`;
const hashed = await bcrypt.hash(rawKey, 10); // 或 argon2id

await db.insert(api_keys).values({
  key_hash:   hashed,
  key_prefix: rawKey.slice(0, 12) + "****",  // 供 GET /api/keys 打碼顯示
  user_id,
  description,
});
// rawKey 僅回傳給前端一次，之後丟棄

// Worker: 認證 API Key
const keys = await db.select().from(api_keys).where(eq(api_keys.user_id, uid));
const isValid = await Promise.any(
  keys.map(k => bcrypt.compare(incomingKey, k.key_hash))
).catch(() => false);
```

## 3. 資料庫綱要設計 (Database Schema - Cloudflare D1)

### 3.1 完整 Schema (v2.0.0)

```sql
-- 使用者帳號表 (Google OAuth 寫入)
CREATE TABLE users (
    id         TEXT PRIMARY KEY,          -- UUID
    email      TEXT UNIQUE NOT NULL,
    name       TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- API 授權金鑰表 (供 iOS 捷徑使用)
-- v2.0.0 變更：key 欄位改為 key_hash + key_prefix，不再明文儲存
CREATE TABLE api_keys (
    key_hash    TEXT PRIMARY KEY,         -- bcrypt / argon2id 雜湊值
    key_prefix  TEXT NOT NULL,            -- 打碼顯示用，ex: "rdv_a1b2c3d4****"
    user_id     TEXT NOT NULL,
    description TEXT,                     -- ex: "iPad 捷徑專用"
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 課綱分類樹表 (v2.0.0 新增，取代 items.subject / items.topic 純文字欄位)
-- 層級：level 0 = 科目, level 1 = 單元, level 2 = 子主題 (選用)
CREATE TABLE taxonomies (
    id        TEXT PRIMARY KEY,           -- ex: "math-probability-conditional"
    parent_id TEXT,                       -- NULL 表示根節點 (科目層)
    label     TEXT NOT NULL,             -- 顯示名稱，ex: "條件機率"
    level     INTEGER NOT NULL,           -- 0 | 1 | 2
    FOREIGN KEY(parent_id) REFERENCES taxonomies(id)
);

-- 錯題/筆記主表
-- v2.0.0 變更：新增 topic_id FK、vector_clock、updated_at；保留 subject/topic 作為 migration 緩衝
CREATE TABLE items (
    id           TEXT PRIMARY KEY,
    user_id      TEXT NOT NULL,           -- 多租戶資料隔離關鍵
    type         TEXT NOT NULL,           -- 'problem' | 'note'
    subject      TEXT,                    -- v1 遺留欄位，migration 完成後廢棄
    topic        TEXT,                    -- v1 遺留欄位，migration 完成後廢棄
    topic_id     TEXT,                    -- FK -> taxonomies.id (v2 正式欄位)
    keywords     TEXT,                    -- JSON Array，原始完整關鍵字供顯示
    keyword_tokens TEXT,                  -- 空格分隔的細粒度 token 字串，供 FTS5 索引
    source       TEXT,
    image_url    TEXT NOT NULL,
    draw_data    TEXT,                    -- 向量筆跡與局部擦除遮罩 JSON
    status       TEXT DEFAULT 'processing', -- 'processing' | 'unsolved' | 'resolved'
    review_count INTEGER DEFAULT 0,
    vector_clock TEXT,                    -- JSON: {"clientId": "uuid", "seq": 42}
    updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id)  REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY(topic_id) REFERENCES taxonomies(id)
);

-- 分享金鑰表 (供唯讀分享使用)
CREATE TABLE shares (
    token      TEXT PRIMARY KEY,          -- 短網址加密 Key (ex: st_abc123)
    item_id    TEXT NOT NULL,
    user_id    TEXT NOT NULL,
    allow_ink  INTEGER DEFAULT 1,         -- 1: 包含筆跡, 0: 隱藏筆跡
    expires_at DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(item_id) REFERENCES items(id) ON DELETE CASCADE
);

-- 查詢效能最佳化索引
-- v2.0.0 新增 idx_user_created 作為 cursor-based 分頁的主要索引
CREATE INDEX idx_user_subject_topic ON items(user_id, subject, topic);
CREATE INDEX idx_user_status        ON items(user_id, status);
CREATE INDEX idx_user_topic_id      ON items(user_id, topic_id);
CREATE INDEX idx_user_created       ON items(user_id, created_at DESC, id DESC);

-- FTS5 全文檢索虛擬表
-- v2.0.0 變更：keywords 欄位改為 keyword_tokens（細粒度空格分隔 token），解決中文模糊搜尋
CREATE VIRTUAL TABLE items_fts USING fts5(
    id             UNINDEXED,
    user_id        UNINDEXED,
    subject,
    source,
    topic,
    keyword_tokens  -- 空格分隔的細粒度中文 token 字串
);
```

### 3.2 Schema 變更說明 (v1 -> v2)

| 表 / 欄位 | v1 | v2 | 原因 |
| :--- | :--- | :--- | :--- |
| `api_keys.key` | TEXT PRIMARY KEY (明文) | 廢棄 | 安全風險 |
| `api_keys.key_hash` | 不存在 | TEXT PRIMARY KEY | 儲存 bcrypt hash |
| `api_keys.key_prefix` | 不存在 | TEXT NOT NULL | 打碼顯示 |
| `taxonomies` | 不存在 | 新表 | 課綱階層管理 |
| `items.topic_id` | 不存在 | TEXT FK | 取代純文字 topic |
| `items.keyword_tokens` | 不存在 | TEXT | FTS5 細粒度 token |
| `items.vector_clock` | 不存在 | TEXT JSON | 離線同步衝突解決 |
| `items.updated_at` | 不存在 | DATETIME | 同步時間戳參照 |
| `items_fts.keywords` | 存在 | 改名 keyword_tokens | FTS5 搜尋語意修正 |
| `idx_user_created` | 不存在 | 新 Index | cursor-based 分頁 |

## 4. AI 服務架構 (AI Service Layer)

### 4.1 AIService 抽象層 (v2.0.0 新增)

> **變更動機**：v1.0.0 的設計在 `POST /api/problems` handler 中直接呼叫 Gemini SDK，換模型需修改 Worker handler 源碼。

**採用策略：AIService interface + 工廠函式**

```
src/
  services/
    ai/
      AIService.ts     -- interface 定義
      GeminiService.ts -- Gemini 實作
      index.ts         -- 工廠函式 (依 env.AI_PROVIDER 動態選擇)
```

```typescript
// src/services/ai/AIService.ts
export interface TagResult {
  topic_id:       string;           // 比對 taxonomies 表的 ID
  keywords:       string[];         // 原始完整關鍵字，供顯示
  keyword_tokens: string[];         // 細粒度 token 列表，供 FTS5 索引
}

export interface AIService {
  tagProblem(
    imageUrl:     string,
    taxonomyTree: TaxonomyNode[]    // 從 KV Cache 傳入，不重複查 D1
  ): Promise<TagResult>;
}

// src/services/ai/index.ts — 工廠函式
export function createAIService(env: Env): AIService {
  switch (env.AI_PROVIDER ?? 'gemini') {
    case 'gemini': return new GeminiService(env.GEMINI_API_KEY);
    // case 'claude': return new ClaudeService(env.CLAUDE_API_KEY);
    default: throw new Error(`Unknown AI provider: ${env.AI_PROVIDER}`);
  }
}
```

### 4.2 課綱樹 KV 快取策略

Worker 啟動或第一次請求時從 KV 載入完整課綱樹，後續 AI 呼叫傳入樹參照：

```typescript
// Worker handler (Hono)
app.post('/api/problems', async (c) => {
  const taxonomyTree = await c.env.KV.get<TaxonomyNode[]>('taxonomy:tree', { type: 'json' });
  const aiService = createAIService(c.env);

  // 非阻塞背景標籤
  c.executionCtx.waitUntil(
    aiService.tagProblem(r2Url, taxonomyTree).then(result => {
      // 將 result.topic_id / keywords / keyword_tokens 寫回 D1 + FTS5
    })
  );

  return c.json({ id: problemId }, 200);
});
```

### 4.3 AI Prompt 規範 (Structured Output)

Gemini Prompt 需附上完整課綱 ID 樹，要求模型輸出 `topic_id` 而非自由文字，並同時輸出 `keyword_tokens` 細粒度列表：

```json
{
  "topic_id": "math-probability-conditional",
  "keywords": ["條件機率", "貝氏定理"],
  "keyword_tokens": ["條件", "機率", "貝氏", "定理", "條件機率", "貝氏定理"]
}
```

## 5. API 路由設計 (Hono Router)

### 5.1 身分驗證與捷徑用戶端模組 (`/api/auth/*` & `/api/keys`)

- `GET/POST /api/auth/*`：由 better-auth 接管，處理 Google 登入、登出與 Session 驗證。
- `POST /api/keys`：生成 bcrypt hash，寫入 D1，**僅在此次回應回傳明文 Key，之後永不可再取得**。
- `GET /api/keys`：列出該使用者所有 API Key（以 `key_prefix` 打碼顯示，如 `rdv_a1b2c3d4****`）。
- `DELETE /api/keys/:hash`：撤銷特定 API Key（以 `key_hash` 為主鍵）。
- **iOS 捷徑客戶端規範**：捷徑上傳前強制先將照片轉為 1080p / 80% 質量 JPEG (體積 `< 500KB`) 以確保可在 1.5 秒內完成上傳；若當前無網路，捷徑會暫存於 iOS 本地佇列，恢復連線後背景補傳。

### 5.2 錯題資源與分享模組 (`/api/problems` & `/share/:token`)

> *附註：所有 `/api/problems` 路由皆受 Auth Middleware 保護，自動從 Session 或 Header 提取 `user_id`*

- `POST /api/problems`：
  1. 接收 `FormData` (包含壓縮後的 JPEG 二進位圖片)。
  2. 寫入 R2 與 D1，回傳 200 OK (不阻塞)。
  3. 透過 `ctx.waitUntil()` 於背景呼叫 AIService 進行 AI 標籤辨識（Prompt 包含學測課綱 ID 樹以確保 `topic_id` 規範化）。
- `GET /api/problems`：獲取題目列表。**採用 cursor-based 分頁**（見 5.3 節），支援條件過濾 (`topic_id`, `status`)。
- `GET /api/problems/:id`：獲取單題完整 Metadata。
- `PUT /api/problems/:id`：手動修正 Metadata (topic_id、keywords)。
- `DELETE /api/problems/:id`：刪除錯題與關聯的 R2 影像檔。
- `POST /api/problems/:id/share`：生成分享 Token (`share_token`) 並寫入 `shares` 資料表。
- `GET /share/:token`：公開存取路由（無需 Auth header），由 Worker 直接校驗 Token 並回傳對應的題目與指定筆跡權限，保護內部 API 不被暴露。

### 5.3 Cursor-based 分頁規範 (v2.0.0 新增)

> **變更動機**：v1.0.0 採用 `limit/offset` 分頁，在 5000+ 題時效能線性下降，且新題插入會造成頁碼位移（虛擬滾動重複載入/遺漏）。

**游標格式**：`(created_at DESC, id DESC)` 複合游標，Base64 URL-safe 編碼。

```typescript
// GET /api/problems?cursor=<base64>&limit=20&topic_id=math-prob&status=unsolved
const [cursorDate, cursorId] = cursor ? decodeCursor(cursor) : [null, null];

const rows = await db.select().from(items)
  .where(
    and(
      eq(items.user_id, userId),
      topicId ? eq(items.topic_id, topicId) : undefined,
      status  ? eq(items.status,   status)  : undefined,
      cursorDate ? or(
        lt(items.created_at, cursorDate),
        and(eq(items.created_at, cursorDate), lt(items.id, cursorId!))
      ) : undefined,
    )
  )
  .orderBy(desc(items.created_at), desc(items.id))
  .limit(limit + 1);

const hasMore  = rows.length > limit;
const nextCursor = hasMore ? encodeCursor(rows[limit - 1]) : null;
return c.json({ items: rows.slice(0, limit), nextCursor });
```

**Index 依賴**：此查詢使用 `idx_user_created ON items(user_id, created_at DESC, id DESC)`。

### 5.4 高頻狀態與離線同步模組

- `PATCH /api/problems/:id/draw`：前端 Debounce (2s) 將向量筆跡與局部擦除遮罩（Vector Stroke Path & Erase Segment Masks JSON，體積 `< 5KB`）寫入 D1/R2，免去重型 PNG 上傳，大幅節省 95% 頻寬並支援無損縮放與秒級「隱藏筆跡」。**v2.0.0 新增 vector_clock 衝突檢測**（見第 6 節）。
- **PWA 離線同步佇列 (Offline Sync Queue)**：當網路中斷時，`draw_data` 優先寫入瀏覽器 IndexedDB 佇列；Service Worker 監聽 `online` 事件，當連線恢復時自動按順序批次同步至 `/api/problems/:id/draw`。
- `PATCH /api/problems/:id/status`：切換狀態 (`unsolved` <-> `resolved`)，並觸發 `review_count` 累加。

## 6. 離線同步衝突解決 (Offline Conflict Resolution)

### 6.1 衝突場景

v1.0.0 的 IndexedDB 佇列「按順序批次同步」，但缺少衝突解決策略。典型衝突場景：

- iPad 離線時寫了筆跡 A（尚未同步）
- iPhone 同時線上發出請求修改同一題的 draw_data（已到達 Server）
- iPad 恢復連線後推送筆跡 A，Server 端 draw_data 狀態不一致

### 6.2 採用策略：Vector Clock + Server Last-Write-Wins

**Client 端**：每個 IndexedDB 佇列操作項目附加 `vector_clock`：

```typescript
// 裝置初始化時生成一個永久 clientId
const clientId = localStorage.getItem('rdv_client_id')
  ?? (() => { const id = crypto.randomUUID(); localStorage.setItem('rdv_client_id', id); return id; })();

// 每次寫入筆跡時
const op: SyncOperation = {
  problemId,
  draw_data,
  vector_clock: { clientId, seq: ++localSeq },  // localSeq 持久化於 IndexedDB
};
await idbQueue.add('sync_queue', op);
```

**Server 端**：`PATCH /api/problems/:id/draw` 接收 `vector_clock` 並執行 LWW 比對：

```typescript
const { draw_data, vector_clock: incoming } = await req.json();
const [current] = await db.select({ vc: items.vector_clock })
  .from(items).where(eq(items.id, problemId));

const incomingSeq = JSON.parse(incoming ?? '{"seq":0}').seq;
const currentSeq  = JSON.parse(current?.vc ?? '{"seq":0}').seq;

if (incomingSeq >= currentSeq) {
  await db.update(items).set({
    draw_data,
    vector_clock: incoming,
    updated_at:   new Date().toISOString(),
  }).where(eq(items.id, problemId));
  return c.json({ status: 'ok' }, 200);
} else {
  // 回傳 409 + 最新資料，Client 可選擇丟棄本地變更
  return c.json({ status: 'conflict', current: current }, 409);
}
```

## 7. 中文全文搜尋 (FTS5 Chinese Search)

### 7.1 設計限制與解法

D1 內建 FTS5 預設 tokenizer `unicode61` 不支援中文斷詞。v1.0.0 的解法（AI keywords 用空白隔開）在搜尋子詞時會 miss（例：搜「機率」，AI 寫入的是「條件機率」整詞，FTS5 `MATCH '機率'` 無法比對）。

**v2.0.0 解法：AI 輸出雙層關鍵字，FTS5 索引細粒度 token**

- `items.keywords`：保留原始完整關鍵字 JSON Array，供前端顯示 Tag。
- `items.keyword_tokens`：AI 額外輸出的細粒度 token 字串（空格分隔），寫入 FTS5 `keyword_tokens` 欄位。
- 搜尋「機率」時，`keyword_tokens` 欄位包含獨立的「機率」token，FTS5 `MATCH '機率'` 即可命中。

### 7.2 搜尋查詢

```sql
-- 雙軌搜尋：FTS5 全文比對 + JSON_EACH 精確比對
SELECT i.*
FROM items i
JOIN items_fts fts ON i.id = fts.id
WHERE fts.keyword_tokens MATCH '機率'
  AND i.user_id = ?

UNION

SELECT i.*
FROM items i, JSON_EACH(i.keywords) kw
WHERE kw.value LIKE '%機率%'
  AND i.user_id = ?
```

## 8. 前端架構與 UI/UX 規範 (Frontend & Mechanics)

### 8.1 路由設計 (React Router)

- `/`：Dashboard 戰情室 (個人進度統計、API Key 管理入口)。
- `/study/:subject`：單科全域虛擬滾動刷題區 (List View)。
- `/study/:subject/:topicId`：單元過濾視圖（v2.0.0：`topicId` 改為 taxonomy ID）。
- `/study/:subject/:topicId/:problemId`：URL 滾動狀態綁定 (`history.replaceState`)，F5 重整不遺失閱讀進度。
- `/problem/:id`：單題專注模式。
- `/search?q={keyword}`：全站中文 FTS5 + JSON_EACH 雙軌獨立搜尋頁面。
- `/share/:token`：公開唯讀分享頁 (同學免登入查看)。

### 8.2 核心互動實作

#### 跨裝置即時同步 (iPhone -> iPad Multi-Device Sync)

iPad 端 PWA 在視窗獲得焦點 (Window Focus) 或進行背景輕量輪詢時，若發覺有新題目，自動**靜默插入 (Silent Prepend)** 至滾動列表頂端，並提供頂端手動重新整理按鈕，達成無縫跨裝置銜接。

#### 觸控分離與掌壓防誤觸 (PointerType Magic & Palm Rejection Guard)

攔截 `PointerEvent`，當偵測到 Apple Pencil (`pen`) 寫字時，自動停用 Canvas 區域內單指 touch 觸發的頁面滾動，防止手掌 (Palm) 貼在螢幕上計算時導致頁面亂跳。滾動僅限在卡片外側容器或軌道處理。若為純 `touch`（無 Pencil 作用中）則觸發原生垂直滾動。

#### 雙手協同 (Bimanual Interaction)

- **左下角彈簧橡皮擦 (Spring-loaded Eraser)**：左手按住懸浮鈕 `onTouchStart` 切換橡皮擦模式。結合向量筆跡路徑與分割演算法（Vector Segment Clipping / Eraser Path Masking），實現**精準局部擦除筆劃**；鬆開恢復畫筆。
- **雙指復原 (Two-finger Undo)**：監聽全局 `touchstart`，`e.touches.length === 2` 觸發狀態棧回退。

#### 虛擬滾動與動態長高畫布 (Viewport-only & Auto-Expanding Canvas)

- **視口限定掛載**：僅在當前 Viewport 視口內的題目卡片動態掛載真實 HTML5 `<canvas>` 繪圖層，滾出視口即轉換為 SVG 並卸載 Canvas context，維持 60fps 順暢滑動。
- **長算式動態長高 (Auto-Expanding Card Canvas)**：當筆尖書寫接近題目卡片底部 (距離底邊 100px) 時，卡片自動向下擴展高度 (+400px 空白計算區)，保持向量筆跡座標不變形，滿足長推導需求。
- **v2.0.0**：前端 `@tanstack/react-virtual` 的 `fetchNextPage` 觸發改為傳遞 `cursor` 參數（取代舊的 `page` 頁碼），與 cursor-based API 完整整合。

#### 智慧反色模式 (Invert Mode)

針對考卷底圖套用 `filter: invert(0.9) hue-rotate(180deg) grayscale(0.2);`，消除刺眼的純白底圖，轉換為柔和深灰底與淺灰字，與低對比黑灰 UI 完美結合。

### 8.3 低對比設計系統與視覺規範實作 (Design System Implementation)

#### 配色 Token 定義 (Tailwind CSS Integration)

- **背景與卡片 (Background & Surface)**：
  - Light 模式：`bg-[#F3F4F6]` / `bg-[#F4F4F2]` (Canvas/頁面背景), `bg-[#FFFFFF]` + `border border-[#E5E7EB]` (Cards & Containers)。
  - Dark 模式：`bg-[#161618]` (消光深灰，避免純黑 `#000000`), `bg-[#202023]` + `border border-[#2C2C30]`。
- **文字與階層 (Typography Contrast)**：
  - 主標題/正文：`text-[#374151]` (Light) / `text-[#D1D5DB]` (Dark)（避免正黑 `#000` 或正白 `#FFF`）。
  - 次要資訊/標籤：`text-[#9CA3AF]`（柔和中灰）。
- **功能組件調色 (Accent Colors)**：
  - Primary / 畫筆：`text-[#6366F1]` / `bg-[#6366F1]` (沉穩霧霾藍/靛青色)。
  - 彈簧橡皮擦 (Eraser FAB)：`bg-[#E11D48]/80` (按壓時切換實色 `#E11D48`)。
  - 標記完成 (Resolved)：`text-[#10B981]` (莫蘭迪綠)。

#### UI 視覺特徵技術實作

- **Soft Elevation & Micro-border**：使用 `border border-[#E5E7EB]` (Light) / `border-[#2C2C30]` (Dark)，搭配微擴散陰影 `shadow-[0_4px_20px_rgba(0,0,0,0.03)]` 呈現輕盈浮空感。
- **Rounded Corners**：組件與卡片統一套用 `rounded-2xl` 或 `rounded-3xl` 消除長時閱讀疲勞。
- **Subtle Feedback**：Hover/Active 狀態僅進行微明度過渡（例：`hover:bg-stone-100 dark:hover:bg-stone-800/50`）。

#### 智慧護眼反色 CSS 濾鏡引擎

當使用者啟用低對比深色模式時，考卷底圖 Canvas/Image 節點套用低對比專用反色矩陣，避免高對比純白底圖刺眼：

```css
/* 低對比深色模式底圖反色濾鏡 */
.dark .exam-paper-image {
  filter: invert(0.9) hue-rotate(180deg) grayscale(0.2);
}
```

## 9. 架構決策記錄 (ADR Summary)

| ADR | 決策項目 | 採用策略 | 替代方案 | 理由 |
| :--- | :--- | :--- | :--- | :--- |
| ADR-001 | 課綱 Taxonomy 管理 | 獨立 `taxonomies` 表 + KV Cache | TEXT 欄位直存 | 支援課綱改版遷移與三層階層表達 |

| ADR-005 | FTS5 中文搜尋 | AI 輸出細粒度 token + keyword_tokens 欄位 | jieba-wasm | 不引入外部相依，維持 Edge 輕量 |
| ADR-006 | 分頁策略 | cursor-based keyset (created_at, id) | limit/offset (v1) | O(1) 跳頁，消除頁碼位移問題 |
