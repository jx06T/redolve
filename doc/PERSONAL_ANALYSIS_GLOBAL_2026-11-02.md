## 使用流程

1. 首頁提供「原題練習」與「各科分析」入口；導覽列的分析入口直接開啟 `/analysis`。
2. 分析首頁直接列出各科目前的個人題數、可用題文、確認數、期間作答、答對次數與最近報告。沒有紀錄顯示空值，不製造能力分數；進頁不呼叫 AI。
3. 點科目進入 `/analysis/:subjectId`。預設讀取時間最新的整科報告，歷史依時間倒序排列，可用前後按鈕、時間選單與分頁載入更早報告。歷史包含不同觀察期間，不因上方更改期間而隱藏。相同資料、期間及模型會沿用已完成報告，避免重複付費呼叫。
4. 上方選擇近 7／15／30／60／90 天作答觀察期間，再手動按「產生整科報告」。題庫包含目前持有的上傳及存入題，不依收錄日期排除舊題，不提供單元／子分類報告範圍。
5. 報告先呈現整科綜合解讀，再依有效資料量提供有依據的段落，不固定三項。長文預設顯示短預覽，可個別展開。每段可引用一至多題，點「題 1」等灰色底線文字開啟當時版本的題文、作答與正解彈窗，並連結原題。引用與練習入口合併為緊湊列；只談統計的段落不必硬配一題。報告內完整統計只保留一個數據詳情入口。
6. 報告下方可追問。對話延續這份報告的資料快照，不假裝已讀取最新作答；回答也可引用多題。可重試失敗回答，重送同一請求不重複呼叫模型。
7. 「練習這些題」帶推薦題目到獨立 `/practice` 頁，按開始後從目前仍可用的原題中抽取。練習仍可選科目與單元；離開不保存練習草稿，已提交作答照常保存與同步。

新舊報告保留各自的題目版本、統計與作答依據。修改正解或更正作答不回寫已產生報告。舊 `/practice#analysis` 入口轉到新的分析頁。

## 全局分析與引用

「全局」是整科目前持有題庫的整體觀察，不代表 AI 重新看過所有圖片，也不是完整考試成績分析。

流程為：程式計算整科與單元統計 → 建立全部可用題文的目錄 → 模型挑選題目 ID → 後端讀取這些題目的固定版本與當時有效作答 → 模型產生結構化報告 → 後端驗證所有引用 → 前端渲染引用卡片。

- 目錄包含每題至多前 160 字（資料量接近儲存上限時進一步縮短）、單元、確認狀態、正解有無、期間作答與答對次數，不含圖片或共享作者的私人筆記。
- 一次最多深讀 30 題，題文／選項／當時答案有長度限制，深讀資料總量上限 120 KB。報告明示深讀題數；不是宣稱已精讀全科所有題目。
- 模型挑選 ID 與報告輸出均使用 JSON schema。這是由應用程式控制的兩階段檢索流程，採用與工具檢索相同的「挑 ID、驗證、讀資料」做法，並非開放模型任意查詢資料庫。
- 引用 ID 必須在這份私人報告的可用題目中，且實際提供過詳細內容。未知或他人題目 ID 會讓本次解讀失敗，不放行到完成報告。
- 追問可以從同一份固定目錄挑其他相關題目，並沿用原報告引用及最近六輪已完成對話；每份報告最多 80 輪，避免無限增長。
- 題目與對話視為不可信資料；模型不能遵從題文中的指令。模型輸出以文字呈現，不當成 HTML 或自行產生的任意網址執行。

## 趨勢的定義

以選定天數為本期，往前取相同天數、互不重疊的前期。程式計算兩期的作答、答對、自動判分、自評、看原圖次數；另算兩期都有作答的同一批題目及其結果。每日資料依選定時區分日。

兩期題目組合可能不同，不能只看答對比例就宣稱進步；同題也可能已記住答案。無前期或重作紀錄時，報告應說明限制，只解讀內容與分布。收錄題數不等於考試錯誤率，訂正完成狀態不是重作結果。

本次沒有用兩份可能重疊期間的報告直接計算「能力變化」。使用者仍可切換歷史報告，數字依各份當時資料保留。

## 模型與執行

- 一般上傳／重新辨識維持既有 `gemini-3.1-flash-lite` 與原有備援規則、20 秒呼叫設定。
- 整科報告與追問預設獨立使用 `gemini-3.1-pro-preview`，可用 Worker 的 `GEMINI_ANALYSIS_MODEL` 覆寫。不會隱性降級成一般辨識模型；失敗提供手動重試。
- 每次報告至多兩次模型呼叫（選題、報告）；每次追問至多兩次（選題、回答）。每次呼叫逾時 90 秒、無 SDK 自動重試。這不等於已完成品質評測或收費設計。
- 建立報告先回傳 pending 快照，前端再呼叫 `/reports/:id/run`。執行時維持回應串流，定期傳送 JSON 空白，避免單靠回應結束後僅 30 秒的 `waitUntil`。報告／追問具有執行租約與去重，頁面離開或連線中斷後可手動繼續／重試，尚未改用持久 Queue。
- 2026-11-02 透過既有 Gemini 帳號列出可用模型，並用兩道人造機率題實際完成 Pro 選題及報告，成功產生 overview、兩項分析及有效題目 ID；沒有傳送使用者題庫。這是連線與格式驗證，不是教學品質保證。

## 資料庫與成本

新增 `0017_analysis_context_and_followups.sql`：

| 結構 | 用途 |
| --- | --- |
| `analysis_report_contexts` | 固定目錄、題目版本、報告當時有效作答 ID 與執行權杖 |
| `analysis_followups` | 每輪問題、回答、引用、模型、請求雜湊、狀態及租約 |

保留既有 `analysis_reports` 與 `analysis_report_questions`。詳細報告、目錄與對話保留 90 天，數字摘要長期保存；刪除題目或帳號一併清理關聯報告。到期時直接禁止讀取細節與追問，排程分批實體清理。歷史作答即使後續被更正，仍依報告固定的有效事件 ID 讀取，避免追問時悄悄改變依據。

總覽使用批次彙總查詢，不逐科讀取完整題目或 AI。報告只在手動產生時載入全科資料，目前上限 2,000 題、本期及前期各 10,000 筆有效事件；超限明確提示，不默默截斷。查詢仍依使用者、科目與期間使用索引，首頁不掃題文或原圖。

## 本地升級

先停止本地 Worker。在專案根目錄執行：

```powershell
node scripts/apply-practice-schema.mjs --target=local --check
node scripts/apply-practice-schema.mjs --target=local --apply
node scripts/init-local-db.mjs --check
```

`--check` 缺少 0017 時回非零是預期行為。腳本會備份本地 D1、跳過已完整套用的 0015／0016，只補缺少的 migration；不重跑整份 schema。若 0014 或分享等基礎結構也尚未完整，依 [完整本地操作文件](./PERSONAL_PRACTICE_LOCAL_RUN_2026-11-01.md) 先初始化。

`.env.local` 與 `.dev.vars` 的既有功能開關維持開啟。要指定分析模型，可於 `.dev.vars` 加入：

```dotenv
GEMINI_ANALYSIS_MODEL=gemini-3.1-pro-preview
```

重啟 Worker 與 Vite，開啟 `http://localhost:3000/analysis` 或 `/practice`。實際 API 仍需本地登入與題目資料。這次只在暫存測試資料庫驗證 0017，未替使用中的本地／正式 D1 執行 migration，未推送或部署。
