Redolve 開發修復任務清單 (Engineering Task List)
模組一：Canvas 繪圖引擎與觸控優化 (DrawCanvas.tsx)
1. 畫布高度未隨寬度等比縮放 (Aspect Ratio Scaling Bug)
現象：在小螢幕裝置上，筆跡雖有縮小，但畫布下方會出現極大空白，導致卡片過長。
原因：DrawCanvas 僅對點位座標進行 * scale，但未將容器/畫布的實體高度同步乘上 scale。
修復建議：
讀取資料庫存的 baseHeight，並套用公式：ResponsiveHeight = baseHeight * scale。
修改 useEffect 中監聽 ResizeObserver 的邏輯：當外層寬度改變時，根據算出的 scale 強制更新 canvasHeight 狀態，讓 <canvas> 和 <svg> 的高度與內容等比縮放。
2. 刷題頁面滾動嚴重卡頓 (Scroll Hijacking Performance Issue)
現象：即使用戶只載入 3 題，用手指上下滑動頁面時仍有極強的「黏手感」與卡頓，失去 iOS 原生慣性。
原因：handlePointerMove 攔截了手指事件，並使用 JavaScript 強制計算 scrollParent.scrollTop -= deltaY，JS 執行緒干擾了 GPU 的原生滾動渲染。
修復建議：
移除 isTouchScrollingRef 相關的所有 JS 手動修改 scrollTop 的程式碼。
改用 CSS 處理：預設給 Canvas 容器加上 touch-action: pan-y（允許原生上下滾動）。
當 handlePointerDown 偵測到 e.pointerType === 'pen'（下筆）時，動態將該 Canvas 的 CSS 改為 touch-action: none（鎖定畫面防跳動）。筆尖離開 pointerup 時恢復 pan-y。
3. 手指防誤觸模式下，橡皮擦仍可作用 (Eraser Trigger Logic)
現象：雖然手指不能畫畫，但若開啟橡皮擦模式，手指誤觸螢幕仍會把字擦掉。
修復建議：
在 handlePointerDown 和 handlePointerMove 執行 performErase 前加入嚴格攔截：if (e.pointerType === 'touch' && !isEraserActive) return; 確保只有「左手按著彈簧橡皮擦按鈕」或「Apple Pencil 硬體雙擊」才能觸發擦除。
將橡皮擦預設粗細 (EraserRadius) 提高，目前 1px 的過細，改為 7px。


模組二：前端狀態與 PWA 體驗優化

1. PWA 缺乏狀態同步機制 (No Pull-to-Refresh)
現象：因為是 PWA，隱藏了原生網址列與重整按鈕，用戶無從得知新上傳的題目是否處理完成或進行重新整理。
修復建議：
實作焦點回歸輪詢 (Focus Revalidation)：監聽 window.addEventListener('visibilitychange')，當用戶從相機切回 PWA 時，背景靜默發出 API 請求檢查第一頁資料。
Toast 通知：若發現新 problemId，不要用 Modal 打斷用戶，改從右下角滑出 Toast：「✅ 偵測到新題目已分類，[點此重新整理]」。用戶點擊後才將資料推入 Zustand Store 頂端。 並考慮在上方工具列提供重新整理按鈕

2. 上傳「樂觀更新」與圖片前端壓縮 (Optimistic UI & Image Compression)
現象：上傳圖片時畫面無立即回饋；直接傳原圖消耗過多 R2 頻寬與儲存空間。
修復建議：
前端壓縮：在 FormData 送出前，利用 document.createElement('canvas') 將圖片畫入，判斷若 width > 1920 則等比縮小，並呼叫 canvas.toBlob(..., 'image/jpeg', 0.8) 輸出壓縮檔再上傳。
樂觀更新：點擊上傳瞬間，先顯示「正在處理中... (Loading Spinner)」，待 API 回傳成功後繼續下一步更新

3. 使用者偏好未記憶 (Persist Preferences)
現象：切換頁面後，工具列位置、當前科目、篩選狀態（未完成/已完成）會被重置。
修復建議：
利用 Zustand 的 persist Middleware，將 toolbarPosition, filterStatus, currentSubjectId 寫入 localStorage。
手機端 (視窗寬度 < 768px) 預設將懸浮工具列收合（變成一個可點擊展開的小 Icon）。

4. 快速完成按鈕行為不順 (UX Flow)
現象：對於已完成的題目點擊懸浮的「標記完成」，會切換回未完成。
修復建議：對於已完成的題目 若使用者點擊懸浮按鈕，只需將該卡片標示為綠色勾勾，並利用 react-virtual 的 scrollToIndex 平滑滾動到下一題，維持刷題心流。

模組三：UI 視覺與排版修正 (CSS / RWD)
1. 彈出層層級與防選取 (Z-index & User-Select)
修復建議：
全域 CSS (body 或主要容器) 加上 user-select: none; -webkit-user-select: none;，防止長按誤選文字。
檢查所有 Modal 的 z-index，確保其高於懸浮工具列（例如 Modal 設為 z-50，Toolbar 設為 z-40）。
2. 橫向滾動溢出與漢堡選單 (Mobile Layout)
修復建議：
刷題頁工具按鈕：小螢幕下（如手機），按鈕群組應套用 flex-wrap 換行，或改為 Dropdown Menu，消除橫向 Scrollbar。
漢堡選單：CSS 改為 fixed 或 absolute 覆蓋在內容上方，取消對下方 DOM 節點的推擠。並綁定 onClickOutside 點擊空白處自動收合。
設定頁：小螢幕時隱藏文字，只顯示 Icon 節省空間。修復 Color Input 在 Safari/Chrome 上點擊無反應的 Bug (通常是 pointer-events 或 z-index 被遮擋)。
3. 圖片放大檢視 (Lightbox)
修復建議：
為題目的圖片加上 cursor-pointer。點擊時，將 imageUrl 傳入全域的 Lightbox 元件，以 fixed inset-0 z-[100] bg-black/90 滿版顯示並支援雙指縮放。
模組四：後端 API 與資料邏輯修正 (Cloudflare Workers)
1. 側邊欄計數邏輯錯誤 (Sidebar Count Bug)
現象：側邊欄的錯題數量比實際少。
原因：目前可能只計算了直接綁定在 Level 0 (科目) 的題目，忽略了深層節點。
修復建議：
修改 Dashboard/Sidebar 的計數 SQL 或前端處理邏輯，必須實作 Bottom-Up 累加。將屬於 Level 2 (子單元) 的數量往上加給 Level 1 (大單元)，再匯總給 Level 0。
2. 分享功能重構 (Share Modal & Logic)
現象：產生分享連結時無法選擇分享範圍；API 報錯卻仍顯示短網址。
修復建議：
點擊分享時，彈出一個 Modal (包含 Checkbox: [v] 包含筆跡 / [v] 包含文字筆記)。
確認後呼叫 API，若回傳 200 才顯示產生的短網址。API 應接住例外 (try-catch)，若失敗則前端顯示紅色 Error 提示，不產生網址。
3. 廢除共用訪客模式 (Security)
修復建議：
移除全域共用的訪客帳號 API 邏輯。未登入者強制導向登入頁，或僅提供純 LocalStorage/IndexedDB 的本機唯讀體驗，禁止呼叫 D1 寫入 API。
4. 筆記區塊與真全文搜尋 (Notes & FTS5 OCR)
現象：搜尋功能殘缺，標籤顯示有雙引號，且無法搜尋筆記。
修復建議：
修復前端標籤顯示問題

Textarea 筆記區塊套用 react-textarea-autosize 套件使其隨內容長高。

後端修改：讓 Gemini 能辨識出「題目完整文字 (OCR)」並且使用者的「筆記 (Notes)」也做新增欄位，並納入 items_fts 虛擬表中建立 FTS5 全文索引，達成真全文搜尋。
