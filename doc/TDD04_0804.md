## 1. 系統概述 (System Overview)

Redolve 是一款專為 iPad + Apple Pencil 深度最佳化的 Serverless PWA 錯題本系統。主打「心流式刷題（無縫滾動）」、「雙手協同手勢」與「AI 自動化標籤」。系統全面採用 Cloudflare 邊緣運算生態系，並導入標準 SaaS 多使用者驗證架構，實現跨裝置安全存取與資料完全隔離。

### 1.1 核心技術堆疊 (Tech Stack)

| 層級 | 技術選型 | 說明 / 備註 |
| :--- | :--- | :--- |
| **前端 (Frontend)** | React 18, Vite (SPA), TypeScript, Tailwind CSS, Zustand, `@tanstack/react-virtual` | 效能優化與虛擬列表 |
| **繪圖引擎 (Canvas)** | HTML5 原生 `<canvas>` + `perfect-freehand` | 支援向量點位 + 局部擦除遮罩 |
| **離線快取 (PWA Storage)** | Service Worker + IndexedDB | 離線筆跡佇列、背景同步、三段快取策略 |
| **後端 API (Backend)** | Cloudflare Workers (Hono Framework) | Edge Runtime |
| **資料庫與儲存** | Cloudflare D1 (SQLite) + Cloudflare R2 | 關聯式資料 (含 draw_data) 與物件儲存 (私有題目圖片，Worker Proxy 存取) |
| **課綱快取 (Taxonomy Cache)** | Cloudflare KV | 快取課綱分類樹，減少 D1 查詢 |
| **身分驗證 (Auth)** | better-auth (Google OAuth) + 自建 API Key Middleware | 雙軌驗證機制 |
| **AI 整合 (AI)** | Google Gemini 2.5 / 3.5 Flash API (透過 AIService 抽象層) | Structured Outputs 視覺辨識 |

### 2.2 課綱分類樹初始化 — Seed API (v1.3.0 新增)

> **v1.2.0 缺失**：`taxonomies` 表與 KV 快取的初始化流程未定義，部署後資料庫為空，Worker 無法運作。

**採用策略：管理者 Seed API**

```
POST /api/admin/taxonomy/seed
Authorization: Bearer <ADMIN_SECRET>
```

此端點執行以下操作：
1. 將 hardcoded 的學測/分科測驗課綱 JSON 批次寫入 `taxonomies` 表（D1）。
2. 同步將整棵課綱樹 JSON 寫入 KV 的 `taxonomy:tree` 鍵。

**觸發時機**：
- 第一次部署後執行一次。
- 課綱改版時再執行一次即可全量更新。

```typescript
// worker/routes/admin.ts
adminRouter.post('/taxonomy/seed', async (c) => {
  const authHeader = c.req.header('Authorization');
  if (authHeader !== `Bearer ${c.env.ADMIN_SECRET}`) {
    return c.json({ error: { code: 'UNAUTHORIZED', message: '無效的管理者憑證' } }, 401);
  }

  const tree = TAXONOMY_SEED_DATA;
  await seedTaxonomiesToD1(c.env.DB, tree);
  await c.env.KV.put('taxonomy:tree', JSON.stringify(tree));

  return c.json({ status: 'seeded', count: tree.length });
});
```

## 3. 身分驗證與安全架構 (Auth & Security)

### 3.1 雙軌驗證機制 (v1.1.0)

1. **PWA 網頁端**：Google OAuth + Session / HTTP-only Cookie。
2. **iOS 捷徑端**：靜態 API Key（bcrypt hash 儲存）。
3. **多租戶隔離**：Hono Middleware 強制 `WHERE user_id = ?`。
4. **分享 Token**：加密短 Token，`expires_at = NULL` 表示永久有效，手動撤銷。

### 3.2 CORS 安全配置 (v1.2.0)

```typescript
app.use('*', cors({
  origin: (origin) => {
    if (origin?.startsWith('http://localhost:')) return origin;
    return ALLOWED_ORIGINS.includes(origin ?? '') ? origin : undefined;
  },
  allowHeaders: ['Content-Type', 'Authorization'],
  allowMethods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'],
  credentials: true,
}));
```

### 3.3 R2 圖片存取 — Worker Proxy (v1.3.0 新增)

> **v1.2.0 缺失**：`image_url` 欄位存放何種值、前端如何存取圖片從未定義。

**採用策略：R2 私有 + Worker Proxy**

- R2 bucket 設定為**私有**，不開放公開存取。
- `items.image_url` 欄位儲存 R2 **object key**（如 `images/{userId}/{uuid}.jpg`），而非完整 URL。
- 前端顯示圖片時，向 Worker 端發起請求：

```
GET /api/problems/:id/image
Authorization: Session Cookie 或 Bearer <API_KEY>
```

Worker 驗證 `user_id` 擁有該 `item_id` 後，從 R2 串流圖片回前端：

```typescript
app.get('/api/problems/:id/image', authMiddleware, async (c) => {
  const item = await db.select({ image_url: items.image_url, user_id: items.user_id })
    .from(items).where(eq(items.id, c.req.param('id'))).get();

  if (!item || item.user_id !== c.get('userId')) {
    return c.json({ error: { code: 'NOT_FOUND', message: '題目不存在' } }, 404);
  }

  const object = await c.env.STORAGE.get(item.image_url);
  if (!object) return c.json({ error: { code: 'NOT_FOUND', message: '圖片不存在' } }, 404);

  return new Response(object.body, {
    headers: {
      'Content-Type': object.httpMetadata?.contentType ?? 'image/jpeg',
      'Cache-Control': 'private, max-age=3600',
    },
  });
});
```

**分享頁圖片存取**：`GET /share/:token/image` — 驗證 Token 有效後同樣走 Worker Proxy 串流。

## 5. draw_data JSON Schema (v1.3.0 新增)

> **v1.2.0 缺失**：`draw_data` 欄位只說「向量筆跡 JSON」，未定義結構，日後新增功能（多色畫筆、高亮、筆跡匯出）時無法相容舊資料。

**設計原則**：採用可延伸設計，新增屬性時以選用（optional）欄位擴充，不做破壞性變更，避免 version switch-case 渲染邏輯。

### 5.1 Stroke（筆跡）結構

```typescript
interface Stroke {
  /** 畫筆顏色，hex 字串 */
  color:   string;          // ex: "#374151"
  /** 畫筆寬度（px，基準尺寸） */
  width:   number;          // ex: 2
  /** 不透明度，0-1 */
  opacity: number;          // ex: 1.0（預設）
  /** perfect-freehand 輸入點，[x, y, pressure] */
  points:  [number, number, number][];
  /** 選用：筆跡類型 */
  tool?:   'pen' | 'highlighter';  // 預設 'pen'
}
```

### 5.2 EraserMask（局部擦除遮罩）結構

```typescript
interface EraserMask {
  /** 被擦除的 strokes 陣列索引 */
  strokeIdx:    number;
  /** 被保留的筆跡片段範圍，[startT, endT]，t ∈ [0, 1] */
  segmentRange: [number, number][];
}
```

### 5.3 DrawData（頂層結構）

```typescript
interface DrawData {
  /** 筆跡列表（順序即繪製順序） */
  strokes:     Stroke[];
  /** 局部擦除遮罩列表 */
  eraserMasks: EraserMask[];
  /** 畫布擴展區塊列表，每次 Auto-Expanding 記錄一筆 */
  expansions?: { addedHeight: number; atY: number }[];
}
```

**延伸原則**：所有新增欄位加上 `?`（optional），讀取時使用 `?? defaultValue`，舊資料無此欄位時自動降級使用預設值，無需版本判斷。

```typescript
// 讀取時的安全降級範例
const tool    = stroke.tool    ?? 'pen';
const opacity = stroke.opacity ?? 1.0;
```

## 6. API 設計規範 (API Design)

### 6.1 標準錯誤回應格式 (v1.3.0 新增)

> **v1.2.0 缺失**：未定義統一錯誤格式，前端需針對每個路由分別處理不同結構的錯誤。

所有路由的錯誤回應統一使用以下格式：

```typescript
interface ErrorResponse {
  error: {
    code:     string;   // 機器可讀的錯誤碼，全大寫 SNAKE_CASE
    message:  string;   // 人類可讀的錯誤說明（中文）
    details?: unknown;  // 選用：額外的偵錯資訊（僅開發環境回傳）
  };
}
```

**常用錯誤碼對照表**：

| HTTP Status | code | 說明 |
| :--- | :--- | :--- |
| 400 | `INVALID_REQUEST` | 請求參數不合法 |
| 401 | `UNAUTHORIZED` | 未登入或 API Key 無效 |
| 403 | `FORBIDDEN` | 無權存取該資源（user_id 不符）|
| 404 | `NOT_FOUND` | 資源不存在 |
| 409 | `CONFLICT` | vector_clock 衝突 |
| 410 | `SHARE_EXPIRED` | 分享連結已過期 |
| 500 | `INTERNAL_ERROR` | 伺服器內部錯誤 |

**Hono 全局錯誤攔截**：

```typescript
app.onError((err, c) => {
  console.error('[Worker Error]', err);
  return c.json({
    error: {
      code:    'INTERNAL_ERROR',
      message: '伺服器發生錯誤，請稍後再試',
      details: c.env.ENV === 'development' ? err.message : undefined,
    },
  }, 500);
});
```

### 6.2 身分驗證與捷徑模組 (`/api/auth/*` & `/api/keys`)

- `GET/POST /api/auth/*`：由 better-auth 接管，處理 Google 登入、登出與 Session 驗證。
- `POST /api/keys`：生成 bcrypt hash，**僅在此次回應回傳明文 Key，之後永不可再取得**。
- `GET /api/keys`：列出所有 API Key（以 `key_prefix` 打碼顯示）。
- `DELETE /api/keys/:hash`：撤銷特定 API Key。

### 6.3 課綱管理模組 (`/api/admin/taxonomy`)

- `POST /api/admin/taxonomy/seed`：全量寫入學測課綱至 D1 + KV（需 `ADMIN_SECRET`）。

### 6.4 錯題資源模組 (`/api/problems`)

- `POST /api/problems`：接收 FormData，寫入 R2（私有 object key 存 `image_url`）+ D1，背景 AI 標籤。
- `GET /api/problems`：Cursor-based 分頁，支援 `topic_id` / `status` 過濾。
- `GET /api/problems/:id`：單題 Metadata。
- `GET /api/problems/:id/image`：Worker Proxy 串流 R2 私有圖片（需 Auth）。
- `PUT /api/problems/:id`：手動修正 Metadata。
- `DELETE /api/problems/:id`：刪除 D1 紀錄 + R2 物件。
- `PATCH /api/problems/:id/draw`：寫入 draw_data，含 vector_clock 衝突檢測。
- `PATCH /api/problems/:id/status`：切換 unsolved / resolved。
- `POST /api/problems/:id/share`：生成分享 Token。

### 6.5 分享模組 (`/share`)

- `GET /share/:token`：公開路由，驗證 Token + expires_at，回傳題目 Metadata。
- `GET /share/:token/image`：公開圖片代理（同 Worker Proxy 但以 Token 取代 Auth）。
- `DELETE /api/problems/:id/share/:token`：撤銷分享。

**Token 生命週期規範 (v1.2.0)**：
- `expires_at = NULL`：永久有效，使用者可於任何時候呼叫 DELETE 撤銷。
- `expires_at` 有值：Worker 在 `GET /share/:token` 時檢查，過期則回傳 410 Gone。

### 6.6 Cursor-based 分頁規範 (v1.1.0)

游標格式：`(created_at DESC, id DESC)` 複合游標，Base64 URL-safe 編碼。

```typescript
const rows = await db.select().from(items)
  .where(and(
    eq(items.user_id, userId),
    topicId   ? eq(items.topic_id, topicId) : undefined,
    status    ? eq(items.status, status)    : undefined,
    cursorDate ? or(
      lt(items.created_at, cursorDate),
      and(eq(items.created_at, cursorDate), lt(items.id, cursorId!))
    ) : undefined,
  ))
  .orderBy(desc(items.created_at), desc(items.id))
  .limit(limit + 1);

const hasMore    = rows.length > limit;
const nextCursor = hasMore ? encodeCursor(rows[limit - 1]) : null;
return c.json({ items: rows.slice(0, limit), nextCursor });
```

### 7.2 AI 標籤失敗行為 (v1.2.0)

3 次指數退退重試，最終失敗時 `status=unsolved`、`topic_id=null`。前端顯示「尚未分類 — 點此編輯」Badge。

```typescript
// ctx.waitUntil 內的降級邏輯
const result = await aiService.tagProblem(r2Url, taxonomyTree); // 含重試
if (result) {
  await db.update(items).set({
    topic_id: result.topic_id,
    keywords: JSON.stringify(result.keywords),
    keyword_tokens: result.keyword_tokens.join(' '),
    status: 'unsolved',
  }).where(eq(items.id, problemId));
} else {
  // 失敗（含額度超限）：靜默降級，保留 topic_id=null
  await db.update(items).set({ status: 'unsolved' })
    .where(eq(items.id, problemId));
}
```

## 8. 離線同步衝突解決 (Offline Conflict Resolution)

Vector Clock + Server Last-Write-Wins（v1.1.0，無修改）。

```typescript
// Server 端（PATCH /api/problems/:id/draw）
const incomingSeq = JSON.parse(incoming ?? '{"seq":0}').seq;
const currentSeq  = JSON.parse(current?.vc ?? '{"seq":0}').seq;

if (incomingSeq >= currentSeq) {
  await db.update(items).set({ draw_data, vector_clock: incoming, updated_at: new Date().toISOString() })
    .where(eq(items.id, problemId));

  return c.json({ status: 'conflict', current }, 409);
}
```

## 10. PWA Service Worker 快取策略 (v1.3.0 新增)

> **v1.2.0 缺失**：Service Worker 快取策略未定義，開發時無設計依據。

**三段差異化快取策略**：

| 資源類型 | 快取策略 | 說明 |
| :--- | :--- | :--- |
| App Shell（HTML、JS bundle、CSS） | **Cache-first** | 優先從快取載入，確保離線啟動速度 |
| API 資料（`/api/problems`、`/api/auth`）| **Network-first + 離線回退 Cache** | 優先取最新資料，網路失敗時降級顯示快取 |
| 題目圖片（`/api/problems/:id/image`） | **Stale-while-revalidate** | 先回傳快取圖片（減少感知延遲），背景靜默更新 |

**Service Worker 實作結構**：

```typescript
const APP_SHELL_CACHE = 'rdv-shell-v1';
const API_CACHE       = 'rdv-api-v1';
const IMAGE_CACHE     = 'rdv-images-v1';

self.addEventListener('fetch', (event: FetchEvent) => {
  const url = new URL(event.request.url);

  if (url.pathname.startsWith('/api/problems') && url.pathname.endsWith('/image')) {
    event.respondWith(staleWhileRevalidate(event.request, IMAGE_CACHE));
  } else if (url.pathname.startsWith('/api/')) {
    event.respondWith(networkFirstWithFallback(event.request, API_CACHE));
  } else {
    event.respondWith(cacheFirst(event.request, APP_SHELL_CACHE));
  }
});
```

## 11. 前端架構與 UI/UX 規範 (Frontend & Mechanics)

### 11.1 路由設計

- `/`：Dashboard 戰情室。
- `/study/:topicId`：單元虛擬滾動刷題區。
- `/study/:topicId/:problemId`：URL 滾動狀態綁定。
- `/problem/:id`：單題專注模式。

## 12. Dashboard 統計查詢設計 (v1.3.0 新增)

> **v1.2.0 缺失**：Dashboard 需要多層 JOIN 聚合查詢，未事先設計易寫出效能差的 SQL。

`GET /api/dashboard` — 回傳以下統計資料：

### 12.1 各科目錯題總數與訂正比例

```sql
SELECT
    t_root.id    AS subject_id,
    t_root.label AS subject_label,
    COUNT(i.id)  AS total,
    SUM(CASE WHEN i.status = 'resolved' THEN 1 ELSE 0 END) AS resolved
FROM items i
JOIN taxonomies t_leaf ON i.topic_id = t_leaf.id
JOIN taxonomies t_root ON (
    CASE t_leaf.level
        WHEN 0 THEN t_leaf.id
        WHEN 1 THEN t_leaf.parent_id
        WHEN 2 THEN (SELECT parent_id FROM taxonomies WHERE id = t_leaf.parent_id)
    END = t_root.id
)
WHERE i.user_id = ? AND t_root.level = 0
GROUP BY t_root.id, t_root.label;
```

### 12.2 最需複習的前 3 個單元

```sql
SELECT
    t.id          AS topic_id,
    t.label       AS topic_label,
    COUNT(i.id)   AS unsolved_count
FROM items i
JOIN taxonomies t ON i.topic_id = t.id
WHERE i.user_id = ? AND i.status = 'unsolved'
GROUP BY t.id, t.label
ORDER BY unsolved_count DESC
LIMIT 3;
```

### 12.3 API 回傳格式

```typescript
interface DashboardResponse {
  subjects: {
    subject_id:    string;
    subject_label: string;
    total:         number;
    resolved:      number;
  }[];
  top_unsolved_topics: {
    topic_id:       string;
    topic_label:    string;
    unsolved_count: number;
  }[];
}
```

## 15. 批次上傳、Webcamera 鏡頭拍攝與考卷來源 Session 記憶架構規格 (v1.4.0 新增)

### 15.1 考卷出處 Session 記憶與預設標籤庫
- 前端建立 `activeSource` 狀態（快取至 `sessionStorage`），預設值為當前上傳 Session 輸入的考卷出處（如 `113年全模數學`）。
- 內建常用來源快速標籤膠囊庫：`['113年學測', '112年指考/分科', '北模', '中模', '全模', '建中段考', '課本例題']`。
- 上傳所有照片時，會一律自動帶入該 `activeSource` 寫入 D1 `items.source` 欄位。

### 15.2 Webcamera 鏡頭拍攝整合 (HTML5 MediaDevices)
- 透過 `navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } })` 啟動裝置鏡頭。
- 快門觸發時，繪製至 HTML5 `<canvas>` 並調用 `canvas.toBlob(..., 'image/jpeg', 0.85)` 轉為 Blob File。
- 支援多張連續快門拍攝，照片自動推入批次上傳佇列。

### 15.3 網頁端批次上傳併發控制
- 支援同時選擇多個圖檔或拍攝多張照片。
- 使用 `Promise.allSettled` 並發請求 POST `/api/problems`（以 `source` 欄位帶入預設考卷名稱）。
- 每個請求獨立上傳至 R2 並進入 D1，靜默觸發背景 Gemini 課綱打標。
