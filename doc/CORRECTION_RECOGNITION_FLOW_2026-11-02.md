# 訂正後自動整理與確認

日期：2026-11-02。分支：`codex/personal-analysis-foundation`。

本文件取代先前「訂正前可開啟辨識確認」及「重新辨識只看原圖」的流程。產品定位是協助使用者整理自己的訂正思考與錯因，不以 AI 解答取代訂正。

2026-11-03 後續更新：顯示統一採 Markdown／LaTeX，錯因改為具體且可跨題沿用的短語，訂正提示版本為 `correction-v3`；詳見[公式渲染與短錯因](./MATH_MARKDOWN_AND_ERROR_REASONS_2026-11-03.md)。下方 `correction-v2` 是筆色與視窗調整的歷史紀錄。

## 2026-11-03：手動整理可關閉視窗與原作答筆色線索

- 按「依目前筆跡重新整理」後，可以用關閉按鈕、Esc 或點擊背景離開視窗，繼續其他題目；關閉不會中止合成圖待送紀錄或辨識請求。只在採用／儲存確認資料的短暫期間鎖定關閉。
- 開始合成圖片即顯示背景處理狀態，重開視窗仍顯示整理中並防止重複送出。結果完成後只標示待確認，不自動開啟視窗；開著的視窗會呈現新建議供確認，原已確認版本保留到明確採用為止。
- 背景失敗仍保留錯誤與重試入口；視窗尚未關閉時也不重複顯示相同錯誤。切換帳號／題目會清除元件內的舊狀態，舊請求結束不能改掉新帳號的處理狀態。
- 背景處理指網站工作階段中的非阻塞作業，沒有新增作業系統背景服務。若整個網站被關閉，已保存在 IndexedDB 的合成圖可在下次進入、連線及登入原帳號後重試。
- 上傳原圖與訂正整理共同採用 `worker/services/ai/originalAnswerPromptRules.ts`：作答區的非紅筆圈選、填答與計算是原作答候選，紅筆通常視為批改或訂正；結合位置、劃除與內容判斷，不能只依筆色、不從正解反推原作答。看不清仍可留空。
- 已存入題的原圖筆跡不因筆色而歸屬本人，仍只沿用已知的本人原作答。訂正提示版本升為 `correction-v2`，後續手動辨識不重用舊提示版本的結果；不批次重跑舊題，不更換一般辨識模型。
- TypeScript、正式建置與訂正／PWA 測試驗證；瀏覽器使用模擬 API、真實 IndexedDB 待送及合成圖片，驗證關閉／重開、元件卸載、完成預覽、失敗重試與儲存保護。筆色規則尚未以真實手寫題庫量測，不宣稱模型辨識準確率已提高。

## 已實作流程

1. 上傳辨識仍沿用既有模型，背景保存題文、題型、選項與可辨識的原作答。單題辨識確認入口在訂正前鎖定，不因缺資料顯示紅點。
2. 使用者自行書寫訂正、補充本人筆記，再按「完成訂正」。若仍有正在書寫的一筆或輸入法組字，先提示完成目前輸入，避免漏掉最後內容。
3. 捕捉按鈕當下的本人筆跡與文字筆記，將原圖與本人筆跡合成一張 JPEG。計算區包含在圖中，不合成他人的參考筆跡；即使畫面暫時隱藏筆跡，仍使用本人保存的訂正內容。
4. 合成圖先以位元組保存在獨立、依帳號隔離的 IndexedDB 待送紀錄，再前往下一題。AI 請求在頁面層執行，不跟隨單張卡片卸載而消失；若合成或本地保存失敗，訂正完成仍保留，提示稍後手動整理。
5. 同一次模型呼叫整理原作答、正解、可能錯因及訂正重點，不建立額外的推測答案步驟，也沒有獨立的「訂正後答案」欄位。
6. AI 結果保存為待採用建議，不直接修改學習資料與確認狀態。入口提示有結果待確認，不強制彈出視窗。
7. 使用者方便時開啟彈窗。原作答及正解可修正或留空；AI 錯因用勾選方式呈現，預設不選，另可自行補充。訂正重點可修改或清空；題型、題文及選項收在可展開的編輯區。
8. 按「採用並確認」後才建立新版本，保存勾選的錯因與整理內容。答案、原作答或錯因留空都能確認，不再因這些缺漏顯示紅點。僅開啟或取消不等於確認。

整題確認狀態仍只有 `ai`／`confirmed`。辨識請求的 pending／complete／failed 是背景作業狀態，不是第三種題目確認狀態。

## 邊界處理

| 情況 | 行為 |
| --- | --- |
| 原作答未寫、看不清或被遮住 | 保留已有紀錄，否則留空，不以訂正答案冒充原作答 |
| 正解缺漏 | 同一次辨識可解題提出建議；不能確定時留空，確認後練習仍可自評 |
| 舊資料已確認 | 保留舊版本；新建議顯示為 AI 辨識，不沿用舊確認 |
| 辨識途中修改題目資料 | 本次結果失敗並保留原資料，需重新整理；不覆蓋新編輯 |
| 新的辨識已取代舊建議 | 舊建議不能再採用，後端在寫入交易中核對最新作業與版本 |
| 訂正後繼續修改筆跡 | 已產生建議仍代表先前按完成當下的快照；可手動依目前筆跡重新整理，不每筆書寫都呼叫 AI |
| 重複完成、網路重送 | 依帳號、題目、合成內容、本人筆記、來源識別、提示版本及模型去重；正常重送沿用結果 |
| 手動重新整理 | 使用目前筆跡與資料版本，允許重新產生建議；同一版本的重送仍去重 |
| 未連線或訂正狀態尚未同步 | 保留當下合成圖片，連線後重試；不把後來的筆跡替換成當時快照 |
| AI 回應失敗 | 不撤回訂正完成，不清除本機快照，提供手動重試 |
| 使用者撤回訂正完成 | 重新鎖定入口，取消尚待送出的快照；已開始的辨識也不會自動採用 |
| 切換帳號 | 中斷目前連線，待送紀錄依帳號索引讀取；送出前再次檢查帳號，不以新帳號傳送前帳號圖片 |
| 已存入題目 | 使用保留來源版本，只合成本人的工作層；原圖作者的作答不當作本人原作答 |
| 刪除個人題目／帳號 | 後端候選紀錄隨關聯刪除；不可再取得或採用 |

已載入的原圖元素可直接用於合成，避免離線時重新下載相同原圖。尚未載入原圖或儲存空間不足時，無法保證產生快照；原有筆跡儲存與同步流程保持獨立。

## 資料與分析

- 新增 `0018_correction_recognition.sql`，建立 `learning_corrections`，保存候選結果、資料基準版本、去重雜湊、執行權杖、租約及採用版本。合成圖不另存伺服器，僅隨請求傳入；本機成功收到完成結果後清除待送圖片。
- 新 API：`POST /api/learning/:kind/:id/correction`，multipart 包含一張 JPEG、來源識別、本人筆記與手動整理標記。先驗證持有權與訂正狀態，圖片上限 2 MB，使用串流空白維持 JSON 請求連線。
- 採用沿用版本化 PATCH，另傳 `correctionId`；後端同一交易核對候選與學習版本並標記採用，不能跨帳號、跨題或重複採用。
- `personal.errorReasons[].accepted` 記錄 AI 錯因是否被勾選，`personal.correctionSummary` 保存使用者採用的訂正重點。不勾選的候選只留在候選紀錄，不寫入個人的已採用錯因。
- 整科分析只讀本人自述或已勾選錯因，並讀取已採用的訂正重點。訂正內容不能當成獨立重作或已掌握證據；歷史作答、正解依據與既有報告保持原快照。
- 前端待送紀錄獨立於舊題目修改合併佇列，ArrayBuffer 避免部分 WebKit 環境無法保存 Blob；每帳號／題目保留最新待送快照，舊請求回應不能刪掉新快照。

目前填空題仍使用文字答案欄位；逐空建模及逐空 UI 尚未納入這次流程變更。

## 本地升級與驗證

停止本地 Worker 後，在專案根目錄執行：

```powershell
node scripts/apply-practice-schema.mjs --target=local --check
node scripts/apply-practice-schema.mjs --target=local --apply
node scripts/init-local-db.mjs --check
```

腳本已同步新增 0018，備份本地 D1 並跳過已完成的 0015～0017。部分結構不一致時停止；不重跑整份 schema。功能沿用後端 `LEARNING_ENABLED`；前端開關已移除，最新配置與 0014～0020 統一檢查方式見[發布操作文件](./ANALYSIS_RELEASE_RUNBOOK_2026-11-03.md)。本次視窗及提示詞調整不需要新增 migration。

驗證涵蓋：一張合成圖的模型請求、訂正前禁止辨識、權限、去重、確認空白答案、明確採用錯因、已確認內容保護、過期建議拒絕、辨識中編輯、存入題本人作答隔離、失敗重試與刪除清理。瀏覽器以模擬 API 實際驗證合成 JPEG、完成後前往下一題、錯因預設不勾選、全空白確認後零紅點、新結果不繼承確認，以及網路失敗保留快照／重送。

這些是功能與同步驗證，不等於實際手寫題庫或 iPad 實機的辨識品質驗收。
