## 1. 系統概述 (System Overview)

Redolve 是一款專為 iPad + Apple Pencil 深度最佳化的 Serverless PWA 錯題本系統。主打「心流式刷題（無縫滾動）」、「雙手協同手勢」與「AI 自動化標籤」。系統全面採用 Cloudflare 邊緣運算生態系，並導入標準 SaaS 多使用者驗證架構，實現跨裝置安全存取與資料完全隔離。

### 1.1 核心技術堆疊 (Tech Stack)

| 層級 | 技術選型 | 說明 / 備註 |
| :--- | :--- | :--- |
| **前端 (Frontend)** | React 18, Vite (SPA), TypeScript, Tailwind CSS, Zustand, `@tanstack/react-virtual` | 效能優化與虛擬列表 |
| **繪圖引擎 (Canvas)** | HTML5 原生 `<canvas>` + `perfect-freehand` | 支援向量點位 + 局部擦除遮罩 |
| **離線快取 (PWA Storage)** | Service Worker + IndexedDB | 離線筆跡佇列與無感自動背景同步 |
| **後端 API (Backend)** | Cloudflare Workers (Hono Framework) | Edge Runtime |
| **資料庫與儲存** | Cloudflare D1 (SQLite) + Cloudflare R2 | 關聯式資料 (含 draw_data) 與物件儲存 (題目圖片) |
| **課綱快取 (Taxonomy Cache)** | Cloudflare KV | 快取課綱分類樹，減少 D1 查詢 |
| **身分驗證 (Auth)** | better-auth (Google OAuth) + 自建 API Key Middleware | 雙軌驗證機制 |
| **AI 整合 (AI)** | Google Gemini 2.5 / 3.5 Flash API (透過 AIService 抽象層) | Structured Outputs 視覺辨識 |

## 3. 身分驗證與安全架構 (Auth & Security)

### 3.1 雙軌驗證機制 (Dual Auth Architecture)

系統採用**雙軌驗證機制**，以服務不同的客戶端需求：

1. **PWA 網頁端 (人類操作)**：透過 Google OAuth 登入。前端依賴 Session / HTTP-only Cookies 進行驗證，確保 iPad Safari 上的存取安全。
2. **iOS 捷徑端 (機器自動化)**：使用靜態 API Key。使用者在 PWA 後台生成一組專屬 API Key，並填入 iOS 捷徑的 HTTP Header (`Authorization: Bearer <API_KEY>`) 中。
3. **資料隔離 (Multi-tenant Isolation)**：所有對 D1 資料庫的 CRUD 操作，皆須透過 Hono Middleware 攔截並解譯出 `user_id`，所有 SQL 查詢強制附加 `WHERE user_id = ?` 條件。
4. **唯讀分享 Token (Share Token Security)**：產生的分享連結採用加密短 Token `/share/:token`，獨立處理存取權限 (允許/隱藏筆跡)，無需暴露內部 `/api/problems/:id` 端點。

### 3.2 CORS 安全配置 (v3.0.0 新增)

> **v2.0.0 問題**：`app.use('*', cors())` 未限制 origin，等於開放所有第三方網站向 API 發起跨域請求，可能搭配使用者 Session Cookie 造成 CSRF 風險。

**採用策略：Origin Allowlist**

```typescript
// worker/index.ts
const ALLOWED_ORIGINS = [
  'https://redolve.pages.dev',          // 正式 PWA domain
  'https://<your-custom-domain>.com',   // 自訂網域（若有）
];

app.use('*', cors({
  origin: (origin) => {
    // 開發環境允許 localhost
    if (origin?.startsWith('http://localhost:')) return origin;
    return ALLOWED_ORIGINS.includes(origin ?? '') ? origin : undefined;
  },
  allowHeaders: ['Content-Type', 'Authorization'],
  allowMethods: ['GET', 'POST', 'PUT', 'PATCH', 'DELETE'],
  credentials: true,   // 允許 Session Cookie 跨域傳遞
}));
```

### 3.3 API Key 安全強化 (v2.0.0)

- 生成時以 bcrypt / argon2id 雜湊，**明文 Key 僅在生成當下顯示一次**，之後永不可再取得。
- 資料庫僅存 `key_hash` 與供顯示用的 `key_prefix`（`rdv_xxxxxxxx****`）。
- 認證時取出該使用者所有 Hash 逐一比對（每用戶 Key 數量極少，效能可接受）。

## 4. 資料庫綱要設計 (Database Schema - Cloudflare D1)

### 4.1 完整 Schema (v3.0.0)

```sql
-- 使用者帳號表 (Google OAuth 寫入)
CREATE TABLE IF NOT EXISTS users (
    id         TEXT PRIMARY KEY,
    email      TEXT UNIQUE NOT NULL,
    name       TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- API 授權金鑰表 (供 iOS 捷徑使用)
-- v2.0.0 變更：改為 key_hash + key_prefix，不再明文儲存
CREATE TABLE IF NOT EXISTS api_keys (
    key_hash    TEXT PRIMARY KEY,
    key_prefix  TEXT NOT NULL,
    user_id     TEXT NOT NULL,
    description TEXT,
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
);

-- 課綱分類樹表 (v2.0.0 新增)
CREATE TABLE IF NOT EXISTS taxonomies (
    id        TEXT PRIMARY KEY,
    parent_id TEXT,
    label     TEXT NOT NULL,
    level     INTEGER NOT NULL,           -- 0=科目, 1=單元, 2=子主題
    FOREIGN KEY(parent_id) REFERENCES taxonomies(id)
);

-- 錯題/筆記主表
-- v3.0.0 變更：移除已廢棄的 subject/topic 欄位與對應 Index
CREATE TABLE IF NOT EXISTS items (
    id             TEXT PRIMARY KEY,
    user_id        TEXT NOT NULL,
    type           TEXT NOT NULL,         -- 'problem' | 'note'
    topic_id       TEXT,                  -- FK -> taxonomies.id；NULL = 尚未 AI 分類
    keywords       TEXT,                  -- JSON Array，原始完整關鍵字供顯示
    keyword_tokens TEXT,                  -- 空格分隔的細粒度 token 字串，供 FTS5 索引
    source         TEXT,
    image_url      TEXT NOT NULL,
    draw_data      TEXT,                  -- 向量筆跡 JSON，一般 < 100KB，高密度 < 500KB
    status         TEXT DEFAULT 'processing', -- 'processing' | 'unsolved' | 'resolved'
    review_count   INTEGER DEFAULT 0,
    vector_clock   TEXT,                  -- JSON: {"clientId": "uuid", "seq": 42}
    updated_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(user_id)  REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY(topic_id) REFERENCES taxonomies(id)
);

-- 分享金鑰表
-- v3.0.0 變更：expires_at 語意明確為「使用者不設定則為無期限 (NULL)」
CREATE TABLE IF NOT EXISTS shares (
    token      TEXT PRIMARY KEY,
    item_id    TEXT NOT NULL,
    user_id    TEXT NOT NULL,
    allow_ink  INTEGER DEFAULT 1,
    expires_at DATETIME,                  -- NULL = 永久有效；使用者可手動撤銷
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY(item_id) REFERENCES items(id) ON DELETE CASCADE
);

-- 查詢效能最佳化索引
-- v3.0.0 變更：移除已廢棄的 idx_user_subject_topic
CREATE INDEX IF NOT EXISTS idx_user_status   ON items(user_id, status);
CREATE INDEX IF NOT EXISTS idx_user_topic_id ON items(user_id, topic_id);
CREATE INDEX IF NOT EXISTS idx_user_created  ON items(user_id, created_at DESC, id DESC);

-- FTS5 全文檢索虛擬表
-- v2.0.0 變更：keywords 欄位改為 keyword_tokens（細粒度空格分隔 token）
CREATE VIRTUAL TABLE IF NOT EXISTS items_fts USING fts5(
    id             UNINDEXED,
    user_id        UNINDEXED,
    source,
    keyword_tokens
);
```

### 4.2 Schema 變更說明 (v2 -> v3)

| 表 / 欄位 | v2 | v3 | 原因 |
| :--- | :--- | :--- | :--- |
| `items.subject` | TEXT (migration 緩衝) | 移除 | migration 完成，清除廢棄欄位 |
| `items.topic` | TEXT (migration 緩衝) | 移除 | 同上 |
| `items.draw_data` 體積 | `< 5KB` 描述 | `< 100KB 一般，< 500KB 高密度` | 符合實際 perfect-freehand 資料量 |
| `shares.expires_at` | 語意未定義 | NULL = 永久有效，使用者手動撤銷 | 明確語意 |
| `idx_user_subject_topic` | 存在 | 移除 | 廢棄欄位移除，Index 同步清除 |
| `items_fts.subject` | 存在 | 移除 | 已無 subject 欄位 |
| `items_fts.topic` | 存在 | 移除 | 已無 topic 欄位 |

## 5. AI 服務架構 (AI Service Layer)

### 5.1 AIService 抽象層 (v2.0.0)

```
src/
  services/
    ai/
      AIService.ts     -- interface 定義
      GeminiService.ts -- Gemini 實作
      index.ts         -- 工廠函式 (依 env.AI_PROVIDER 動態選擇)
```

```typescript
export interface TagResult {
  topic_id:       string;
  keywords:       string[];
  keyword_tokens: string[];
}

export interface AIService {
  tagProblem(imageUrl: string, taxonomyTree: TaxonomyNode[]): Promise<TagResult>;
}

export function createAIService(env: Env): AIService {
  switch (env.AI_PROVIDER ?? 'gemini') {
    case 'gemini': return new GeminiService(env.GEMINI_API_KEY);
    default: throw new Error(`Unknown AI provider: ${env.AI_PROVIDER}`);
  }
}
```

### 5.2 AI 標籤失敗行為規範 (v3.0.0 新增)

> **v2.0.0 缺失**：TDD 未定義 Gemini API 呼叫失敗（含 rate limit 超限）後的具體行為，導致 `status` 永遠卡在 `processing`。

**採用策略：指數退退重試 + 靜默降級**

```typescript
// worker/services/ai/GeminiService.ts
async tagProblem(imageUrl, taxonomyTree): Promise<TagResult | null> {
  const MAX_RETRIES = 3;

  for (let attempt = 0; attempt < MAX_RETRIES; attempt++) {
    try {
      const result = await this.callGeminiAPI(imageUrl, taxonomyTree);
      return result;
    } catch (err) {
      if (attempt < MAX_RETRIES - 1) {
        // 指數退退：500ms, 1000ms, 2000ms
        await new Promise(r => setTimeout(r, 500 * Math.pow(2, attempt)));
        continue;
      }
    }
  }
  return null; // 全部重試失敗
}

// worker handler
ctx.waitUntil(
  aiService.tagProblem(r2Url, taxonomyTree).then(async result => {
    if (result) {
      // 成功：寫入 topic_id / keywords / keyword_tokens
      await db.update(items).set({
        topic_id: result.topic_id,
        keywords: JSON.stringify(result.keywords),
        keyword_tokens: result.keyword_tokens.join(' '),
        status: 'unsolved',
      }).where(eq(items.id, problemId));
    } else {
      // 失敗（含額度超限）：靜默降級，保留 topic_id=null
      await db.update(items).set({
        status: 'unsolved',  // 不卡在 processing
        // topic_id / keywords / keyword_tokens 保持 NULL
      }).where(eq(items.id, problemId));
    }
  })
);
```

**前端對應顯示邏輯**：

- `status === 'processing'`：顯示「AI 辨識中...」Spinner。
- `status === 'unsolved'` 且 `topic_id === null`：顯示橘色 Badge「尚未分類 — 點此編輯」，引導使用者前往 `PUT /api/problems/:id` 手動設定。
- `status === 'unsolved'` 且 `topic_id !== null`：正常顯示。

**Rate Limiting 策略**：不在 Worker 端加入 Rate Limit。AI 額度超限時同樣觸發上述靜默降級流程。未來若有需求，可在前端題目詳情頁加入「重試 AI 分類」按鈕，呼叫 `POST /api/problems/:id/retag`（v3.x 考量）。

## 6. API 路由設計 (Hono Router)

### 6.1 身分驗證與捷徑用戶端模組 (`/api/auth/*` & `/api/keys`)

- `GET/POST /api/auth/*`：由 better-auth 接管，處理 Google 登入、登出與 Session 驗證。
- `POST /api/keys`：生成 bcrypt hash，**僅在此次回應回傳明文 Key，之後永不可再取得**。
- `GET /api/keys`：列出所有 API Key（以 `key_prefix` 打碼顯示，如 `rdv_a1b2c3d4****`）。
- `DELETE /api/keys/:hash`：撤銷特定 API Key。
- **iOS 捷徑規範**：上傳前強制轉為 1080p / 80% JPEG (`< 500KB`)；無網路時暫存 iOS 本地佇列，恢復後背景補傳。

### 6.2 錯題資源模組 (`/api/problems`)

> *所有路由受 Auth Middleware 保護，自動提取 `user_id`*

- `POST /api/problems`：
  1. 接收 `FormData`（壓縮後 JPEG）。
  2. 寫入 R2 + D1，回傳 200 OK（不阻塞）。
  3. `ctx.waitUntil()` 背景呼叫 AIService，3 次指數退退重試，失敗時靜默降級（見 5.2 節）。
- `GET /api/problems`：Cursor-based 分頁（見 6.4 節），支援 `topic_id` / `status` 過濾。
- `GET /api/problems/:id`：單題完整 Metadata。
- `PUT /api/problems/:id`：手動修正 Metadata（`topic_id`、`keywords`）。
- `DELETE /api/problems/:id`：刪除錯題與 R2 圖片。

### 6.3 分享模組 (`/api/problems/:id/share` & `/share/:token`)

- `POST /api/problems/:id/share`：生成分享 Token 並寫入 `shares` 表；`expires_at` 預設 NULL（永久有效）。
- `DELETE /api/problems/:id/share/:token`：使用者手動撤銷分享連結。
- `GET /share/:token`：公開路由，無需 Auth。Worker 校驗 Token 存在性與 `expires_at`（若非 NULL），回傳題目與筆跡。

**Token 生命週期規範 (v3.0.0)**：
- `expires_at = NULL`：永久有效，使用者可於任何時候呼叫 DELETE 撤銷。
- `expires_at` 有值：Worker 在 `GET /share/:token` 時檢查 `expires_at < CURRENT_TIMESTAMP`，過期則回傳 410 Gone。
- 不實作自動清除 Cron，過期 Token 保留在 DB 供查閱，不影響效能。

### 6.4 Cursor-based 分頁規範 (v2.0.0)

游標格式：`(created_at DESC, id DESC)` 複合游標，Base64 URL-safe 編碼。

```typescript
// GET /api/problems?cursor=<base64>&limit=20&topic_id=math-prob&status=unsolved
const [cursorDate, cursorId] = cursor ? decodeCursor(cursor) : [null, null];

const rows = await db.select().from(items)
  .where(and(
    eq(items.user_id, userId),
    topicId ? eq(items.topic_id, topicId) : undefined,
    status  ? eq(items.status,   status)  : undefined,
    cursorDate ? or(
      lt(items.created_at, cursorDate),
      and(eq(items.created_at, cursorDate), lt(items.id, cursorId!))
    ) : undefined,
  ))
  .orderBy(desc(items.created_at), desc(items.id))
  .limit(limit + 1);

const hasMore    = rows.length > limit;
const nextCursor = hasMore ? encodeCursor(rows[limit - 1]) : null;
return c.json({ items: rows.slice(0, limit), nextCursor });
```

**Index 依賴**：`idx_user_created ON items(user_id, created_at DESC, id DESC)`。

### 6.5 高頻狀態與離線同步模組

- `PATCH /api/problems/:id/draw`：Debounce 2s，寫入向量筆跡（`draw_data`，D1 TEXT，一般 `< 100KB`）。含 vector_clock 衝突檢測（見第 7 節）。
- `PATCH /api/problems/:id/status`：切換 `unsolved` <-> `resolved`，觸發 `review_count` 累加。
- **PWA 離線佇列**：Service Worker 監聽 `online` 事件，連線恢復時按順序批次同步。

## 7. 離線同步衝突解決 (Offline Conflict Resolution)

Vector Clock + Server Last-Write-Wins（詳見 v2.0.0 設計，本版無變動）。

**Client 端**：

```typescript
const clientId = localStorage.getItem('rdv_client_id')
  ?? (() => { const id = crypto.randomUUID(); localStorage.setItem('rdv_client_id', id); return id; })();

const op: SyncOperation = {
  problemId,
  draw_data,
  vector_clock: { clientId, seq: ++localSeq },
};
await idbQueue.add('sync_queue', op);
```

**Server 端**（`PATCH /api/problems/:id/draw`）：

```typescript
const incomingSeq = JSON.parse(incoming ?? '{"seq":0}').seq;
const currentSeq  = JSON.parse(current?.vc ?? '{"seq":0}').seq;

if (incomingSeq >= currentSeq) {
  await db.update(items).set({ draw_data, vector_clock: incoming, updated_at: new Date().toISOString() })
    .where(eq(items.id, problemId));
  return c.json({ status: 'ok' }, 200);
} else {
  return c.json({ status: 'conflict', current }, 409);
}
```

## 8. 中文全文搜尋 (FTS5 Chinese Search)

AI 輸出雙層關鍵字，FTS5 索引細粒度 token（詳見 v2.0.0 設計，本版無變動）。

```sql
SELECT i.* FROM items i
JOIN items_fts fts ON i.id = fts.id
WHERE fts.keyword_tokens MATCH '機率' AND i.user_id = ?
UNION
SELECT i.* FROM items i, JSON_EACH(i.keywords) kw
WHERE kw.value LIKE '%機率%' AND i.user_id = ?
```

| :--- | :--- |
| `status === 'processing'` | 灰色「AI 辨識中...」Spinner |
| `status !== 'processing'` 且 `topic_id === null` | 橘色 Badge「尚未分類 — 點此編輯」，連結至 PUT 編輯頁 |
| `topic_id !== null` | 正常顯示 taxonomy label |

### 9.3 核心互動實作

觸控分離、掌壓防誤觸、雙手協同、虛擬滾動、動態長高畫布、智慧反色模式（詳見 v2.0.0 設計，本版無變動）。

前端 `@tanstack/react-virtual` 的 `fetchNextPage` 觸發傳遞 `cursor` 參數（v2.0.0）。

### 9.4 低對比設計系統 (Design System)

配色 Token、Soft Elevation、圓角、Subtle Feedback、護眼反色 CSS 濾鏡（詳見 v2.0.0 設計，本版無變動）。
