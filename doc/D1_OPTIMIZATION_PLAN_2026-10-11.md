# D1 查詢成本優化

狀態：本機實作與驗證；尚未推送。正式環境成本須部署後確認。

## 本次範圍

- [x] 空白關鍵字瀏覽不查 OCR FTS、不比對文字、不計算相關度。
- [x] 未選擇科目時不載入題目大綱；選擇後只載入該科目範圍。
- [x] 隱藏刷題側欄搜尋，提供套用目前範圍的「前往搜尋」。

- [ ] 其他成本優化僅規劃，見待辦。

## 已實作契約

### 空白查詢

- `q.trim()===''` 且 `browse=1`：組合原有來源／分類／標籤／狀態／權限篩選，按建立時間、新到舊排序。
- 不組合 `fts_hits` CTE、`items_fts` JOIN、逐題 `MAX(rowid)`、`LIKE` 搜尋條件或相關度運算。`relevance_score=0`，回應格式維持相容。
- 單一來源按 `created_at DESC,id DESC`；多來源保留 `created_at DESC,origin,id DESC` 的穩定順序。移除單一來源的常數 origin 排序，讓現有索引可在取得一頁後停止。
- 沒有 `browse=1` 的空白搜尋仍回傳空結果。非空關鍵字保留原搜尋行為。
- 全部路徑保留本人、目前集合權限、貢獻者資格、圖片 ready、generation、訂閱與授權期限檢查。訂閱仍不能取代觀看權限。
- 存入題仍以已取得 snapshot 與私人工作區讀取，來源撤權或刪除不會使存入版本消失。
- 一般共用題回應保留原有授權筆記摘要；`metadata_only=1` 不聚合用於顯示的共用筆記。空白存入瀏覽不聚合參考層筆記作搜尋評分。

### 搜尋頁精簡投影

- 空白輸入仍使用 `/api/search?browse=1` 作分頁列表，並非全文搜尋；保留目前來源、分類、狀態、標籤及權限。只有提交非空關鍵字才套用文字搜尋條件。
- `projection=compact`：回傳圖片存取所需 ID、來源與分類等清單欄位；不回填 `problem`，不傳筆跡／筆記／標籤資料。圖片由原本授權圖片 API 載入。
- 上傳題不執行完整 `items` hydration；空白存入列表不 JOIN `personal_workspaces`；空白共用列表不聚合顯示筆記。非空查詢仍可搜尋有權限的筆記／標籤，不因省略回應欄位而漏掉命中。
- `projection=full` 為 API 預設，相容原客戶端。詳細檢視與刷題維持完整資料流程；metadata 大綱仍以 `metadata_only=1` 取得。
- 前端快取鍵包含精簡／完整模式，切換到詳細檢視會取得完整題目，不能使用精簡資料代替。簡單檢視不覆寫刷題的完整題目 store。
- 搜尋頁不查題目所屬共用集；上傳／存入搜尋不載入未使用的可貢獻集合清單。共用中搜尋仍取得集合選單，刷題仍保留加入集合與已共用標示。
- 訪客只有空白字元時視為本機列表，與後端 trim 行為一致。

### 科目大綱

- 所有科目：主要題目列表照常載入、可手動載入更多；大綱 metadata 請求為零。
- 保留完整分類樹與展開狀態，未載入的數字不顯示為真實零題。提示「選擇科目後載入題目大綱」。
- 選擇科目、其下單元或未分類：大綱請求帶入科目根節點／未分類，保留來源、共用集、狀態、標籤與既有關鍵字條件。
- 同科目內切換單元沿用該科目大綱，不重新遍歷整個題庫。回到所有科目時取消先前請求並清空舊大綱。
- 已選科目仍會分頁取得該科目大綱，不在本次改為新的彙總 API。

### 側欄前往搜尋

- 移除側欄搜尋輸入與提交；搜尋頁保留既有搜尋框。
- 導向 `/search`，帶入目前上傳／存入／共用中、共用集、科目與單元、標籤、狀態及既有關鍵字。
- 不帶入題目 focus 或舊檢視模式；個人來源不帶共用集篩選。
- 刷題預設排除封存時，以 `exclude_archived=yes` 保留範圍；搜尋頁重新套用或清除篩選後依其新選擇計算。
- 點按只切換頁面，不更新刷題篩選或重排刷題列表；瀏覽器返回沿用既有位置／題目快取機制。

## 成本驗證

本地 Miniflare D1 合成資料：219 題、219 OCR FTS 紀錄；未分類、相同時間戳，測試實際搜尋 route 產生的 SQL。不代表正式帳號及所有篩選組合的成本。

| 查詢 | 修改前 rows_read | 修改後 rows_read |
|---|---:|---:|
| 空白上傳瀏覽，30 題＋1 筆續頁判斷 | 5,039 | 31 |
| 空白上傳 metadata，50 題＋1 筆續頁判斷 | 5,039 | 51 |
| 空白上傳第二頁，offset=30、limit=30 | 未取基準 | 61 |
| 非空關鍵字 vector，30 題＋1 | 49,275 | 49,275 |

- 空白單來源執行計畫使用 `idx_user_created`，不掃 FTS、不使用臨時排序樹。
- 第二頁仍使用 offset，成本包含跳過前頁；深頁成本是待辦。
- 上表未包含完整資料 hydration；full 模式仍保留該查詢，compact 模式跳過。
- 補充完整路由量測（相同 219 題 fixture、30 題首頁，包含 hydration，不含登入驗證）：舊 full 列表共讀取 250 列，新 compact 列表 31 列；取消一條 hydration 查詢。不是正式環境或所有篩選組合的保證。
- 科目、標籤與權限篩選可能讀取更多候選列，不能把 31 當作所有查詢的保證。

## 待辦：本次不實作

| 優先度 | 問題 | 建議方案 | 驗收條件 |
|---|---|---|---|
| P1 | 關鍵字搜尋每題重新查 FTS 最新 rowid，且舊重複列處理成本高 | 評估唯一 OCR 文件／穩定 rowid 映射；一次取得有效命中。保留中文 substring 與 phrase 語意，先量測再決定 migration | 重複舊索引不命中；OCR 與 metadata 一致；比較 219／大量題庫 rows_read，無跨帳號洩漏 |
| P1 | `SELECT * FROM items WHERE user_id=? AND id IN (...)` 實際選用按使用者的索引，仍掃本人多筆題目 | 檢查 planner、既有複合索引與必要欄位；評估 `(user_id,id)`，避免強制索引掩蓋問題 | 同帳號 30 IDs 的掃描接近結果數；他人 ID 零回傳；新增索引才安排 migration |
| P1 | 已選科目大綱仍會全量分頁 | 分開單元彙總與題目大綱分頁；只對展開／需要導航的節點載入，保持既有分類樹及返回位置 | 不逐頁拉完整科目才可操作；計數不冒充完整值 |
| P2 | 有關鍵字時，共用筆記多次聚合於篩選、評分與摘要 | 先依目前授權／generation 形成可讀文字，再重用；評估執行計畫，避免 CTE 意外全量 materialize | 撤權／過期即時生效，notes 與 ink 的可見性獨立；成本下降 |
| 已完成 | 簡單搜尋也可能取得大筆 draw_data／typed_notes | `projection=compact` 精簡投影；詳細與刷題使用 full；快取鍵區分模式 | 精簡檢視維持圖片、來源、分類；切換詳細取得完整題；前往刷題保留範圍 |
| P2 | 共用題卡重複取得個人檔案或相同權限資訊 | 前端按帳號／scope 共用請求及短期快取；權限仍在服務端逐請求驗證 | N 題不產生 N 次相同個人檔案請求；切帳號清空，撤權仍立即拒絕 |
| P2 | 深頁 offset 掃描逐步增加 | 評估建立時間＋ID／來源的 keyset cursor，兼容返回位置與刪除／封存後續載 | 大量頁數成本穩定、同時間戳不重複漏題、返回仍正確 |
| P3 | 開啟頭像需取得多份統計／個人檔案／集合資料 | 必要時新增精簡帳號摘要 API；目前只在開啟時載入，優先度低於搜尋 | 每次開啟呼叫數下降，部分失敗不可顯示成零 |

保留現有索引式驗證 session／使用者查詢；不能以減少請求為由跳過驗權。
