# 訂正證據與階段報告重構規劃

本文件記錄 2026-11-04 草案經討論後的修訂，供後續實作與驗收。現行觸發、時間範圍與比較基準見[最新統計與階段分析](./ANALYSIS_CYCLES_2026-11-02.md)。

## 已確認的範圍

- 報告以整科為單位，由使用者手動觸發。首次建立基準，後續距上一份成功報告完成滿 72 小時，且至少有一筆實質變化，才可生成。報告沿用前次資料截止點，「最新」的天數篩選只影響即時統計。
- 訂正由使用者完成。報告根據已保存的證據整理共通問題與複習方向，具體考點或錯因須附可核對的原題引用。資料少時可以只交代變化及限制，允許空的 `findings`。
- 訂正筆記原文維持在現有的上傳題與存入題個人工作區。報告及追問沿用訂正摘要、本人填寫或勾選採用的錯因和重作紀錄。筆記原文與獨立筆記快照從 P0 移除。
- 題目考點使用既有 `tags`，對應上傳題的 `items.keywords` 或存入題保留版本的標籤。`error_tags` 專供錯誤類型彙整。資料模型維持無 `concept_tags`、`correction_image_ref`。報告與追問使用文字及結構化資料，訂正合成圖依既有辨識流程暫時使用。
- AI 詳細解讀與追問沿用 90 天保存期，數字摘要長期保留。跨報告發現的保存方式留到 P1 定義。

## 錯誤標籤試行規格

以下是第一版試分類。以實際錯因驗證分類能否重現、是否能引導不同的複習動作，再定正式碼表。報告可同時呈現考點、具體錯因及其分類。例如考點為「半角公式」，具體錯因為「未檢查角度範圍就選正負號」，分類為「漏查條件或範圍」。

| 候選代碼 | 顯示名稱 | 適用依據 |
| --- | --- | --- |
| `misread_task` | 讀錯題意 | 誤讀題目要找的目標、方向或作答要求，例如題目要找不成立的選項，卻在找成立的選項。 |
| `missed_condition` | 漏查條件或範圍 | 漏掉定義域、參數限制、分母非零、角度範圍或定理的適用條件。 |
| `concept_misunderstood` | 概念或性質理解有誤 | 有證據顯示誤解定義、公式關係或性質，例如把內積分配律寫成另一條規則。 |
| `invalid_method` | 解法或步驟不當 | 具體策略或推論步驟無法推出結論，例如拿單一特例證明一般命題。 |
| `calculation_error` | 計算或代換出錯 | 可定位到代入、符號、展開或運算錯誤。 |
| `work_incomplete` | 作答未完成 | 有證據顯示停在中間步驟、漏驗一個選項或缺少最後一步。單憑空白答案無法分類。 |

### 歸類、來源與統計

1. 每個標籤須回指具體錯因。單條錯因先選最直接的一類。一題若有各自具證據的多條錯因，可有多類。證據不足或無法穩定歸類時保留錯因原文，標籤留空。
2. 區分易混邊界。誤解題目要找什麼歸「讀錯題意」，漏套限制歸「漏查條件或範圍」。明確誤解規則歸「概念或性質理解有誤」，現有證據只指出推論步驟無效時歸「解法或步驟不當」。從「半角公式正負號寫錯」單句無法判定是哪一類時，保留原文即可。
3. 逐條沿用現有 `origin` 和 `accepted`。證據可分本人填寫、AI 建議經本人採用、AI 建議尚未採用。整題的確認狀態獨立處理。現有流程可能移除未採用的建議，缺漏的候選不得回填為已拒絕。
4. 系統從錯因衍生的分類保留來源及對應錯因。本人勾選一條錯因時，確認範圍是該錯因；衍生分類仍標示為系統分類。只有現存且版本相符的未採用 AI 候選可以作為選題線索，與採用錯因分開呈現與計數。
5. 同題同類在分布中只計一次。若同題同類同時有本人填寫或採用的錯因及未採用候選，以本人證據計入已採用分布，候選仍可在個別證據中標示。跨題發現需要能核對的多題證據，單題最多支持單題觀察或待驗證假設。

### 試行配置

分類集中於 [`worker/services/errorTagConfig.ts`](../worker/services/errorTagConfig.ts)。調整 `label` 可改名稱，在 `aliases` 加入完整且明確的錯因短句可擴充分類，`code` 用來識別同一類。比對會正規化全半形、首尾空白及句尾標點。沒有命中或同一句落入兩類時，保留錯因原文。新報告使用更新後的配置，已建立的報告快照沿用當時的分類。第一版無需資料庫遷移或增加環境變數。

## P0 交付

1. 以現有資料版本建立報告快照。在第一階段題目目錄加入既有標籤、精簡訂正摘要、可用錯因及來源，並投影試行 `error_tags`。標籤與考點以現有資料為來源。先以快照內投影實作並記錄題目覆蓋，等量測後再決定是否需要持久化索引。輸入超出預算時須記錄實際覆蓋範圍。
2. 維持兩次 AI 呼叫。第一階段讀精簡目錄與全科統計，選最多 30 題。第二階段讀同一份統計與階段變化，以及選中題目的題文、選項、答案、訂正摘要、錯因及相關重作，撰寫報告。兩階段都按證據來源處理錯因。報告追問依既有流程沿用報告當時的資料。
3. 沿用現有報告格式，提示詞先寫可直接觀察的事實，再列有依據的假設與複習方向。只有一筆新變化時可輸出精簡更新，並維持原有生成門檻。先用現行模型與固定案例比較輸出，等證據品質穩定後再測其他模型。

### 驗收案例

| 輸入 | 預期 |
| --- | --- |
| 題目有「托勒密定理」標籤，訂正只說最後一個選項沒算完 | 歸「作答未完成」，建議重作該選項。現有證據只支持計算未完成。 |
| 一題誤把「選不成立」看成「選成立」，另一題忽略參數正負限制 | 分別歸「讀錯題意」和「漏查條件或範圍」。 |
| 只寫「半角公式正負號錯」，訂正摘要未交代原因 | 保留具體錯因。概念誤解、條件遺漏與運算錯誤仍無法區分，分類留空。 |
| 三題不同單元均有本人填寫或採用的錯因指向漏查條件 | 可提跨單元的條件檢查問題，並引用三題。 |
| 同題有兩條錯因指向同一類，其中一條只是未採用的 AI 候選 | 該題在類別分布計一次，仍保留每條錯因來源的區別。 |
| 滿 72 小時只新增一次答對，或本階段沒有與舊發現相關的重作 | 可依資格生成精簡更新。描述這次答對或證據尚不足，原發現的狀態須等待更多證據。 |
| 存入題的原圖或共享筆記有他人訂正 | 分類和報告只使用可歸屬本人的訂正證據。 |

## 後續階段

- P1 補強選題假設的結構化輸出與第二階段驗證、索引版本、可跨期的 `learning_findings`、證據關聯與更正失效。定義錯誤標籤可由本人修正時的優先順序，以及 90 天到期與刪除政策。
- P2 接上由發現回看原題或重作的行動，拆分選題／報告／追問模型配置。在相同資料集比較選題覆蓋、推論忠實度、引用切題度、延遲和每份可用報告的成本。

## 本次程式進度

- 後端將錯因分類按題去重，分開提供本人填寫或採用、以及僅有未採用建議的題數。選題先產生有題目 ID 的候選假設，報告撰寫再用詳細證據核對。超過證據預算而未載入的題目，不會透過候選假設送給報告模型。
- 報告可從每項發現已引用的題目中推薦最多五題重作，沿用既有的練習入口。沒有適合題目時可省略該入口。舊報告沿用原有引用題組。
- 選題、寫報告、追問可各自覆寫 Gemini 模型。Worker 記錄模型、提示詞版本、延遲，以及上游提供的 token 用量。尚未完成跨供應商實測。
- 跨報告持續性發現的資料模型、配對與到期清除仍需獨立交付。

## 圖片訂正、弱點追蹤與整輪結算

這一階段以本人確認的具體失誤為證據。題目考點沿用既有標籤，廣義錯因分類仍由可配置規則推導。高中數學的 30 項弱點放在 [`src/types/weakness.ts`](../src/types/weakness.ts)，使用穩定 ID。其他科目可從個人弱點清單開始。

- 圖片訂正沿用合成圖，文字筆記選填。模型回傳最多四個具體候選，優先比對本次提供的弱點 ID。無法配對時保留可勾選的錯因文字，也可以用候選名稱與驗證動作建立個人弱點。舊版字串候選仍可讀取。辨識本身不會建立或確認弱點。
- 同一套弱點選擇介面用於訂正與練習結算，可搜尋、新增、取得 AI 建議。補充建議使用可取得的文字資料；本次重作只有最後答案時，候選標為情境推測。訂正確認保存在既有題目版本內。
- 最後一題後顯示逐題結算，答錯和略過排前。答錯題可確認本次弱點，作答照原流程先存本機。弱點標記待作答同步後可儲存，之後也能從重作紀錄補記或撤回。後端以作答 ID 及版本防止重複計數與覆蓋他人的更新。
- 科目「最新」可展開弱點追蹤，查看已關聯題目、本期確認、再次出現、同題重作答對與隔一週未看原圖仍答對。報告會讀取當時有效的弱點證據。已確認的弱點與作答證據隨來源保留，AI 詳細報告仍使用原有保存期。模型只收到文字和結構化資料。
- 首版以現行 Gemini 為基準。類似題生成、獨立驗算、異題方法判定及長期練習清單安排在第二階段。那一階段以能獨立驗證正解的題型開始，並把作答完成與方法驗證分開。

本地有既有資料庫時執行 `node scripts/apply-practice-schema.mjs --target=local --apply`。正式發布前用相同腳本的 `--target=remote --check` 檢查，確認需套用 `0021_weakness_evidence.sql` 時，再使用 `--target=remote --apply`。`node scripts/check-release-schema.mjs --target=remote` 會一併檢查早期遷移與星號 schema。
