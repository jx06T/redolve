# 最新統計與階段分析

日期：2026-11-02。使用者已同意實作；取代舊文件中「報告選擇天數、固定兩期比較、頁尾目前統計」的流程。分支：`codex/personal-analysis-foundation`。

## 使用流程

1. 各科首頁仍顯示目前題庫與所選天數的作答數字，進頁不產生 AI 報告。
2. 進入科目預設開啟「最新」。近 7／15／30／60／90 天只篩選作答時間，不篩除較早收錄的題目；題庫總數明確標示為全科目前持有量。最新頁不再呈現「前期／本期」比較。
3. 「分析報告」獨立顯示生成入口、生成條件、倒序歷史與所選報告。此標籤沒有天數選單，不受最新頁篩選影響。`#latest`／`#reports` 保留標籤位置，`?report=id` 保留報告選擇；舊報告直連可直接開啟報告標籤。
4. 第一份報告是截至當下的「首次學習基準」。之後每份「階段總結」從上份成功報告的資料截止點接續，搭配全科目前題庫及上一份觀察，說明新資料帶來的變化。
5. 成功完成後至少間隔 **72 小時，且有實質新資料**，才可再總結。沒有最低五題／十次等硬門檻；沒有新資料時不重複呼叫模型，可閱讀既有報告與追問。頁面提供下次可用時間、變更數量與「重新檢查」。
6. 等待、失敗或連線中斷時沿用同一份固定快照繼續／重試。失敗不重設三天間隔；讀取歷史、引用及既有追問不受生成間隔限制。生成條件讀取失敗也不阻擋歷史報告閱讀。

報告內維持「總覽、分析重點、數據詳情、追問」四區；長文折疊、灰色底線引用、題目快照彈窗與原題練習入口沿用。舊版固定天數報告保留原內容與「舊版 N 天」標記，不轉換或改寫既有結論。

## 實質新資料

| 訊號 | 計算方式 |
| --- | --- |
| 新增題目 | 上份基準未包含、現在已有可用題文的上傳／存入題。原本未整理的題目補好題文也計入 |
| 學習資料更新 | 同題固定版本的題文、題型、選項、正解、原作答、訂正摘要或已接受／本人填寫錯因發生變化；每題至多計一次 |
| 新作答 | 原始作答事件第一次由伺服器收到，依帳號、科目、原始事件去重 |
| 結果更正 | 舊作答的有效更正事件，獨立列數；不當成多做一次練習 |

確認狀態單獨改變、完全相同的內容另存版本、標題／來源名稱／標籤變更、刪題與同步重送不算實質新學習。這裡判斷的是上次基準與現在保留資料的差異，不是每次編輯動作的累加計數。

最新統計依 `answered_at` 篩選作答日；階段總結依伺服器 `received_at` 接收新資料。離線較早作答在今天補傳，會納入下一份總結，並保留原作答時間。更正的結果歸到原始作答的接收階段，舊階段的結果更正會出現在本階段依據與「結果更正」數量，但不增加本階段練習次數。兩種頁面因時間口徑不同，數字可能不同。

截止點使用毫秒時間與該毫秒已收錄事件 ID，避免同一毫秒稍後到達的事件被漏掉或重複。72 小時從報告**成功完成**起算，資料分界則使用報告**建立快照**的截止點；生成期間的新作答留給下次。

## 後端與 AI

- `GET /analysis/eligibility?subjectId=...` 回傳生成狀態、下次時間、前份／進行中報告 ID、新增題目／資料更新／新作答／結果更正數量；只讀取資料，不呼叫 AI。
- `POST /analysis/reports` 接受科目與時區，不再以 `days` 決定報告範圍；舊客戶端送來的 `days` 不生效，不能藉切換天數繞過條件。後端會重新檢查生成資格。
- `analysis_subject_state` 保存各帳號科目的最後成功報告、資料截止點、成功完成時間、最小版本索引與單一進行中報告指標。建立及完成均使用具條件的 D1 批次交易，避免並行產生兩份或重複模型執行。
- `analysis_report_cycles` 保存每份階段的基準 ID、實際起訖、固定版本索引與時間邊界事件。實際範圍記在 `stats.cycle`；既有 `analysis_reports.days` 因舊 CHECK 限制保留 30 作相容欄位，不能將它顯示為新報告的 30 天範圍。超過 90 天的階段仍可保存。
- 程式計算數字；選題模型收到整科目錄、變更題目 ID 與上一份總結，報告模型收到本次統計、深讀原題及上一份摘要。前份解讀保留長度上限；詳細內容到期時只提供仍可用的數字，明示缺少舊解讀，不虛構記憶。
- 兩階段長度與題目組成可能不同，不以總數／答對比例直接判定能力進退。首次基準不宣稱改善。題目引用仍須是本次實際提供的原題 ID；上一份文字不能充當本次題目依據。
- 提示詞仍獨立於模型，只補階段資料語意；一般題目辨識、模型設定及 Pro 生成新題範圍不變。

詳細解讀、目錄與追問仍保留 90 天，數字摘要長期保存。最小版本 ID／截止點用來接續階段與執行間隔，不保存題文或 AI 原文。刪除私人來源會清理相關報告（包含引用上一份內容衍生的報告），帳號刪除清理狀態；刪除來源本身不重置生成間隔或當成新學習。若上一份報告已被刪除，下一次有實質新資料後可繼續總結，但不提供已刪除的舊解讀。

舊報告尚無成功完成時間，第一次接續時以建立時間作相容起算點，使用當時固定版本與截止點初始化基準，不建立虛構歷史。

## 查詢上限與遷移

新增 `0019_analysis_cycles.sql`，包含上述兩表、成功報告科目索引及作答接收時間索引。已同步 `worker/schema.sql`、初始化／唯讀檢查腳本。不要重跑整份 schema，也不使用已撤回的 0011。

先停止本地 Worker，在專案根目錄執行：

```powershell
node scripts/apply-practice-schema.mjs --target=local --check
node scripts/apply-practice-schema.mjs --target=local --apply
node scripts/init-local-db.mjs --check
```

`--check` 缺少 0019 時回非零是正常的；套用會先備份本地 D1，跳過已完整安裝的增量，定義不一致則停止。基礎結構未齊者先依[完整本地流程](./PERSONAL_PRACTICE_LOCAL_RUN_2026-11-01.md)初始化。正式環境需另對正確 D1 執行 `--target=remote --check`／`--apply`，並循既有 CI 發布；本次沒有套用本地使用中／正式資料庫，亦未推送或部署。

每科至多 2,000 題；最新統計只讀所選區間，至多 10,000 筆有效作答。階段至多 10,000 筆有效新作答、20,000 筆接收依據，超限明示協助處理，不截斷後宣稱完整。生成資格的接收資料也有限額，不無限掃描。仍最多深讀 30 題，沿用文字／儲存大小限制，不重讀全部圖片。只有報告標籤讀生成條件與歷史，首頁／最新統計不呼叫 AI。
