## 1. 定義

- 一個組件包含多個使用者自行建立的計畫，例如「數學講義／12 回」「英文複習／50 頁」「物理練習／20 題」。
- 每個計畫只有名稱、計量單位、目標、已完成數與進度條。第一版不與錯題訂正、AI、待辦勾選自動連動。
- 使用既有各科訂正率的灰白圓角卡片、淡桃色至鼠尾草綠漸層進度條、數值文字風格。進度語意為自行登記的完成量。
- 例：`數學講義　3 / 12 回（25%）`，下方進度條；首頁每條列左側減一、右側加一，中間不反應。

## 2. 操作規則

已確認：寬版共 2 頁，學習計畫與待辦、倒數／探索並排在第二頁；手機共 5 頁，學習計畫獨立。新建計畫只在設定頁，首頁空清單提供前往設定入口。一張組件卡包含多條計畫進度，每條列的點擊區域為左 25%／中間 50%／右 25%，無可見按鈕；整張卡外圍不計次。

- 新計畫從 0 開始。已完成數只透過 +1／−1 登記，不提供直接填數值、批次輸入或數值點擊對話框。
- 以章節為主要情境，單位預設「章」，可選「回／頁／題／單元／自訂」。單位是文字標籤，第一版以整數計次；每次 +1 加一個單位。
- 名稱、目標、單位、移除於設定 → 個人檔案 → 首頁小組件 → 學習計畫管理。
- 首頁三點選單沿用「前往設定／重新同步」；顯示開關隱藏組件不刪除計畫。
- 名稱與進度條不沿用科目卡的跳轉刷題行為；讀取進度、登記進度、編輯計畫各有明確區域。
- 已完成數不可小於零；達標後 +1 停用，保留減少／校正進度能力。不得在完成時自動刪除資料或每天歸零。
- 新增、改名、改目標、移除及重新排序不影響其他計畫。改名、單位修改不重置已完成數。
- 移除使用既有內建對話框，明示刪除該計畫與進度；沒有整張卡點擊刪除或瀏覽器 confirm。
- 卡片內容多時內部垂直捲動，切頁、設定返回、重新整理保留範圍與資料；新建不強制整頁捲動。

## 3. 問卷決議與頁面規劃

| # | 項目 | 已確認決議 |
|---|---|---|
| 1 | Dashboard 位置 | 後續修正為寬版第二頁三欄並排，共 2 頁；手機學習計畫獨立，共 5 頁 |
| 2 | 新建入口 | 只在設定新建；首頁空清單連至設定 |
| 3 | 完成登記 | 同一組件卡包含多條進度，每條右側 25% 加一；中間 50% 不計次 |
| 4 | 點錯修正 | 每條左側 25% 減一；零進度時停用，無可見按鈕 |
| 5 | 批次登記 | 不提供；僅逐次加減，以章節為主要使用單位 |
| 6 | 達標呈現 | 保留原位，標示已完成，+1 停用；−1 可減少並恢復進行中 |
| 7 | 截止日期 | 第一版不加入日期 |
| 8 | 降低目標到已完成數以下 | 保留實際數字（如 15／12），顯示達標，條長最多 100% |
| 9 | 計畫排序 | 設定頁把手拖曳，首頁依此顯示 |

- 寬版頁面：複習進度 → 日常工具（待辦、倒數／探索、學習計畫三欄）。手機：複習重點 → 各科進度 → 待辦 → 倒數／探索 → 學習計畫。
- 寬版隱藏待辦／學習計畫時其餘欄位等分，不留空欄。舊寬版 progress 面板網址／記憶映射至 tools；手機仍使用自己的 progress 記憶，不刪資料或重建編輯器。
- 是 Dashboard 內容滑頁，不新增全站導覽 Tab。保留頁名切換、邊緣間距、面板記憶與手勢；不增加 1／5 等數字。
- 一頁一張主組件卡，卡內多條進度。每條沿用科目進度列的名稱、已完成／目標與淡漸層條；兩側點擊區不可搶走滑頁手勢，列表超量時內部捲動。手機頁名簡寫「計畫」以保持切換列不溢出。
- 首頁數值及進度條不開啟編輯、不連去刷題。目標未達顯示如 3／12 章（25%）；達標顯示實際分數與「已完成」，條長上限 100%，不遮掉超出目標的實際數字。
- −1 每次減少一個單位；即使下修目標造成 15／12，仍應依序減為 14／12，不得突然截斷為 12／12。直到低於目標才恢復 +1。
- 設定頁在首頁小組件的顯示開關中增加「顯示學習計畫」，並增加管理卡：新增、點項目編輯名稱／目標／單位、把手排序、移除確認。管理操作不把已完成數歸零。
- 空清單：「尚未建立學習計畫」＋前往設定入口。隱藏組件不刪資料；隱藏當前頁時回到有效面板，不留空白頁。重新顯示恢復資料與順序。
- 設定排序沿用倒數把手方式，不在首頁增加拖曳手勢。待辦拖曳排序仍維持撤回。

## 4. 同步與狀態

- 訪客只保存本機；登入沿用本人資料隔離、40 秒快取、同時請求合併與耐久離線佇列。切帳號不混資料，不自動合併訪客計畫。
- +1／−1 是增減操作，附唯一 operation_id；伺服器對本人計畫原子計次並去重。在目標允許範圍內，兩個裝置加一應累計兩次；同一操作重送只能計一次。已達標後的新 +1 不再增加；過期介面／離線／併發的無效增量需回傳目前進度及未新增原因，不能讓本機一直保留錯誤預覽。−1 僅以零為下限，不按目標截斷現有進度。
- 同步時確認待送操作是否已被接受，再疊加未接受的草稿；不能把已執行的 +1 又加在新雲端快照上。
- 計次即時顯示，不等待網路才動進度條；失敗保留草稿，失敗時才顯示灰字底線重試。保留既有同步狀態顯示風格。
- 名稱、目標、單位按欄位比較基準；不同欄位可合併，同欄變動才需版本選擇。
- 排序沿用已實作的拖曳 hook 與排序衝突規則，放開才儲存；未來不得重引入已撤回的待辦排序。
- 移除留最小墓碑，舊離線重送不能復活計畫；若已移除，明示並停止套用該計畫待送操作。

## 5. 資料與程式分層（已實作）

```ts
type ProgressPlan = {
  id: string;
  name: string;
  unit: string;
  target_count: number;
  completed_count: number;
  row_version: number;
  created_at: number;
  updated_at: number;
};
```

- D1 使用獨立 `study_progress_plans` 表，另含 user_id、deleted_at 與本人有效項目索引。既有 home_widget_items 的 kind CHECK 只有待辦／倒數，不為新計畫重建舊表。
- `study_progress_operations` 使用 operation_id 主鍵、本人／計畫、delta、effect、applied 與時間，只保留去重收據；不建立完整閱讀歷史、每日圖表或打卡系統。
- 獨立 `study_progress_preferences` 保存顯示開關、plan_order JSON ID 陣列、版本與時間；一次排序只更新一列，不修改所有計畫。原有小組件 preferences 不變。
- TypeScript 普通型別＋資料物件；`progressPlanService` 集中 list/create/updateMetadata/increment/decrement/remove/reorder，hook 訂閱資料，UI 不自行拼 API 或持有 fetch/save class。
- 列表與設定共用相同資料服務；計次直接套用回應，不重查錯題 Dashboard、科目統計或課綱。
- 常態列表只查本人有效計畫與偏好；有效計畫使用 `(user_id,created_at,id) WHERE deleted_at IS NULL` 索引，去重以 operation_id 主鍵查詢，不掃全部帳號或操作，不增加輪詢。測試已核對查詢計畫；正式 rows_read 成效於發布後觀察。
- API 集中於 `/api/progress-plans`：GET 列表、POST `/sync` 同時核對快照與待送操作、POST `/plans` 新建、PATCH／DELETE `/plans/:id` 修改／刪除、POST `/plans/:id/step` 計次、PATCH `/preferences` 偏好。全部驗證本人登入與 account_id，沿用 origin 防護及 no-store。
- 目標 1–1,000,000；名稱最多 100 字，單位最多 12 字；最多 100 個有效計畫、2,000 筆待送修改，超過明示，不截斷。
- 新 migration 為 `0012_study_progress.sql`，只新增三表兩索引；本地已備份後套用。0011_todo_order 已撤回，正式未執行、本地已恢復，禁止套用或復用。
- 新模組缺表時回 503 `PROGRESS_SCHEMA_PENDING` 並保留草稿；不阻擋既有題庫、待辦與倒數。沒有新增 secret、binding 或 AI／分享資料流。
