> 後續已改採「最新／分析報告」獨立標籤、首次基準與階段總結，取消報告的天數篩選與頁尾目前統計。生成須距上次成功至少 72 小時且有實質新資料；以[階段分析實作紀錄](./ANALYSIS_CYCLES_2026-11-02.md)為準。下文保留前一階段的版面試作過程；長文折疊、引用與四區閱讀仍沿用。

日期：2026-11-02。狀態：使用者同意依建議方案試作，已完成介面調整。

## 試作結果

- 報告總覽保留三項數字與三行整科解讀預覽；分析重點預設兩行，超出時可個別展開完整原文，不限制觀察項目數。
- 原題依據採灰色底線文字，點開題目快照彈窗；引用與練習本組在同一列，窄螢幕自然換行。
- 合併報告內重複的完整統計入口；單一數據詳情包含作答變化、各單元、資料組成、每日紀錄。
- 追問輸入框在對話前方；既有對話預設收合，新追問會自動展開。引用沿用相同彈窗。
- 目前統計保留在頁尾收合，明確標示「非本報告」。報告切換會重設閱讀展開狀態，保留各份報告的固定數字與內容。
- 未更改模型提示詞、資料庫、統計計算與引用驗證；沒有為展開操作新增 API 或 AI 呼叫。

驗證：以模擬資料檢查長文展開／收起、五項分析、原題彈窗及焦點還原、追問、最新／歷史報告、390px 無整頁橫向溢出，以及零作答／到期／等待／失敗狀態。展開與看引用的模擬 AI 呼叫數維持零；追問由模擬回覆驗證，未呼叫真實模型。

TypeScript、正式前端建置與四項 PWA 發布檢查均通過。

前一項練習體驗已先完成並提交 `a3c50c0`：隱藏無法使用的重新辨識按鈕、保留手動修改、原圖控制懸浮於圖片上、操作顏色區分。

## 已明確提出的需求

- 原題依據改為緊湊的灰色底線文字連結，不使用大型框狀按鈕。

## 目前問題與可沿用資料

`PersonalAnalysisReport` 目前同時提供「查看兩期變化與資料組成」與「報告當時的完整統計」，兩者都渲染同一份 `AnalysisStatsContent`。科目頁下方另有目前統計，容易混淆目前狀況與歷史報告當時的狀況。

分析段落只有標題與一段完整說明，引用另佔一排大型按鈕，練習再佔一排。內容即使不多，仍有大量垂直空間與相同層級的文字。

現有資料已包含 `overview`、各重點的 `title`／`explanation`／`evidenceIds`、統計與題目快照，足以先改善呈現。第一步不需修改資料庫或重新產生舊報告。

## 建議畫面，由上到下

| 分區 | 預設可見 | 展開後 | 視覺層級 |
| --- | --- | --- | --- |
| 頁面操作 | 科目、觀察期間、產生報告 | 無 | 頁面標題與唯一主要按鈕 |
| 歷次報告 | 選取時間、前後切換 | 更早報告 | 緊湊導覽；與下方報告分開 |
| 1. 報告總覽 | 報告時間與期間、個人題目／期間作答／重作答對三項數字、整科解讀預覽 | 完整整科解讀、資料範圍說明 | 主標題、明顯數字、短段落 |
| 2. 分析重點 | 所有重點標題、各自的短預覽、引用與練習入口 | 該重點的完整分析 | 小標題明顯；段落間用細線與留白區分 |
| 3. 數據詳情 | 一個「查看數據詳情」入口 | 期間變化、單元表、資料組成、每日紀錄 | 預設收合，內容使用明確小標，不重複總覽數字 |
| 4. 報告追問 | 發問輸入框、送出 | 歷次問答及其引用 | 獨立區塊，不與報告分析混排 |

總覽、分析重點、數據詳情、追問各有明確標題。使用既有柔和背景、品牌紫與細分隔線，避免每一段再套一個大灰框。

## 長度：先改善閱讀，再另議模型輸出

建議整科解讀先顯示約三行，每一項分析先顯示約兩至三行；長文有明確的「展開完整分析／收起」。所有重點的標題皆保留，不限制最多三項，也不隱藏後面的重點。

這是完整原文的折疊預覽，不另用 AI 生成一份摘要，也不將截出的文字當成新的分析結論。引用與練習入口放在折疊文字之外，隨時可用。

目前 `explanation` 未區分「發現／錯因／建議」，前端不靠字詞猜測拆段。若後續希望模型直接輸出較短、分層的結論，再於操作流程定案後另行調整提示詞與資料契約。

## 原題依據：一列完成

建議呈現：

```text
原題依據：題 1、題 2                         練習本組 →
```

- 題號以低對比灰色底線文字呈現，取消外框、大面積背景與獨立卡片感。
- 與「練習本組」放在同一列；空間不足允許自然換行，避免長題號造成整頁橫向溢出。
- 引用仍使用後端已驗證的題目 ID，保留報告當時版本；不是把題號當作即時題庫序號。
- 題目快照的點開方式列在最後的批閱項目；若採彈窗，關閉後回到原分析位置。
- 題號可視文字緊湊，但鍵盤焦點與觸控點擊範圍仍須可用，不以極小文字取代可操作按鈕。
- 沒有題目引用的純統計分析，不製造「題 0」或空白引用列。
- 追問回答中的引用沿用相同樣式。

## 數據只整理一次，分清兩種時間

報告內只呈現該份報告的固定統計。保留一個數據詳情入口，移除兩個重複渲染整份統計的入口。

詳情內分為四組，避免把不同性質的資訊塞進同一張清單：

| 小組 | 內容 |
| --- | --- |
| 作答變化 | 前期／本期、兩期皆作答同題、同題首次與末次結果 |
| 各單元 | 單元、題數、答對／作答；單純供分析閱讀，不恢復子分類報告範圍 |
| 資料組成 | 已確認／AI／未整理、可用題文、正解與原作答缺漏、上傳／存入、自動／自評、原圖使用 |
| 每日紀錄 | 日期、答對／作答、自動／自評；附分日時區 |

比較條件與限制跟著相關數據，以較低層級說明一次；仍保留「不是整科能力分數」與資料不足限制。

目前題庫統計若保留，必須在報告外清楚標示「目前統計，非本報告當時數據」。歷史報告切換不改用最新數據，也不自動產生新解讀。

## 實作與驗收方向

本次調整 `PersonalAnalysisReport`、`AnalysisCitations`、`AnalysisConversation` 及科目頁的區塊組合，新增共用 `ExpandableAnalysisText`；資料計算、引用驗證與保存政策沿用。

驗收應涵蓋：不同報告切換、純統計重點、零重作紀錄、很多引用、長題文、手機換行、鍵盤展開與關閉、過期報告，以及等待／失敗狀態。點展開、看引用與切換版面本身不呼叫 AI、不重讀圖片，不為版面重複查詢統計。
