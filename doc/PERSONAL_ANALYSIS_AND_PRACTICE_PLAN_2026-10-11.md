# Redolve 個人錯題分析、抽題與 Pro 出題規劃

- 日期：2026-10-11
- 狀態：產品規劃，尚未實作本文功能。
- 範圍：整理本次討論共識，作為後續資料庫、API 與介面實作的依據。

## 1. 產品目的與流程

以科目作為分析入口，向下查看單元、考點、錯誤原因與具體題目。上傳時由 AI 一併辨識題目及作答資訊，減少使用者逐題填寫；再透過抽題重作，累積真正的作答結果，協助安排下一次複習。

流程：上傳原圖 → AI 辨識 → 使用者可確認或修改 → 抽題重作 → 保存每次結果 → 科目分析 → 推薦練習；Pro 再加入弱點變式出題。

本文的「上傳 AI 辨識」處理單張原題；「個人 AI 分析」解讀多道題目與歷次重作紀錄，兩者用途不同。

## 2. 已確定的設計

1. 上傳時的同一次背景 AI 分析，擷取科目、單元、關鍵字、原題逐字稿、題型、選項、原本作答及正確答案。
2. 題目資料只有「AI 辨識」與「使用者已確認」兩種確認狀態，以整題為單位。
3. 無法辨識的欄位留空；不新增待確認、有衝突、缺少資料等狀態。
4. 上傳資料不另存「作答結果」；這個詞只表示某次抽題重作的答對／答錯。
5. 每次重作新增一筆 `practice_attempts`，不覆蓋上傳時的原本作答。
6. 抽題主要顯示逐字稿整理出的題目文字與選項，提供「檢視原圖」按鈕。
7. 原圖預設放大並置中，減少左側批改答案出現在初始視野；使用者可以自由拖曳、縮放。原圖可能露出答案，無須遮蔽或裁切。
8. 正解缺漏時提供「補齊正確答案」入口；使用者也可只記錄本次答對／答錯。
9. 已訂正／未訂正表示整理進度，與每次重作答對／答錯分開。
10. 個人分析的數字由程式計算，AI 負責解讀考點、可能的錯誤模式與練習建議。

## 3. 上傳 AI 辨識與題目資料

以下為邏輯欄位，實體資料表放置方式在實作前決定。個人作答資料需同時支援本人上傳題與存入的個人題目，不能寫回他人的共享題目。

| 欄位 | 內容 | 缺漏處理 |
| --- | --- | --- |
| `topic_id` | 沿用現有科目／單元分類樹 | 留空，允許使用者指定 |
| `keywords` | 題目具體考點與搜尋關鍵字 | 可為空陣列 |
| `ocr_text` | 原題逐字稿，保留文字與公式，不混入作答及批改註記 | 可留空或不完整；原圖仍可查看 |
| `question_type` | 單選、複選、填充、計算、申論、其他或未知 | 使用未知，不強制使用者補填 |
| `options` | 選項編號與文字，供選擇題呈現及選項分析 | 非選擇題或辨識不到時留空 |
| `original_answer` | 上傳圖片中，使用者訂正前的原本作答 | 無法區分原作答與批改時留空 |
| `correct_answer` | AI 從圖上辨識或解題得到的正解 | 無法判定時留空 |
| `error_reasons` | AI 建議或使用者填寫的錯因，可複選 | 可留空；AI 建議以可能原因表達 |
| `confirmation_status` | `ai` 或 `confirmed` | 上傳後預設 `ai` |

答案格式需支援單選選項、複選選項集合與文字答案；不將所有答案限制為 A／B／C／D。第一版只對有正解的選擇題自動判分，其他題型採使用者自評。

### 3.1 確認狀態

| 值 | 介面名稱 | 定義 |
| --- | --- | --- |
| `ai` | AI 辨識 | 題目資料由 AI 填入，使用者尚未整題確認；辨識結果可能有誤 |
| `confirmed` | 使用者已確認 | 使用者按「確認正確」，或修改後儲存，表示已確認目前這份題目資料 |

整題確認不會補齊空白欄位，也不代表每個欄位都有值。使用者不必逐題確認才能使用基本複習功能；分析頁須說明是否包含未確認的 AI 資料。

介面提供「確認正確」與「修改」。已確認內容不得被背景 AI 自動覆蓋；重新分析的覆蓋方式在實作前明訂。

缺少原本作答不代表未作答；它只表示目前沒有該資訊。錯誤原因若僅由選項推斷，AI 分析需使用「可能」等表達，不把推測當成使用者親述。

## 4. 抽題與原圖檢視

### 4.1 抽題範圍與呈現

第一版從使用者的個人題庫抽取原題，包含本人上傳題與已存入的個人題目。科目是主要範圍，可進一步指定單元。

測驗頁顯示題目文字與選項，隱藏先前保存的 App 筆跡、訂正筆記、原本作答及正解。題目文字不足，或題目需依賴圖表時，使用者透過「檢視原圖」補充閱讀；不要求圖表裁切才能納入抽題。

原圖查看規格：

- 開啟時預設放大並置中，盡量減少左側答案出現在初始畫面。
- 允許使用者拖曳、縮放及檢視完整原圖。
- 不偵測、遮蔽或移除原圖上的答案。
- 查看原圖不阻擋作答、不改變題目確認狀態，也不自動新增一次作答。
- 初始放大倍率與不同螢幕的適配方式，實作時依閱讀體驗決定；無法保證所有圖片都避開答案。

### 4.2 抽題方式

以隨機抽題為基礎，優先提高近期重作仍錯、距離上次重作較久的題目出現機會，同時保留其他題目，避免持續抽到同一題。尚無作答紀錄的題目也可被抽到。

第一版不需要固定的複雜權重公式。優先順序與隨機比例應可調整，實作時再決定具體參數。同一輪測驗應避免重複抽取同一題。

### 4.3 判分與補齊正解

| 情境 | 操作與紀錄 |
| --- | --- |
| 選擇題有正解 | 提交答案後比對，保存本次答案及答對／答錯 |
| 手寫、計算、申論等題型 | 使用者自行按「這次答對／這次答錯」；本次答案文字可留空 |
| 正解缺漏 | 提供「補齊正確答案」；補齊後存回個人題目資料並標記 `confirmed`，支援這次及後續判分 |
| 暫時不補正解 | 可直接自評本次答對／答錯，原題正解仍留空 |
| 略過或未提交 | 不新增 `practice_attempts`，不計入作答分母 |

複選題第一版採完整選項集合一致才算答對，不做部分給分。AI 辨識正解可供比對，但分析與介面仍需顯示它尚未經使用者確認。

## 5. 重作紀錄：`practice_attempts`

每次完成重作，新增一筆個人紀錄。作答結果屬於本次紀錄，題目資料不再新增同名欄位。

| 邏輯欄位 | 用途 |
| --- | --- |
| `id` | 每筆作答的唯一 ID，可用於避免同步重試造成重複寫入 |
| `user_id` | 紀錄擁有者 |
| 題目參照 | 對應本人上傳題或存入題；實作需分清 `item_id` 與 `saved_ref_id`，不能混用 ID |
| `answered_at` | 作答時間 |
| `answer` | 本次選項或文字答案；自評題可留空 |
| `result` | `correct`／`incorrect`，顯示為答對／答錯 |

題目資料保存原本作答與正解；作答表保存每次重作答案與結果。最近一次結果、重作次數、最近作答時間從作答紀錄取得，不另在題目表維護一份。

現有 `review_count` 表示既有訂正流程的計數，不能當成新的重作次數或答對次數，也不能轉換成不存在的歷史作答事件。

紀錄顯示位置：

- 題目詳情的「重作紀錄」，依時間呈現每次結果。
- 科目分析頁，彙整各單元表現與近期再錯。
- 抽題服務，利用最近結果及時間調整抽題機會。

離線時每次作答須獨立保存，連線後逐筆同步；不能沿用僅保存某題最後一個值的方式，否則會遺失中間的作答。

## 6. 個人 AI 分析

### 6.1 讀取資料

以當前使用者選定的科目為範圍，讀取本人題目資料及作答紀錄。可再限制單元與時間；第一版的預設時間範圍在實作時決定。

| 輸入 | 分析用途 |
| --- | --- |
| 科目、單元 | 分組統計及找出集中出錯的單元 |
| 題目逐字稿、選項、關鍵字 | 理解具體考點與選項差異 |
| 原本作答、正解 | 尋找可能混淆的觀念；缺漏時不執行這部分推斷 |
| 題目確認狀態 | 說明分析是否依賴未經確認的 AI 資料 |
| 歷次重作答案、結果、時間 | 查看反覆出錯、進步及久未複習的情況 |
| 錯因與本人訂正筆記 | 補充使用者已說明的原因與解題理解 |

預設使用文字與作答紀錄，不每次重新讀取全部原圖，也不假設 AI 已經理解手寫筆跡。共享題目的他人筆記不當成本人錯因；個人分析不公開到題目集或分享頁。

### 6.2 分析方式

先由程式查詢並統計，再將統計及相關題目交給 AI 解讀。

| 程式計算的事實 | 定義 |
| --- | --- |
| 單元收錄題數 | 該單元不同個人題目的數量，不等於考試答錯率 |
| 重作次數 | 已提交的作答紀錄數量 |
| 重作答對比例 | 答對次數／已提交次數；自評也包含在內 |
| 反覆答錯題目 | 同一題存在多次答錯紀錄，可列出最近結果 |
| 近期表現 | 指定期間的已提交結果，報告附上期間與樣本數 |
| 久未複習 | 距離最近一次已提交作答的時間；無紀錄題目另行呈現 |

AI 負責：

1. 從題目與選項找出單元內更具體的考點。
2. 比較重複出錯的題目，提出可能的概念混淆或方法問題。
3. 引用對應題目與紀錄，說明判斷依據。
4. 依近期仍錯與久未複習等資訊，推薦原題及下一步練習。

例如，程式顯示某單元最近重作仍有數題答錯，AI 可比對這些題的內容，提出「可能混淆條件機率的條件方向」，並連結相關題目。單純收錄很多機率題，不能直接推定使用者不會條件機率。

### 6.3 分析頁輸出

- 優先補強單元與具體考點，附上原題依據。
- 重作表現及變化，清楚標示期間、題數、作答次數。
- 可能的錯誤原因，允許使用者修正。
- 下一組建議練習，說明推薦原因。
- 使用資料摘要：已確認題數、AI 辨識題數及缺漏正解題數。

分析可使用未確認的 AI 資料，但須說明資料組成，不能把它們描述為使用者已確認的事實。只有上傳紀錄時，只能分析錯題內容與分布；尚不能判斷重作後是否改善。

沒有全科或單元的總作答量時，不輸出真正的考試錯誤率；重作比例也不能當成整科能力分數或預測成績。查看原圖及自評是允許的，因此報告描述的是本產品中的複習表現。

## 7. Pro 弱點出題

Pro 依個人分析結果生成新題，與抽取既有原題分開。

流程：選定弱點考點 → 取相關原題與已知正解 → 生成題目、答案、解析 → 驗題 → 使用者作答 → 保存重作結果並更新分析。

可生成概念辨識、基本應用、情境遷移等題組，針對具體錯誤模式，而非只換數字。原題或正解不足時，先推薦原題複習或補齊資料。

較強模型主要負責出題、推理與解析，也可支援原題重新辨識。模型選擇需用已確認題目評測，不能只依模型名稱判定品質。

生成題須保存來源題、目標考點、題目內容、答案、解析及模型版本。正式出題前檢查條件完整性、答案與解析一致性，以及選擇題答案是否符合題型要求；檢查未通過不交給使用者作答。

生成題的作答仍記錄在作答事件中，但需可辨識它是生成題，以便分開查看原題與變式表現。具體參照欄位在 Pro 階段擴充。

| 一般功能的規劃 | Pro 功能的規劃 |
| --- | --- |
| 上傳 AI 辨識、確認與修改 | 經評測的較強模型及進階重新辨識 |
| 原題隨機複習、重作歷史 | 弱點變式題組 |
| 科目基本分析與原題推薦 | 個別解析與依結果調整後續題目 |

模型、收費、額度及基本／進階分析的最終界線尚待決定。既有題目集訂閱不等於 Pro 付費權限；Pro 需獨立的權限與用量設計。

## 8. 實作順序與驗收重點

| 階段 | 交付內容 | 驗收重點 |
| --- | --- | --- |
| 1. 上傳辨識 | 擴充 AI 輸出、保存題目資料、確認／修改、補齊正解 | 批次上傳可繼續；缺漏留空；只有兩種確認狀態；已確認內容不被背景覆蓋 |
| 2. 原題抽題 | 題目文字、可移動縮放的置中原圖、判分／自評、作答表及歷史 | 正解可補齊；每次作答獨立保存；重試不重複計數；略過不計次；原作答不被覆蓋 |
| 3. 個人分析 | 程式統計、AI 解讀、科目報告、推薦抽題 | 數字可追溯；有題目依據；缺少紀錄不宣稱進步；不混入他人的個人資料 |
| 4. Pro 出題 | 模型評測、生成與驗題、進階分析、付費權限及額度 | 生成品質有評測；答案與解析可驗證；作答回流；成本與重試有上限 |

本文不新增資料庫 migration，也不變更現有 API。實作前需定案個人題目資料的實體表位置、原題／存入題的參照方式、時間範圍、抽題參數及正解修正後的歷史結果處理方式。既有紀錄不因修改正解而默默改寫。

## 9. 現有程式對照

- `worker/services/ai/AIService.ts`：目前 `TagResult` 只有分類、關鍵字、搜尋 tokens 與 OCR 文字，需擴充作答資訊。
- `worker/services/ai/prompts.ts`：擴充上傳辨識提示與輸出結構。
- `worker/routes/problems.ts`：接入上傳資料保存與題目修改。
- `worker/schema.sql`：目前沒有本文規劃的 `practice_attempts` 或答案欄位。
- `worker/routes/dashboard.ts`：目前以收錄與訂正狀態統計，不能替代重作表現分析。
- `src/types/question.ts`：已有上傳題、存入題及共用題參照，新增個人作答資料須與既有參照相容。
- `src/services/offlineStorage.ts`：新增作答事件的離線保存方式，避免多次作答被合併成最後一次。
