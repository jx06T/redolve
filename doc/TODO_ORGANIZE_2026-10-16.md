## 操作規格

目的：依序選出現在或稍後想做的事項，整組移到指定位置；不要求選完整張清單。

1. 首頁／設定待辦卡片右上角「整理」進入淡綠整理模式；先將今日已完成事項預覽移至前方，再開始選取編號。此時尚不寫入；取消還原進入前順序。首頁入口位於三點選單左側。
2. 點未完成事項左框，依點選順序編號；重點已選事項取消，後續編號遞補。選取不移動清單、不改完成時間、不發請求。
3. 按「Sort to…」進入目的地步驟。原有事項仍在原位、編號保留、已選文字淡化；主動顯示可點的線與左下箭頭（↙），不加「插入 X 上方」等位置文字。插入線使用零高度容器與 32px 覆蓋式點擊區，不增加題項間距；清單上下固定 10px 留白保留邊界標記，所有模式一致。
4. 插入位置以邏輯取出已選事項後的未完成清單計算；每個不同目的地只顯示一次。最前與最末皆可選，全部選取時只剩一個目的地。
5. 點位置即依編號插入並退出整理。未選事項保留相對順序；今日已完成事項統一置於今日清單上方且保留順序，歷史事項不參與。

- 例：A B C D E，選 C B E；選最前 → C B E A D；選 D 前 → A C B E D；選最後 → A D C B E。單一移動、相鄰交換沿用相同流程。
- 「返回選取」保留編號；Escape 在目的地步驟返回選取、在選取步驟取消整理。取消不寫入。未選事項時停用 Sort to。
- 整理期間暫停新增、文字編輯、完成、刪除、歷史拉開與設定／重新同步操作；保留新增草稿。目的地步驟也暫停變更編號。
- 保留原生縱向清單捲動、Dashboard 橫向滑頁；從插入位置滑動、拖離／取消不應誤套用。標記可用 Tab／Enter／空白操作，提供無障礙名稱但不顯示位置文字。
- 移除選取／目的地步驟的常駐說明文字；整理操作移至既有卡片標題列，狀態位置顯示已選數量，首頁／設定均不額外新增操作列高度。三點選單可「查看整理說明」，整理中僅保留此選單項；關閉說明不改編號與步驟。
- 選取／目的地切換時，以可見事項位置保持捲動；套用不強制回頂端，退出焦點回整理按鈕。
- 整理時固定原有項目的順序；同步導致事項刪除、完成或移入歷史，該事項退出選取並重新編號。新同步項目附加於後方。選取全失效時返回選取步驟；失效目的地不改成其他位置。
- 當日勾選／取消勾選保持當前位置，即使已經設定 todo_order 也不自動分組。按「整理」先預覽今日完成事項置前，在選取編號前呈現；取消還原原順序，選定插入位置才儲存分組與排序。跨日仍按原規則移到歷史區。

## 待辦新增方向（2026-10-16）

- 首頁／設定共用一個 TodoComposer，只有一個真正的 textarea。
- 空白未聚焦：左半「↓ 新增至下」、右半「↑ 新增至上」；提示 pointer-events:none，手指實際點到 textarea。pointerdown 只記錄方向；原生 focus 才確認選擇，無 preventDefault／非同步 focus／更換節點。
- 聚焦後提示消失，單一送出按鈕改用對應方向箭頭；按鈕與輸入框等高，箭頭不另提供切換操作。
- Enter 送出保留焦點、清空文字且維持方向；Shift+Enter 換行，多行由上至下新增。中文組字期間含 keyCode229 不送出。
- 既有草稿內的點擊只調整游標，失焦也保留方向與文字；空白失焦恢復左右提示。新增失敗保留文字，再次編輯即清除舊錯誤。無常駐數量紅字；實際失敗才顯示簡短灰字，數量／字數檢查仍保留。
- 本裝置、各帳號分別記住最後方向（rdv:todo-insert:v1:<account>），不寫入 D1。首次 bottom；鍵盤直接聚焦沿用記憶，Alt+上下鍵可在輸入時切換，提供螢幕閱讀器說明。
- 新增至上插在第一個未完成事項前，若全部完成則接在既有清單之後；新增至下接在目前清單末尾。不將散落在清單中的當日完成事項集中到上方，所有既有項目保留相對順序；歷史區不參與，不強制捲動。
- homeWidgetService.addTodos 先驗證整批，再沿用建立佇列新增。top 或已有自訂順序時，在建立操作之後排入一次 todo_order 寫入；bottom 且無自訂順序維持原建立時間排序，不額外寫偏好。建立時間取本機時鐘與已載入同類項目最大值，避免重載後時間相同／倒退插錯位置。
- 方向選擇零 API，整批排序一次、依舊使用 0013；離線／缺欄位／排序衝突維持原有持久佇列與版本選擇。無新增 migration。
- 先前雙按鈕／Enter 設定實驗只保留在忽略的本地 .wrangler/qa/todo-input-design-draft/，已由上述設計取代；不可整檔還原。

## 排序動畫（2026-10-16）

- 進入整理的完成分組、套用選取排序、取消還原皆使用 300ms transform 位移；DOM／本地順序立即更新，不等待雲端。選取編號、切換目的地、普通勾選、背景重新同步不播放動畫。
- useTodoReorderAnimation 以穩定 ID 量測移動前後的位置，沿用 React 18 與瀏覽器 Web Animations API，不新增套件。只動畫化畫面附近且移動距離未超過一個清單視窗的列，避免跨長清單飛行；每次操作集中讀取位置，不逐幀量測。
- 捲動清單／Dashboard 滑頁、改變視窗大小或減少動態效果設定會取消動畫；不支援 animate 時直接完成排序。元件卸載會清理動畫與事件，舊動畫被新操作取代時從目前畫面位置接續。
- 390／1280px、訪客／登入測試檢查實際 Animation／transform 中間位置、300ms、進入／套用／取消動畫、減少動態效果，以及分組先於第一個編號。另檢查同一動畫中選取項目淺綠、被推移項目不變色，兩者都有中途位移，完成與中止還原背景。保留原有同步衝突、零寫入取消、原生手勢與等高回歸。無新 API 或 migration；實體 iPhone 手感仍待驗收。

- 動畫調整：300ms；只有使用者編號選取且實際位移的事項保留淺綠背景 rgba(168,197,189,0.22)，末段淡回原背景；被推移的未選事項只播放 transform，進入整理的完成分組與取消還原也只位移、不變色。位移與背景共用同一個 Animation，完成、捲動中止或新操作取代都自動清除，不留下永久標記；減少動態效果同時停用兩者。

## 手機插入點擊修正（2026-10-17）

- 原生觸控實際事件為 pointerdown → pointerup → pointerleave → click；原程式於任何 pointerleave 標記拖離，導致正常手機輕點被拒絕。修正為只在仍按下期間的 pointerleave 判定拖離，pointerup 記錄放開並補查位移，pointercancel 仍拒絕。
- 不改 32px 點擊區與零高度排版；不 preventDefault、不關閉原生捲動與橫向滑頁，沿用移動 8px 與捲動位移防誤套用。
- 既有手機測試只用滑鼠 click 套用、真實 touch 測滑動；現改用瀏覽器原生 tap 驗證手機最前／中間／最後插入、相鄰交換、首頁與設定，桌面維持 click／鍵盤及滑鼠拖離返回驗證。修正前原生 tap 測試可重現失敗。無新增 migration。
