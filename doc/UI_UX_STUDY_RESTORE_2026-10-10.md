## 2. 刷題：題圖與書寫優先

### 2.1 畫面結構

```text
側欄收起：
  〔側欄開關〕      〔我上傳｜我存入｜我共用中｜返回〕
                    完整題卡連續滾動              〔原懸浮筆刷工具〕

側欄展開：
  原版側欄                 原版題卡連續列表
  ├─ 共用中才出現選集      ├─ 題目資訊與既有操作列
  ├─ 科目／狀態            ├─ 原題圖片＋筆跡
  ├─ 可展開搜尋與標籤      ├─ 原推導區／筆記區
  ├─ 原課綱樹              └─ 既有底部操作列＋加入共用集
  └─ 原文字題目大綱
```

- 恢復原有側欄開關位置、可收起狀態與手機抽屜；刷題主區不增加標題卡、來源介紹段或搜尋表單。
- 來源／返回懸浮列位於主閱讀區上緣、沿用既有小型圓角控制，不佔一整排固定頁首；預留不遮住首題操作的距離。手機維持一排精簡控制，不與側欄開關／筆刷工具／底部導覽互相遮擋。
- 側欄增加的搜尋／標籤用一個可收合「搜尋與篩選」區；科目、狀態與樹保持主要位置。集合選擇只出現於我共用中。
- 移除側欄「所屬共用集（只篩選我的原題）」；若要依集合刷題，切換我共用中並在側欄選集。不並列兩套集合篩選。
- 側欄搜尋限制在當前來源、集合、科目／單元；不混入公開探索或訂閱內容。Enter／提交才查詢，清空回到原刷題範圍。
- 側欄條件均原地更新題流，不導航至搜尋／集合管理等功能。
- 三來源保留原「待訂正／已訂正／全部／封存」狀態選項。初次待刷狀態與原版一致；記住使用者後續選擇。共用來源依本人集合進度篩選，不依作者原題狀態。
- 主區只有一個題目主滾動容器，使用可用視窗高度；不再以額外頁首造成狹小的內嵌捲動盒。側欄抽屜的捲動與主區分開。
- 原桌面／手機筆刷工具、手指與筆分離、推導區原座標、橡皮擦、觸控行為維持。

### 2.2 樹與題目大綱

- 恢復原樹形、展開收合、父節點包含子節點、當前單元標示及題數。
- 我上傳／我存入用本人可用分類；我共用中用目前集合題目可見的來源分類。來源自建分類不得誤當本人分類或讓其題目消失。
- 計數必須對應目前來源、集合與狀態，不能拿個人原題總數套到存入或共用樹。必要的 facets／計數接口列實作待辦。
- 大綱恢復文字題碼、分類、狀態與目前題目標示，不新增圖片縮圖。
- 大綱與主區同一篩選範圍；不能把「已載入 15 題」標成「全部 150 題」。取得全範圍的大綱時只分頁讀必要 metadata，不下載全部題圖或筆跡。
- 點大綱定位同一題卡；未載入目標需取得目標及定位所需資料，載入中／失敗明示，不按了沒反應。
- 全部題目可連續刷到；保留虛擬渲染，只掛載可見題卡的書寫資源，不因要求全部題目而一次掛載所有 canvas。

### 2.3 續載、切換與返回

- 本輪先採手動「載入更多題目」；載入中停用，失敗轉為「重試載入更多」，不依賴捲動事件。大綱定位／返回指定尚未載入題目時仍按需取得前置頁面。
- 每個來源使用正確 next cursor／offset，去重以完整來源識別為準；失敗原位重試該頁，不清空已載入內容。
- 切換來源、集合或篩選取消舊請求；慢回應不得寫入新範圍。無權或被撤權不可使用舊快取作授權。
- 各來源／集合保存自己的科目、狀態、搜尋、大綱展開及題目 anchor；不把另一集合的 topic／cursor 帶過來。
- 返回上一步恢復來源、集合、題目與篩選、捲動位置。無上一筆應用內紀錄時，不用一個不明的 window.history.back 離開網站。
- 作業草稿及同步狀態由既有 workService 保留；恢復舊外觀不換回舊資料儲存路徑。
- 封存／完成訂正後保留當前卡直到明確換範圍或刷新，避免書寫中卡片突然消失。

## 3. 統一題卡；依權限決定操作

- 以原 ProblemCard 的尺寸、題目資訊、上方操作列、推導區、筆記收合與底部操作列作唯一視覺基準。
- 三來源使用共用的題卡殼與同一組控制元件；不再維護兩份相似但操作不同的題卡。
- 我上傳：本人原題及本人私人訂正；我存入：保留版題圖及本人私人訂正；我共用中：來源原題＋本人該集合共用層＋有權看到的他人參考層。
- 共用卡將「正在寫我的共用筆記」等必要識別縮至既有資訊列；本人可寫、他人只讀。參考筆跡／作者筆記放既有筆跡顯示／筆記區附近，不另設一套主工具列。
- 標籤、題圖資訊、複製、重整、顯示／隱藏、下載等逐一對照原操作語義與來源能力；UI 統一不等於讓貢獻者刪別人的原題或改作者私人分類。
- 加入指定共用集：原題擁有者才有此操作；放底部封存／完成訂正旁。已存題／他人的共用原題不因此獲得再發布權。
- 已加入集合標示縮至資訊列，加入後原位更新標示；不跳頁、不另外放巨大按鈕或重複入口。
- 存入版特有的來源更新、分類辨識與移除我的版本收進既有更多操作／資訊區；私人筆記維持，更新確認沿用既有流程。
- 共用私人進度已核准：狀態鍵為 user＋collection entry，封存只隱藏自己的待刷視圖；新增資料／同步／篩選支援另列 migration，不借用作者原題 status。詳見 §7.1。

## 4. 搜尋：查找與查閱

```text
一般全站導覽
搜尋輸入框＋提交
我上傳／我存入／我共用中｜簡單篩選｜簡單檢視／完整檢視
結果列表：〔前往刷題〕
```

- 與刷題分開 page layout；共用範圍型別、查詢服務與必要的視覺元件，不共用整頁模板或藏入 search boolean 分支。
- 三來源同範圍規則；共用中可指定有貢獻權的集合。公開探索與純訂閱保持獨立。
- 簡單檢視：題碼／題名、分類、關鍵字／筆記摘要等精簡結果；不是刷題連續書寫畫面。
- 完整檢視：相同題卡的唯讀呈現，含題圖、可見筆跡與筆記；不儲存作業、不增加複習次數。
- 每題一個「前往刷題」：帶入來源／集合／目標 ID；保留搜尋的關鍵字、檢視方式、篩選與結果位置供返回。
- 搜尋到已完成／封存題目也能定位。此次開啟目標必要的篩選調整不得永久覆蓋使用者先前的待刷條件。
- 空搜尋、提交時機與返回記憶沿用已確認規則；簡單／完整切換不丟掉查詢、不另建一份結果或重置分頁。

## 5. 設定：一組分頁，一個職責

```text
筆觸偏好｜科目分類｜個人檔案｜共用集管理｜訂閱中心
```

- 延續原三標籤的同一容器、樣式、選取態；新增兩項同列，不另開第二排捷徑。窄螢幕分頁可橫向捲動，不再多套導覽。
- 個人檔案：公開顯示名稱、預設上傳目的地、API Key；三個區塊有一致標題／儲存狀態，API Key 沿用既有建立、遮罩與撤銷流程。
- 預設上傳目的地只能選當前可貢獻集合；撤權或集合失效時回到個人題庫並明示，不把上傳原題弄丟。
- 共用集管理：只列本人建立／可編輯集合，顯示名稱、角色、題數等簡潔資料；點列表項進入管理。建立集合是一個相近的小型按鈕，表單用既有應用對話框。
- 待接受邀請與待接手管理權保留為必要待辦狀態，與已加入集合區分，不混入無權編輯的集合列表。
- 不放前往刷題、搜尋、我的題庫、存入題庫、訂閱中心等捷徑群；訂閱中心已是相鄰分頁。
- 訂閱中心只管理關係；觀看仍是延伸題目。必要閱讀入口與特定列表項相關，不以通用跳轉卡片佔頁首。
- 站方管理入口保持僅站方管理者可見，置於設定附屬區，不混在共用集主要任務中。
- 設定返回保留分頁與列表位置；舊 #apikeys 等連結映射新個人檔案，不變成 404 或遺失 API 管理入口。

## 6. 集合管理：設定與維護，不做第二個刷題頁

- 頁首只顯示名稱、必要角色／狀態與返回管理列表；移除訂閱中心／共用書寫等重複跳轉群。
- 保留必要名稱／分享範圍／權限／成員／管理權轉移／刪除操作與應用內確認。
- 題目區是「已加入題目管理」，用精簡題碼／分類／提供者列表供移除、調整順序等管理。不提供完整題圖閱讀、筆記編輯或存入／已看篩選。
- 正常看題與書寫使用刷題我共用中；純訂閱觀看使用延伸題目。公開邀請／分享連結的唯讀閱讀能力仍需保留，不因移除管理頁閱讀區而破壞外部連結。
- 加入原題仍沿用批次候選流程：分類／搜尋控制同一排，候選網格與選取狀態一致；跨分類保留 ID、已選數與失敗重試。適量縮圖供「選擇待加入原題」，不與刷題側欄無用縮圖混為一談。
- Switch、表單與按鈕沿用全站既有元件，不增加特製彩色分區、重複大標題、另一套確認流程。
- 成員顯示對方可用公開暱稱＋觀看者／貢獻者／建立者角色；未設定暱稱用「未設定暱稱的成員」與局部可區分標示，不把 UUID／email 當暱稱。顯示姓名不參與授權判斷。

## 7. 介面與資料抽象

- 保留 TypeScript 型別＋普通物件與服務函式；不導入全面 class。
- 分開 StudyPage／SearchPage 的布局及頁面行為，共用 QuestionRef、CollectionEntry、QuestionWork、SourceScope。
- StudySidebar 使用原 Sidebar 樹形與樣式，透過受控 props／hooks 接收來源、分類、計數、大綱及篩選事件，避免直接綁死原題 store。
- QuestionCard 共用殼、操作列、推導區與筆記控制；owned／saved／shared adapter 提供題圖、自己的 work、參考層與 capabilities。
- capabilities 必須來自目前來源與後端授權；不能以相同 UI 推導相同權限，亦不把 shared write fallback 至 owned write。
- 查詢、分頁、焦點定位、分類計數、大綱索引是服務介面；刷題與搜尋的操作意圖分開，不再以共用整頁代替共用 API 介面。
- 本輪以 UI 恢復為主；只有計數／大綱／暱稱缺少必要資料與已核准的新個人進度才補接口。不自行變更分享授權或發布模型。

### 7.1 共用題的個人進度資料契約

- 獨立 ReviewProgress 物件：狀態、封存前狀態、複習次數、版本序號；不塞入共用筆跡、作者原題或公開 metadata。
- 建議獨立 collection_item_progress 表，主鍵 user_id＋entry_id；未有紀錄視為本人尚未訂正。entry_id 已唯一對應集合，同一來源題在不同集合的進度不互相影響。
- 狀態 unsolved／resolved／archived；解除封存恢復封存前狀態；複習次數沿用原卡完成／撤回訂正語義，實作時對照既有行為。
- GET 集合題目 detail／PUT /collections/:id/items/:entryId/progress 僅讀寫目前登入者的進度，後端驗證當前集合存取與貢獻權；不接受前端指定其他 user_id，也不隨公開搜尋／分享連結輸出私人進度。
- 進度 CAS 序號與 draw_seq／notes_seq 分開，狀態改動不覆蓋正在同步的筆記／筆跡。
- 共用集待刷列表、搜尋狀態篩選、課綱計數、大綱使用本人進度；新增共用題不承襲作者已訂正／已封存狀態。
- 將共用題存入個人題庫後，是獨立私人版本與其進度；不以此次封存／完成訂正同步作者原題、其他成員或另一集合。
