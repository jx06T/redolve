# 報告追問對話框

日期：2026-11-03。使用者要求以對話機器人的方式呈現追問，訊息獨立捲動、輸入放在底部。

- 追問區改為固定高度的卡片（85dvh、最高 56rem），分成標題、訊息捲動區與底部輸入區。歷史追問直接呈現，不再使用展開／收起區塊。
- 使用者訊息靠右，AI 回覆靠左，沿用 Markdown／LaTeX 與原題引用彈窗。輸入區留在卡片底部，訊息再長也不增加整頁高度。
- 初次讀取、送出與接收回覆只更新內層 scrollTop，不呼叫會捲動外頁的 scrollIntoView。使用者往上閱讀時保留閱讀位置，顯示「回到最新訊息」；非同步排版完成時也遵守相同規則。
- Enter 送出、Shift＋Enter 換行，略過輸入法組字中的 Enter。送出即清空當次輸入，等待期間可繼續寫下一個問題；回覆到達不會清掉新草稿。
- 失敗訊息保留在對話中，可使用同一個 ID 重試，不另加一則重複問題；讀取失敗及伺服器尚在處理的紀錄提供重新載入。
- 每份報告沿用各自歷史，切換報告會中止舊的讀取並清除畫面草稿與舊狀態。不改變 API、資料期限、判分、費用或生成次數規則。

## 模型格式要求

`learningPromptRules.ts` 新增共用 `responseFormatRules`，由數學格式規則帶入上傳辨識、訂正整理、報告選題、整科報告與追問：

- 外層只輸出本操作要求的嚴格 JSON，不加前後說明或 JSON 程式碼圍欄。
- Markdown／LaTeX 僅出現在文字欄位；陣列及物件維持 schema 型別。公式使用 `$...$`／`$$...$$`，JSON 正確跳脫反斜線、引號與換行。
- 沿用既有 ID，引用及選題只能來自輸入提供的 ID，不自建網址；首次辨識新選項仍可建立題內唯一 ID。
- 訂正提示版本為 `correction-v4`。原有 API JSON schema 與回傳驗證保持，沒有以 Markdown 取代資料協定。

## 驗證範圍

瀏覽器以模擬 API 驗證長歷史、自動捲動、閱讀舊訊息不被拉走、底部輸入位置、下一個問題草稿、Enter／Shift＋Enter、原題引用、報告切換與失敗重試；另檢查桌面及手機寬度。這不等於實機輸入法或真實模型品質驗收。

只修改前端與提示詞，不需要 migration。舊的背景辨識與 Markdown 版本 `267a2e4` 已先推送；本次對話框另行提交。
