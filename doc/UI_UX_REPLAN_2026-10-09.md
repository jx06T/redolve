## 2. Navbar、來源切換與篩選

### 2.1 全站導覽

- 寬螢幕：Logo、五個主 Tab、上傳／主題／帳號等既有工具。工具按鈕與五個頁面 Tab 視覺分組。
- 移除全站科目下拉及地球按鈕。進設定、總覽、延伸題目不會看到不相關的科目選擇器。
- 「搜尋」Tab 提供上傳／存入／我共用中三來源；第三來源針對可貢獻集合。公開探索及訂閱閱讀保留自己的頁內搜尋。
- 刷題才額外顯示既有頁內尋找框，窄版放於內容頂部，不擠壓主 Tab。標示「在已載入題目中尋找」，Enter 定位匹配，不暗中離開刷題。
- 刷題明確前往搜尋時帶入來源、指定集合及目前篩選；進入後兩頁各自保存狀態，不持續互相覆寫。搜尋頁顯示篩選標籤及清除入口。
- 手機底部使用「總覽｜刷題｜搜尋｜設定｜延伸題目」；延伸題目取代原本底部上傳位置，維持貼底方式。上傳移由頂部工具提供，首頁空狀態仍可有上傳入口；頂部不再重複五個 Tab。

### 2.2 同頁來源切換

刷題與搜尋頂部共用同款三段切換：

```text
[ 我上傳 ] [ 我存入 ] [ 我共用中 ]
```

- 只有這一處選擇來源；移除「全部個人題庫／我存入的題目」導覽膠囊與重複來源下拉。
- 切換只換本頁資料來源與配色；刷題仍在刷題，搜尋仍在搜尋。
- 記住上次使用的來源；上傳／存入／共用中各自保留篩選及閱讀位置。共用中另保留指定集合；權限失效不能因記憶狀態而繼續載入。
- 來源切換、科目篩選與明確頁面跳轉都寫入可還原的頁面狀態；上一頁可恢復，不重新載入整站。
- 系統背景更新、載入下一批、訂正存檔不新增瀏覽歷史。
- 科目／單元／狀態／標籤是篩選，不是新增來源。原題若需依「已加入的共用集」篩選，放側欄進階篩選，仍然只查自己的原題。

### 2.3 返回上一步與閱讀狀態（已確認）

- 在頁面內容標頭提供可辨識的「返回上一步」入口；瀏覽器上一頁與應用內返回使用一致的站內歷史。
- 每次明確跨頁、來源切換、套用篩選、提交搜尋前保存 NavigationCheckpoint：頁面、來源、collectionId、已提交關鍵字、篩選、排序、題目識別、題卡內相對捲動位置。
- 進搜尋後返回，或從更新摘要前往集合後返回，都還原原本題目與條件。圖片載入／虛擬列表重建後以題目 anchor＋相對位置復位，不只保存 scrollY。
- 定位其他題而調整篩選前先保存 checkpoint；顯示「已調整篩選以顯示此題」與「返回先前位置」。這個返回還原原題＋原條件，而非只把篩選改回。
- 返回只恢復瀏覽狀態，不撤銷已完成的存入、加題、筆記或分類修改；未同步草稿由作業上下文另行保存。
- 沒有有效站內歷史（例如直接開分享連結）時，用「返回刷題／總覽」等明確替代目的地，不盲目離開網站。
- 原題已移除或來源撤權時，還原可用的條件與附近位置並說明；不得用歷史快取繞過當下權限。
- 手機篩選面板有 draftFilters／appliedFilters，按套用才載入結果及建立歷史；取消不改條件。載入下一批、背景分類及自動儲存不新增歷史。
- 三來源長列表接近底部自動載入；loading／失敗重試留原位置，避免同一分頁重複請求。返回目標很深時需支援依題目定位或可恢復的分頁資料，不能假裝首批不存在就找不到。

## 3. 總覽與公開探索

### 3.1 總覽

保留原進度、近期複習、快捷入口。原有原題數據不在未標示來源時突然改成上傳＋存入的合計；如展示已存統計，須分開標示。

新增一個小型「近期動態」區與一張「探索公開題目」入口卡，不重做整頁。

建議把重複的「我的訂閱集／我訂閱的題目集」合併為同一個訂閱動態來源：
- 訂閱新題：「〔向量練習〕新增 5 題」→ 延伸題目並選定該集。
- 我的共用集：「〔段考複習〕有貢獻者加入題目」→ 該集管理；不顯示觀看者個人訂正紀錄。
- 已存題目：「3 題有可取得的來源更新」→ 刷題的已存來源及對應題目／清單。

動態只是閱讀入口，不代表必須發通知、跳彈窗或重新發布。改標籤／文字不計為新題；有權限且確實可取得更新才顯示來源更新，不能用已撤權來源洩漏新內容。

### 3.2 公開探索

- 從總覽進入即載入題圖卡，不等關鍵字、不先只列題目集名稱。
- 「所有公開題目」定義為：有效原題、有效提供者、有效成員關係，且集合 active＋public＋listed。
- 保留「公開但不列入探索」的作者選擇；持連結／指定對象內容不在探索列出。
- 頂部簡單搜尋，範圍固定公開探索；沒有「我的題庫／共用與訂閱」切換。
- 題卡有完整可辨識圖片、科目／標籤、來源集合、提供者；橘色識別條。可分批載入。
- 題目工具建議提供「存入／檢舉／分享」，訂閱設於集合資訊處，明示訂閱的是哪一集。
- 點來源集合進「集合閱讀」；訂閱成功保留目前頁面，提供「前往延伸題目」，不強制跳頁。
- 已訂閱的公開題仍可出現在探索，顯示「已訂閱」；已存題顯示「已存入」，不直接從結果移除。
- 同一原題可能在不同集合；先保留各自來源與權限，不以同一圖片自動合併。
- 未登入可讀公開內容；存入／訂閱時登入，回到原題與原頁，不自動替使用者完成未確認的操作。
- 熱門推薦列為後續能力，無真實排名時不顯示假資料或預留空模組。

## 4. 刷題與搜尋：三來源、明確書寫目標

### 4.1 刷題

```text
刷題                       [我上傳 | 我存入 | 我共用中]
┌ 側欄 ──────────┬ 主內容 ───────────────────────┐
│ 科目／單元      │ 已載入題目中的尋找、目前篩選    │
│ 訂正狀態        │ 題卡：圖片＋私人筆跡＋私人筆記  │
│ 標籤            │ 題目工具列                     │
│ 縮圖定位        │ 題卡…（連續捲動）              │
└────────────────┴───────────────────────────────┘
```

- 上傳與存入使用相同連續列表、側欄、手寫與筆記互動；已存題不只以摘要卡跳到另一個詳情頁才能訂正。
- 上傳題卡維持白色；已存題卡用綠色來源條／邊框，圖片與實際書寫區維持乾淨底色。
- 上傳題卡在既有工具中新增「加入共用集」。選單僅列目前仍有貢獻權的集合，顯示名稱、對外狀態及是否已加入。
- 加入成功保留卡片與閱讀位置，新增「已加入〔集合名〕」標示；可點標示明確進集合，不自動導航。
- 不把本人私人筆記自動複製到共用層；「加入共用集」只分享原題與既有白名單來源資訊。
- 已存題使用本人的私人作業；已取得的來源筆記是唯讀參考層，不能擦除成自己的筆跡。
- 原題專屬操作不能原樣套用到 saved：例如「加入共用集」不出現在已存題；不提供繞過重新分享限制的複製操作。
- 「移除我的已存版本」不叫「刪除原題」；不影響來源、其他人、訂閱。
- 「更新來源內容」只在有權取得且內容有更新時出現，保留自己的筆跡／筆記／狀態／分類，不另開一份題。
- 連續列表的載入、虛擬捲動、收合展開不能改寫筆跡座標或遺失尚未存檔的操作。

### 4.2 搜尋

- 刷題與搜尋對應同一份 StudyScope：owned、saved、contributing（我共用中）。contributing 須指定有效可貢獻集合；不包含僅可觀看／訂閱的集合，也不混入公開探索。
- 語意一致：相同來源、相同可見性、相同科目／狀態條件下，可刷的題目才能被搜尋。搜尋另加文字條件，不創造另一套題庫。
- 未分類與分類中的已存題仍在個人題庫；至少能按已有標題、來源與自己的文字搜尋。手寫線條不假裝可做文字搜尋。
- 空關鍵字先列目前來源的最近題目；共用中須先選集。按 Enter／搜尋按鈕才提交文字查詢。三來源均呈現與刷題相同的題卡及可用操作；共用中寫自己的共用層，不修改他人原題或私人筆記。
- 「在刷題中開啟」為明確導航動作，攜帶來源與題目 ID，定位該題；不是點來源篩選就換頁。
- 查看來源新內容必須明確走來源入口；saved 搜尋使用已取得版本，不偷換成作者最新版本。
- 搜尋結果空白時說明目前來源與條件，提供清除篩選，不顯示像資料遺失的空白畫面。
- 某題因編輯而不再符合文字或分類條件，保留當前卡片至重新搜尋，提示結果待更新，避免正在訂正的題卡突然消失；權限撤銷仍需立即停止供應來源內容。

### 4.3 我共用中：集合協作也使用刷題與搜尋

```text
刷題／搜尋        [ 我上傳 ] [ 我存入 ] [ 我共用中 ]
題目集：[選擇我有貢獻權的集合 ▾]
共用書寫 · 集合名稱 · 我的角色 · 分享範圍
正在編輯「我的共用筆跡／文字」；其他作者圖層唯讀
連續題卡＋既有畫筆／筆記操作
```

- 「我共用中」定義為：目前有題目貢獻及本人共用層書寫權的集合內題目，包含自己及其他貢獻者提供的題目。它不是「自己曾公開的原題」篩選。
- **補完建議**：先選一集再顯示題目；新進入未有有效選擇時顯示選集空狀態。選單含目前可貢獻集合，與延伸題目的已訂閱選單使用不同資料條件。
- **補完建議**：搜尋的我共用中也限定所選集合；不預設跨所有共用集合聚合，避免同原題在不同集合的筆記與權限混用。
- 可貢獻不需先訂閱；只訂閱不會出現在這裡；同時具有兩種關係時可從兩處使用不同模式。
- 同一原題在「我上傳」編輯私人層，在「我共用中」編輯指定集合的共用層。模式條持續顯示集合名稱與書寫目標，不讓相同題圖掩蓋儲存位置差異。
- 共用書寫必須顯示本人的可編輯層；另預設顯示原題提供者的可見共用層作參考，若兩者同一人則去重。其他作者可選擇顯示且維持唯讀。Q22 的閱讀預設不能讓本人新畫的線條隱形。
- 個人訂正狀態／私人分類篩選只用於 owned／saved；contributing 以集合中可見分類／來源資訊篩選，不引入所有人共用的「已訂正」狀態。不可操作的工具不直接照搬。
- 搜尋可查可見題目資訊及已授權共用文字，結果保留同樣的共用作業；不索引其他人的私人筆記。
- 管理者與貢獻者各依既有角色權限操作；寫自己的層不代表能改其他人的原題、筆記或集合設定。
- 原題標示「已加入某集」時可提供明確「前往共用書寫」；從設定管理的相同入口也開啟這一頁，保留返回 checkpoint。
- 撤去貢獻權時立即停止共用寫入，選集資料更新；若仍有觀看權，可提供明確前往唯讀集合的動作，不能在同一卡片悄悄改存成私人筆記。

## 5. 延伸題目：只觀看已訂閱集合

```text
延伸題目                        [題目集：請選擇 ▾]
選定後：集合名 · 提供者 · 存取範圍
[ 在「此集合名稱」中搜尋 ]             [全部 | 已標星]
┌ 題圖（完整寬度，可連續捲動）───────────────────┐
│ 已獲准顯示的共用筆跡、文字筆記                 │
├──────────────────────────────────────────────┤
│ [存入]         [標星]        [檢舉]     [分享] │
└──────────────────────────────────────────────┘
下一題…
```

- 選集選單只來自「我已明確訂閱」，不把自己建立、可編輯、偶然看過的公開集合混進來。
- 選單支援名稱搜尋與三種排序：訂閱時間（新到舊）、觀看紀錄（最近觀看優先，未看過的放後）、名稱字母順序（介面語系排序；中文依相應語系校對規則）。保留使用者上次排序；初次預設訂閱時間為補完建議。
- 新題數以新加入的集合項目及既有閱讀紀錄計算，不把內容更新當成新題；無權取得的集合不顯示新題數。排序不改變訂閱關係，不要求逐題打開詳情才計觀看紀錄。
- 閱讀途中新增題目，頁首顯示「有新題目」，按下才刷新列表並保存返回 checkpoint；既有題目的授權及可讀內容仍按原更新規則處理，撤權不能等手動刷新。
- 直接打開 Tab 的初始狀態為「選擇題目集」；由總覽／訂閱管理帶 collection_id 進來，可以直接選中該已訂閱集合。上一頁回來恢復原選擇。
- URL 指定的集合未訂閱：不偷加入選單；提示「尚未訂閱此集」，可明確前往集合閱讀。存取權限仍逐次檢查。
- 未選集不發題目列表請求、不顯示混合 feed。未訂閱任何集合時提供「探索公開題目」入口與簡短說明。
- 選集後最新加入者在前，使用連續列表直接顯示圖片；不把 metadata 變更當成新題。
- 集合內搜尋只搜尋目前選定的集，placeholder 包含集名；切換集合時清掉上一集關鍵字與「已標星」篩選，避免新集看起來空白。
- 不需要進單題詳情才能讀圖；分享連結可定位串流中的該題，仍展示集合上下文。
- 延伸題目維持閱讀模式，不放共用書寫入口。貢獻者從刷題／搜尋 → 我共用中進入；即使同時是訂閱者，閱讀頁也不自動切成編輯模式。
- 共用文字與筆跡先通過權限與展示開關；閱讀預設顯示原題提供者的共用筆跡，其他作者由圖層選擇器開啟。提供者無可見共用層時顯示原題，不拿其私人筆跡替代。
- 共用文字在題圖下方依作者顯示摘要，點擊展開；完整題圖持續顯示。個人圖層顯示偏好不能打開未獲准內容。

四個題目動作：
| 操作 | 狀態與結果 |
|---|---|
| 存入 | 存入中 → 已存入；保留來源卡片與捲動位置。已有個人版本時不重複建立。成功提示提供「查看已存題目」。 |
| 標星 | 本人對這個集合內這一題的私人標記，不存圖、不訂閱、不取得永久觀看權；可於此集的「已標星」篩選找回。 |
| 檢舉 | 應用內表單，帶集合與題目識別；送出成功留原頁，不影響已存資料。 |
| 分享 | 開啟應用內分享面板、複製此題的集合定位連結；不建立新的公開授權、不複製自己的登入憑證或觀看 token。接收者仍須通過原 ACL。 |

「已存入」仍占原存入按鈕位置，不另長出第五個工具；在成功提示或該位置的明確文字入口可開自己的版本。標星與存入各自回報，不互相切換。

若此題本來就是本人上傳的原題，存入位置顯示不可重複操作的「我的原題」，不送出會失敗的自我存入請求。貢獻者也不因此取得延伸頁的共用書寫工具。

來源失效：單題失效僅標示該題；整集失權時保留在選單的「目前無法存取」區，不把已存題刪掉。取消訂閱後從選單移除，已存版本與私人星號紀錄保留；重新訂閱且有權讀取同一項目才恢復星號顯示，不將舊星號轉接到刪除後新建的項目。星號不保留來源圖片。

## 6. 設定：管理區，不與閱讀混排

設定保留既有偏好分頁，增加「共用題目集」「訂閱中心」。分頁可直接連結，重新整理不跳回第一頁。

### 6.1 共用題目集管理

- 一份簡單列表：名稱、狀態、我的角色及少量整體數據；列末主動作「管理」。
- 包含目前由我管理、或目前有貢獻權的集合；訂閱本身不讓集合出現在這裡。
- 列表顯示題目數、有效貢獻者數；訂閱總數僅集合管理者可見。另顯示本人角色與關係，不公布個人訂閱者閱讀／訂正狀態。
- 角色與關係分別標示「管理者／貢獻者」及「已訂閱（訂閱者）」，可同時存在；純訂閱者仍在訂閱中心，不因角色標籤加入共用管理列表。貢獻權不等於可修改全集合設定。
- 歷史建立者轉交後以目前權限為準；「創始人」不是永久管理特權。

進一集後分為：
1. 題目：目前題目清單、批次加入、依權限移出。
2. 前往共用書寫：明確導向刷題 → 我共用中 → 該集合；不在設定維護另一份書寫頁。
3. 集合設定：名稱、說明、觀看範圍、是否出現在公開探索、共用內容展示、成員、移交、暫停及刪除。僅目前管理者可操作。

貢獻者不顯示可點擊的權限／刪除集合操作；可加入自己的原題、移出自己的題、寫自己的共用層。管理者可移出集合內任何題，仍不可改他人原題或筆跡。

### 6.2 訂閱中心

- 只管理「訂閱哪幾集」：集合名稱、作者、可讀／失效狀態、本人角色／已訂閱關係、觀看入口、取消訂閱。同時是貢獻者或管理者時可並列標籤，不因此混入書寫工具。
- 搜尋框搜尋訂閱列表的集合名稱／作者，不假裝在搜尋題目。
- 「觀看題目」→ 延伸題目並選中該集。
- 「取消訂閱」使用應用內確認，明示「將從延伸題目移除，已存入的題目會保留」；完成後留管理列表。
- 不因訂閱產生貢獻權，不因有貢獻權自動產生訂閱。

### 6.3 公開名稱與平台管理

「貢獻題目時顯示的名稱」是帳號的公開署名，用於原題提供者及共用筆記作者，不是集合名稱、權限角色或私人帳號備註。

採用設定 → 帳號 →「共用時顯示的名稱」，說明：「其他人會在你提供的題目與共用筆記旁看到這個名稱。」首次貢獻時若尚未設定，以小型對話框補齊，之後不用在每個集合重填；不可預設使用 email 當公開署名。

平台管理只供站方指定管理者。一般使用者與集合管理者都不因此取得平台管理權。若目前看得到此頁，需另確認登入者是否本來就是平台管理者，不能僅憑畫面判定權限漏洞。前端隱藏入口之外，後端仍須驗權。

## 7. 批次加題：先選範圍，再執行加入

共用集管理 → 題目 →「加入我上傳的題目」開啟大型選題面板：

```text
加入至〔集合名稱〕                    目前：公開／指定對象／草稿
來源固定：我上傳的題目
[科目 ▾] [單元 ▾] [含子單元] [標籤] [關鍵字]
☐ 題圖縮圖  來源、分類  已加入／可加入
☐ 題圖縮圖  來源、分類
已選 N 題     [選取本頁] [選取全部符合條件的 M 題]
[取消]                            [加入 N 題]
```

- 分類篩選後可選數題，也可明確選取全部符合條件；操作前顯示實際範圍與總數。
- 「選取本頁」與「全部符合條件」分開，不能讓虛擬列表的未載入題目悄悄漏掉。
- 跨頁、跨分類、跨關鍵字保留選取。固定顯示「已選 N 題（其中 M 題不在目前篩選）」及「查看所有已選／清空選取」，可逐題取消。選取全部符合條件時追加當次固定候選並去重，後續條件變更不重新解釋既有選取。
- 已加入項目標記已加入，不重複新增；不能選入自己的 saved 題或他人的原題。
- 類別批次加入是當下清單，不建立「未來所有此分類自動公開」規則。老師原有「預設上傳後加入某集」是另一項明確帳號偏好。
- 大批數量可分批處理；部分失敗時保留面板，顯示成功／失敗／未處理，只重試失敗或未處理項目。取消後續處理不撤銷已成功加入的題。
- 選集面板持續顯示公開／指定對象等分享範圍，確認加入即執行，不逐次追加公開確認框。
- 後端須固定本次候選 ID 範圍、逐題重驗擁有權／集合權限／圖片狀態；UI 不僅靠當前載入頁推測總數。
- 刷題／搜尋原題卡的「加入共用集」使用同一選集與回報行為。若之後提供列表批次選取，也不另創不同加入規則。

## 8. 對話框與 Switch

### 8.1 刪除集合

- 使用應用內 ConfirmModal，禁止瀏覽器原生 confirm。
- 標題「刪除〔集合名稱〕？」；內容明示「集合會停止共用；原題與他人已存入的版本不會因此刪除」。
- 「取消」與「刪除集合」；處理中禁重複送出，失敗留對話框並說明，成功返回設定中的共用題目集列表。
- 刪集合、移出題目、刪自己的原題、移除自己的已存版本，四者用不同動詞與說明，不共用含糊的「刪除」文案。

### 8.2 共用內容展示

兩個獨立設定列，不把文字和方形 checkbox 擠在同一個可點區：

```text
向觀看者展示共用筆跡                         [ Switch ]
允許觀看者查看現有與後續的共用手寫內容。

向觀看者展示共用文字筆記                     [ Switch ]
允許觀看者查看現有與後續的共用文字內容。
```

- 左側標題／說明不切換狀態；右側圓角軌道＋圓形滑塊是獨立點擊區，觸控目標建議至少 44×44。
- 有鍵盤焦點、Space 操作、可觸及名稱及開關狀態；不要只靠顏色表示開啟。
- 建議直接儲存：切換時有處理狀態、避免連點，失敗回復該項並顯示原因；不能讓使用者誤以為成功。
- 兩個開關不互相連動。說明清楚：影響共用層，私人筆記不受影響；已合法存入的版本不會被收回。
- 批次選題的多選框仍然是 checkbox；不是把所有方框都換成 switch。

## 9. 存入、分類與不消失保證

### 9.1 成功流程

1. 點「存入」，按鈕顯示處理中，防重複送出。
2. 伺服器確認個人版本已存在，才顯示「已存入」；返回穩定的 saved ID。
3. 保持來源卡片、捲動位置、星號；不因已存而自動移出目前列表。
4. 提示：「已存入『我存入的題目』」＋「查看」。
5. 點查看進入刷題的 saved 來源，定位該題；清除會遮住目標的舊篩選並明示，不落到空清單。
6. 初始分類未完成也可以閱讀、寫自己的筆記；分類結果更新不能把正在看的題卡抽走。

同題重複存入回傳既有個人版本，不重設筆記、不再觸發一次分類、不暗中更新來源。暫時斷線不能先顯示雲端存入成功；結果不明時可安全查詢／重試。

**跨集合相同原題**：以可信原題 ID 判定，且只查本人的既有 saved 紀錄；提示「你曾從其他集合存入相同原題」，可選「查看我的既有版本」或「另存此來源」。不以圖片相似度猜測，不洩漏無權來源的現行內容。仍以使用者＋集合項目維持冪等，同一來源不重建；另存來源建立獨立作業上下文。

**來源更新**：逐題操作，先取得有權讀取的變更摘要（例如標籤／共用筆記），提供「更新來源內容／維持目前版本」與「前往集合查看」。跳轉帶 entryId 定位並保存返回 checkpoint；從集合返回回到原已存題、原篩選。確認更新時重驗權限與版本；若來源已再變更，刷新摘要重新確認，避免套用未檢視的版本。無法精確列出差異時明示僅有版本更新，不捏造摘要。

### 9.2 分類規則

| 來源分類 | 存入行為 |
|---|---|
| 有效且可用的官方分類 | 依官方分類 ID 沿用，不用名稱相似度猜測，不重新呼叫 AI。 |
| 私人自建分類 | 不複製對方私人課綱，存入成功後以已取得的題圖重新呼叫 AI，分類到本人可用分類。 |
| 未分類／官方分類已停用或無法對應 | 建議走同一 AI 分類流程；未有可靠結果留未分類。 |
| AI 無可靠結果、服務失敗或額度不足 | 個人版本保留在「我存入的題目」，標記「待分類／分類失敗」，可重試或手動指定。 |

補完建議：
- 分類任務與題目存入、訂正狀態分離；不能因 AI processing 而從個人清單消失。
- AI 候選只能是本人可用的課綱節點，不替本人擅自建立新課綱或複製作者的私人分類名稱。
- 使用者先手動指定分類時，晚到的 AI 結果不能覆蓋。
- AI 分類不讀來源作者私人文字／筆跡，不修改來源題目。
- 手動「更新來源內容」保留本人的分類與訂正；重新分類是另外的明確操作。
- 來源之後撤權，已取得圖片仍可在自己的分類流程使用；不能以來源已失權為由刪掉下載版本。
- 待分類至少在「所有科目／未分類」可見，首頁的「查看已存題」可直接定位，不要求使用者猜科目。

### 9.3 現在回報的「存入後消失」

標為 BUG-SAVED-01，尚未判定根因。後續需分別查：
- 存入請求是否真正成功、是否取得 saved ID。
- 列表是否讀取 saved 資料，還是只查 uploaded。
- 是否被科目、狀態、已存／未存條件或舊分頁排除。
- 是否只更新當前卡片，其他清單仍使用過期快取。
- 是否誤把來源權限套到已存版本。

不能把「新的頁面名稱」當成已修復此問題；需驗證重新整理、重登、撤權後仍能讀自己的已存內容。

## 14. API 以上的應用服務抽象與 UI 分層

目標：頁面只表達「查某範圍題目」「存入」「儲存這份作業」，由統一介面處理不同 API 的資料格式與操作流程。下列服務名稱、型別與檔案分組是規劃，尚未深入對照現有程式；實作時優先整理現有 API client 與服務。

### 14.0 已確認的建模與非全面 class 原則

領域物件指具備明確識別、欄位及關係的資料模型，不要求是 class 實例。採用 TypeScript 型別／interface＋普通資料物件，配合服務函式與組合；不規劃日後為了「正式化」全面改成 class。

| 核心物件 | 責任與關係 |
|---|---|
| Question | 題目內容的領域模型，包含識別、題圖參照、分類及版本；不在資料物件掛 fetch／save／delete。 |
| Collection | 集合名稱、分享設定及可取得的角色／統計摘要；成員、題目與作業按需要另取。 |
| CollectionEntry | 題目加入某集合的關係及穩定 entryId；同一原題在不同集合有不同上下文。 |
| QuestionWork（題目作業） | 某人針對原題私人、已存私人或指定集合情境的筆跡／文字與儲存版本。私人訂正狀態僅放適用的私人作業變體。 |

名詞調整：原稿的 Workspace 資料概念改稱 QuestionWork；寫入目標稱 WorkTarget，服務稱 WorkService。它不是新增產品頁面或使用者必須學習的名稱。以上是應用模型命名，不要求更名既有資料表（例如 personal_workspaces）、API 路徑或立即遷移資料。

實作規則：

1. **資料與副作用分開**：Question／Collection／CollectionEntry／QuestionWork 為普通資料；查詢、存入、加題與儲存作業由服務函式執行。服務名稱不表示必須 new 一個 class，可用模組匯出函式或普通函式集合。
2. **關係用組合表示**：以 ID／ref 連接題目、集合項目及作業，避免 OwnedQuestion → SharedQuestion → SavedQuestion 等繼承樹。同一題的擁有、共用與存入關係可並存。
3. **API 邊界驗證**：TypeScript 型別不會自動驗證 JSON；adapter 在必要邊界驗證回應並轉為一致模型。傳輸／持久資料使用可序列化欄位，不依賴 prototype 還原或實例方法。
4. **明確狀態更新**：純資料轉換使用純函式；React／query cache 採不可變更新或既有明確訂閱機制。不能在資料物件內偷偷改欄位並假設所有畫面會更新。
5. **同步依穩定識別**：不同頁面透過統一 cache key、服務結果與版本更新取得一致內容，不以某個 class instance 的記憶體身分作唯一依據。
6. **分頁與按需載入**：取得集合摘要不等於取得全部題目；entries 分頁、題圖與作業依可視／編輯需要載入。允許批次 API 或列表附帶必要資料，避免每張卡產生多個串行請求。
7. **可測試的服務**：API client／本機 adapter 等依賴明確傳入或組裝；資料轉換可獨立驗證，業務操作可替換介接。不要為每個 DTO 建立 factory／repository class。
8. **有限的狀態控制器**：畫布引擎、復原堆疊、同步佇列若確有持續狀態與生命週期需求，可保留或局部使用 class；不強制以 class 實作，也不讓控制器成為可持久化領域資料。既有第三方 class 無須為此重寫。

概念對照：

```ts
// question、collection、work 是普通資料物件。
// 服務集中實現操作；不要求 question.save() 或 new Question(dto)。
const entries = await collectionService.listEntries(collectionId, { cursor });
await workService.saveNotes({ target, notes, expectedNotesSeq });
```

這些介面是設計示意，實作時仍需對照現有 endpoint 與參數，並保留後端的授權與版本檢查。

### 14.1 呼叫方向與介面職責

```text
頁面／題卡
  ↓ 使用者意圖
React hooks／作業控制器
  ↓ 統一且具型別的應用介面
Application Services（題目查詢、存入、共用、作業、訂閱）
  ↓ 來源對應與資料轉換
Adapters（owned API / saved API / collection API / guest local）
  ↓
API Client（HTTP、登入資訊、解析、取消請求）
  ↓
既有後端 API（授權、原子寫入、版本檢查、資料庫）

guest local adapter → 本機儲存
```

- API Client 管傳輸；不決定存入後跳哪一頁，也不判定集合業務權限。
- Adapter 將既有 DTO 轉為一致的領域讀取模型，並將明確指令轉成正確 endpoint／payload。它知道 saved 與 owned 的欄位差異；UI 無須自行猜測。
- Application Service 組織一項完整應用動作，例如存入前檢查相同原題、執行存入、回傳穩定個人版本與分類狀態。具有原子性要求的部分由後端完成；多個前端 HTTP 請求不能假裝是一個交易。
- Hooks／controller 負責 React loading、query cache、樂觀呈現、草稿生命週期與服務訂閱。服務不引用 React、路由或 toast，方便在搜尋、刷題、批次面板共用。
- 頁面負責根據結果顯示 UI 與執行明確導航。服務回傳領域錯誤，頁面依情境呈現；不由深層 API 模組偷跳頁。
- 既有後端逐次授權仍是最終依據；前端統一介面不取代它。這一層可逐步包住現有 API，不要求一次改完後端或新增通用資料表。

建議的最小服務介面：

| 應用介面 | 主要操作 | 統一處理 |
|---|---|---|
| QuestionService | list、search、get、locate | 三種刷題來源／外部閱讀的內容格式、scope、分頁、題目定位與能力。 |
| LibraryService | inspectSave、save、previewSourceUpdate、updateSource、removeSaved | 跨集同原題提示、存入冪等、個人版本、分類狀態、來源摘要及版本確認。 |
| WorkService | load、saveInk、saveNotes | 私人原題／私人已存／本人共用層的寫入目標、獨立序號、衝突與權限錯誤。 |
| CollectionService | get、listEntries、listContributable、addItems、removeEntry、updateSettings | 可貢獻集合、固定候選的批次操作、逐題結果；設定與移出各自權限。 |
| SubscriptionService | list、subscribe、unsubscribe、setStar | 訂閱關係、三種排序、集合項目私人星號、失效狀態。 |

這是功能分組，實作可沿用少量現有模組；不要求每個方法都產生一層 class／interface／factory。管理成員、移交等既有能力維持原服務，按需要收斂入口。

概念呼叫範例（不表示現有 API 已支援）：

```ts
const page = await questions.search({
  scope: { kind: 'study', source: 'contributing', collectionId },
  query, filters, cursor, signal,
});

const result = await library.save({
  collectionId, entryId, idempotencyKey,
}); // { savedRefId, outcome: 'created' | 'existing', classificationState }

await workService.saveInk({
  target: { kind: 'shared', collectionId, entryId, generationId },
  strokes, expectedInkSeq, mutationId,
}); // 寫入者由登入身分決定，不能讓呼叫端代填另一位作者
```

介面共通規則：

1. **Scope 與 target 必填**：讀取範圍和寫入目標分開定義；集合閱讀的 collection ref 本身不代表有共用書寫權。
2. **穩定領域模型**：QuestionRef、內容版本、分類狀態、可用動作及 WorkTarget 分開；不把異質 DTO 全部強制轉成舊 Item 型別。
3. **分頁契約**：回傳 entries、nextCursor、必要的 total／hasMore。cursor 綁 scope／filter／sort，換條件不得沿用舊 cursor。只有底層確實可得時才回傳精確總數。
4. **統一錯誤**：區分未登入、無權限、來源失效／不存在、版本衝突、驗證失敗、暫時斷線、限流、儲存空間不足；保留診斷用 code／requestId，不把原始敏感回應直接顯示給使用者。
5. **取消與過期結果**：讀取接受 AbortSignal；來源或帳號切換時忽略舊結果。取消 HTTP 等待不代表伺服器已取消寫入，結果不明時用冪等識別確認。
6. **重試規則**：安全讀取可有限重試；存入／批次加入／作業寫入需先具備適當冪等與版本語意。403／版本衝突不自動覆寫重試，避免失權後反覆寫入或蓋掉新作業。
7. **結果驅動快取更新**：服務回傳 savedRefId、影響的題目／集合及新版本；hook 用統一 cache key 更新關係、列表、計數。服務不直接操作元件 state。
8. **認證與圖片讀取**：API Client 使用既有登入機制；授權圖片 URL 僅當傳輸資料，可重取，不當永久題目 ID。登出隔離私人 cache、草稿與進行中回應。
9. **後端缺口需明列**：若摘要版本、定位、星號或批次候選能力不存在，記錄必要 endpoint／資料變更，不能在前端用假值補出「完成」。

### 14.1.1 應用模型與 UI 的對應

| 模型／UI | 用途 |
|---|---|
| QuestionRef／QuestionContent | Question 的識別及授權內容讀取格式。 |
| Collection／CollectionEntry | 集合與成員題目關係；以識別連接，不整批內嵌所有題目。 |
| QuestionWork | 題目作業資料；私人與共用變體使用明確目標、作者及獨立儲存版本。 |
| WorkTarget | 明確選中原題私人、saved 私人、指定集合本人共用層；不由頁面顏色猜測。 |
| StudyScope／QueryScope | 刷題與搜尋共用三來源；訂閱閱讀／公開探索使用另一種 query scope。 |
| Capabilities | UI 可用動作提示；每次執行仍由後端授權。 |
| QuestionFrame／Image／Toolbar 等 | 呈現層重用，共用排版與畫布，透過 hook 調用應用服務。 |

### 14.2 題目識別與版本

概念型別：

```ts
type QuestionRef =
  | { kind: 'owned'; storage: 'local' | 'cloud'; itemId: string }
  | { kind: 'saved'; savedRefId: string }
  | { kind: 'collection'; collectionId: string; entryId: string };

type StudyScope =
  | { kind: 'study'; source: 'owned' | 'saved' }
  | { kind: 'study'; source: 'contributing'; collectionId: string };
type QueryScope =
  | StudyScope
  | { kind: 'collection-reading'; collectionId: string }
  | { kind: 'explore' };
```

- 訪客 local 原題由本機儲存介接；不能把本機 ID 當雲端 item ID 呼叫 API。登入移轉沿用既有流程，另驗證來源映射。
- savedRefId 為穩定的個人版本入口，下載內容版本另記；使用者明確更新來源時只替換已取得內容，保留作業上下文、分類與私人訂正。
- collectionId＋entryId 代表特定集合內的一題。相同原題加入不同集合，各自有觀看權、共用層與星號；不能只用 source item ID 或圖片 hash 合併。
- 重複存入的判定沿用同一使用者＋同一集合項目，不以相同圖片自動合併不同來源。收藏按鈕必須能取得對應的 savedRefId。
- React key、草稿 key、快取 key 都以正確來源識別建立；私人資料另綁登入帳號，訪客資料綁可跨重新整理保留的本機訪客命名空間，避免登出換帳號後讀到前一人的狀態。
- 舊分享連結經相容解析器解析至可讀來源；私密憑證不放入可複製 URL 或一般快取鍵。既有明確的分享授權連結依原規格處理，不能把本人登入／觀看憑證轉送給別人。

### 14.3 題目內容與題目作業分離

| 使用情境 | 顯示內容 | 可寫入目標 |
|---|---|---|
| 上傳題刷題／搜尋 | 本人原題與自己的私人作業 | 該原題的私人筆跡／文字／訂正狀態 |
| 已存題刷題／搜尋 | 已取得題圖與參考層，加上自己的私人作業 | savedRefId 對應私人作業 |
| 延伸題目／集合閱讀／探索 | 現行授權允許的題圖與共用參考層 | 無書寫目標；僅依頁面提供閱讀操作 |
| 刷題／搜尋的我共用中 | 指定集合題目與可見貢獻者層 | 本人在該集合項目、有效世代的共用層 |

- 原題作者的私人筆跡不因加入集合變成共用層；管理者也不因此取得他人的筆跡寫入權。
- 畫布元件只處理固定圖片座標、工具、可見圖層與筆跡變更回呼；儲存介接層處理 API、權限、版本序號與失敗重試。
- 共用層 key 必須含集合、項目、作者及既有有效世代識別；撤權後重新加入不能誤續寫已失效的舊層。
- 私人文字與筆跡保留各自版本控制及寫入入口；避免修改文字時以完整舊物件覆蓋新筆跡。既有並行寫入規則保持，UI 明示儲存失敗或衝突，不額外引入「所有修改一律複製兩份」流程。
- 固定題圖／座標基準持續遵守現階段不支援替換、裁切原題的限制；更新 saved 參考內容不搬移本人筆跡。

作業控制器管理草稿、待送出內容、儲存狀態與失敗恢復，生命週期高於單張虛擬列表卡片。卡片離開畫面不能直接丟掉 debounce 中的內容；切換帳號時不能把前一帳號的請求套到新帳號狀態。

**本機草稿與儲存 UX（Q29／Q30）**：
- 斷線或伺服器暫時失敗時，將本人未同步筆跡／文字保存於本機，顯示「尚未同步」，允許換頁。不能把仍在記憶體的草稿宣稱為已保存在此裝置。
- 草稿按帳號、WorkTarget、世代、文字／筆跡序號隔離；僅保存本人的待寫內容及必要定位資訊，不順便持久快取外部題圖或其他人的共用層。
- 連線恢復後重驗權限及 expectedSeq；成功才清除已確認部分。撤權／世代失效停止重送並標示原因；版本衝突保留未同步作業、提示處理，不靜默覆蓋。
- 若來源圖已不可讀，只能保留本人草稿，不能透過復原草稿重新供應被撤權的題圖。
- 本機儲存失敗／額度不足時持續顯示風險及重試，離頁前明確提示可能遺失的內容，不顯示虛假的「已保存」。
- 登出前若仍有草稿，顯示未同步數與處理入口；換帳號不顯示或送出前一人的草稿。重新登入相同帳號後才恢復可用草稿；清除瀏覽器資料會移除本機草稿，需在待同步狀態說明。
- 一般編輯顯示「儲存中 → 已儲存」後淡出；斷線、失敗、衝突提示持續顯示且有重試／處理入口。尚未同步不能顯示已雲端儲存。

**收合高度規則**：`isCollapsed` 是呈現狀態；展開高度、書寫範圍是另外的狀態。收合時不能把量測到的 0／標頭高度寫回展開高度。重新掛載須依同一作業上下文還原，寬度改變依既有座標換算，不拉伸既有筆跡。此處是回歸驗收要求，尚未聲稱找到現行高度問題的根因。

### 14.4 動作契約與權限

避免單一 `canEdit`：它無法區分編輯自己的題、自己的共用層與管理集合。

| 動作 | 輸入識別／效果 |
|---|---|
| 存入自己的題庫 | 集合項目 → 穩定 savedRefId；可重試且不重複建立，不清除原題卡。 |
| 更新已存來源 | savedRefId＋有權取得的來源版本 → 更新下載內容；私人作業保持。 |
| 加入共用集 | 本人的 cloud itemId＋可貢獻集合 → 集合項目；同一組合重試不重複加入。 |
| 移出集合 | collectionId＋entryId；影響集合成員關係。 |
| 移除我的已存版本 | savedRefId；影響本人已存內容與私人作業，確認框明示此效果。 |
| 刪除我的原題 | itemId；沿用原題刪除影響與資產保留規則，明示對共用來源的影響。 |
| 刪除集合 | collectionId；只具有該權限的管理者可用，保留合法已存版本。 |
| 寫入共用層 | 指定集合項目與本人圖層；不可代寫其他作者。 |

伺服器回傳可用能力供 UI 顯示；每次執行仍以當下權限為準。訂閱關係、作者身分、來源顏色、前端按鈕顯示，都不能代替後端授權。操作中被撤權時留在原頁顯示原因，更新可用動作，不把它當成成功。

共用的應用動作負責成功／失敗回報與快取更新。卡片、搜尋結果、批次面板不各自實作一套存入／加題規則；批次操作在共用單題語意之上增加固定候選範圍、分批執行及逐題結果。

### 14.5 查詢、狀態與路由

- 刷題與搜尋共用 StudyScope 及相同篩選定義；搜尋增加文字條件。各來源由薄介接層轉成相同列表讀取格式，不能假造 user_id 或其他原題欄位來讓 saved 看似 owned。
- 集合搜尋必有 collectionId；公開探索必帶公開可列出的限定。禁止以沒有 scope 的通用搜尋意外退回全站結果。
- URL 編解碼與入口建構集中處理。來源切換只更新本頁 scope；「前往刷題」「管理」「查看已存題」才執行明確的跨頁導航。
- 列表快取包含帳號、scope、篩選、排序、分頁；切換集合／來源時取消或忽略舊回應，避免晚到資料覆蓋新頁。
- 存入成功後更新來源卡片的 saved 關係，更新個人 saved 列表及相關計數；不能只刷新原題列表。AI 後續分類也要更新同一個人版本的相關查詢。
- 儲存個人題目的權限依本人 saved 所有權判定；來源失效只影響線上來源讀取／更新，不令個人版本消失。
- 外部來源保持線上授權讀取，不因共用題圖元件而放進持久 Service Worker 圖片快取。已存資產保留規則與「離線快取」分別處理。

狀態歸屬：

| 狀態 | 所在層 |
|---|---|
| 頁面、source、選集、關鍵字、篩選、定位題 | 路由／頁面狀態；可還原 |
| 題目、saved 關係、訂閱、星號、權限 | 伺服器資料與對應查詢快取；訪客原題用本機儲存 |
| 尚未儲存的筆跡／文字、版本序號、重試 | 指定作業控制器；不隨虛擬卡片卸載丟失 |
| 開啟哪個選單、hover、暫時的確認框 | 元件呈現狀態 |
| 展開高度／書寫範圍、收合狀態 | 分別保存；同一題作業上下文恢復，不互相覆寫 |

### 14.6 題卡組合與最小抽取範圍

共用結構：`QuestionFrame` → 出處／來源標示、`QuestionImage`、唯讀參考層、可選的作業上下文、工具列。由頁面選擇明確模式：

- `OwnedStudyCard`：私人作業＋原題工具。
- `SavedStudyCard`：私人作業＋已存專屬工具。
- `CollectionReadingCard`：完整題圖＋唯讀參考內容＋該閱讀頁的動作集合；延伸題目固定四操作。
- `ContributionEditingCard`：刷題／搜尋的我共用中使用；共用標示＋本人的共用作業＋協作工具。

來源條、圖片載入／重試、工具列排版、筆記收合、AppDialog、SwitchRow、SourceTabs 可重用。工具列由明確的 action slots 組合，不建立包含大量 `isSaved/isPublic/isEditable/...` 旗標與內部跳轉的巨型題卡。

沿用專案現有 React 版本與狀態工具；本計畫不要求升級 React、不新增通用事件匯流排、外掛框架或通用 CRUD 層。每次抽取以確實存在的兩個以上使用情境或清楚的責任邊界為依據，先保留原題行為，再接 saved 與外部閱讀。

### 14.7 分層對應驗收

| 問題／風險 | 應驗證的分層行為 |
|---|---|
| 存入後消失 | saved 識別穩定；個人查詢與權限正確；分類失敗、重登、來源撤權後可找回。 |
| 點篩選跳到別頁 | scope 只換同頁資料；路由跳轉只出現在明確導航動作。 |
| 筆記收合高度跑掉 | 收合不覆寫展開尺寸；卸載再掛載、旋轉裝置後筆跡位置與可見範圍正確。 |
| 快速捲動遺失未存筆跡 | 作業控制器在卡片卸載後仍完成儲存或保留可恢復草稿。 |
| 個人筆記出現在集合 | 內容介接只取得白名單共用層；私人作業不進集合讀取結果。 |
| 切換集合／帳號後出現前一份內容 | scope／帳號隔離及過期回應丟棄有效；題卡 key 不只依圖片。 |
| 同一原題在不同集合權限不同 | 以集合項目取得內容及星號；從有權集合讀到的狀態不替其他集合授權。 |
| 更新下載內容覆蓋私人訂正 | savedRefId 與私人作業不變；參考內容更新不寫入私人圖層。 |

## 15. 實作順序與完成判定

建議順序，僅規劃：
1. 以 §0.1 答案為已確認規格；核對 §13 補完邊界，鎖定三來源、角色、URL 與返回 checkpoint。
2. 優先排查 BUG-SAVED-01，建立「存入後可找回」驗收基準。
3. 盤點現有 API client／服務，依 §14 定義最小應用介面與 DTO adapters；先接原題，再接 saved，驗證錯誤、重試、帳號隔離與 作業寫入目標。UI 抽取另做，避免把傳輸邏輯留在題卡。
4. 做主導覽、三來源切換與返回 checkpoint；接入共用題卡／作業上下文，驗證 owned、saved、contributing 的連續刷題與搜尋，尤其同圖不同層的隔離。
5. 整理設定管理列表、跨分類批次選取、內建對話框與 switch；管理頁只連向刷題的共用書寫，角色／訂閱標籤分開顯示。
6. 接延伸題目及單集搜尋，使用唯讀題卡組合，落實四操作與星號持久化。
7. 接總覽動態入口與獨立公開探索，確認未搜尋即有公開題、私人內容不進探索。
8. 補分類任務、舊連結相容及實機驗收，才視為整體改版完成。只有具體功能缺少持久欄位／索引時才另提 migration，不為前端抽象預先重建 schema。

以同一套資料跑完整路徑：
總覽探索 → 選集合並訂閱 → 延伸題目看圖／標星／存入 → 刷題 saved 訂正 → 個人搜尋找到同一版本；
刷題 owned → 加入共用集 → 設定管理可見 → 刷題／搜尋 contributing 選集，各寫自己的共用層；
觀看權撤銷 → 來源停止服務 → 已存版本與私人訂正保留。

交付時逐項標示：已完成／待查／未實作。路由名稱、模型欄位、暫時能打開的舊頁面不能代替流程驗收。
