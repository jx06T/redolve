# 個人 AI 分析：規劃符合性與修正紀錄

日期：2026-11-01。分支：`codex/personal-analysis-foundation`。

本次依使用者畫面回饋、React 錯誤堆疊及產品規劃修正。辨識維持手動重試；原題抽題、作答紀錄、統計、AI 解讀、引用與建議練習已具備可操作的第一版主要流程。發布設定、個人真實資料／iPad 實機驗收仍須依發布流程處理。

## 1. 使用者指定的介面修正

- 題目右上工具列最前方加入辨識圖示，位於複製按鈕前；移除題目上方常駐的辨識大區塊。
- 點擊開啟彈窗，集中顯示原作答、正解、確認狀態、修改表單、重新辨識預覽及重作紀錄。
- 缺題文、未完成結構化辨識、未知題型、選項不足、缺正解、本人上傳題缺原作答，或讀取失敗時顯示低飽和紅點。
- `ai` 本身不代表辨識失敗；存入題缺本人原作答是正常情境，不因這一項顯示紅點。錯因可空，不因空白標紅。
- 紅點表示有資料需留意，不阻止整題 confirmed，也不使題目必然被所有分析排除；分析按各判斷的可用依據降級。
- 只對目前作用中的個人題目讀取缺漏狀態；使用者明確開啟其他題目的彈窗時才讀該題。共享閱讀器與訪客不增加這個個人編輯流程。

## 2. 錯誤與修復依據

使用者提供的主要崩潰是 `Maximum update depth exceeded`，堆疊指向 `QuestionStream.syncActive → setActiveProblemId`。原先 active 題目切換會掛載／卸載大塊辨識 UI，造成高度重新量測與 active 切換互相影響。

修正措施：

1. 辨識入口在工具列維持固定尺寸，內容以 portal 彈窗呈現，不因 active 切換改變卡片高度。
2. active 同步排到下一個 animation frame，避免在 React 的被動 effect 中連鎖寫入 store。
3. 題目邊界量測增加 24px 容忍範圍，避免微小高度變化反覆切換同一邊界兩側的題目。
4. `setActiveProblemId` 對相同 ID 不重複通知；過期 virtual row 不直接索引已移除的題目。
5. 補上標準 `mobile-web-app-capable` meta；檢查工具自身的 `unload` policy 訊息不是本次 React 崩潰原因，未因此放寬權限政策。

| 從舊報告開始建議練習 | 使用該報告保存的科目／單元範圍，再由後端依目前所有權、分類與可用性重新篩選，不套用其他畫面範圍 |
| 手動失敗重試 | AI 失敗有說明及重新產生入口；網路讀取失敗可重新載入報告。沒有新增 Queue 或自動背景重試 |
| 詳細報告 90 天、摘要長期保存 | 沿用到期隱藏及排程清理、刪題／刪帳號清理；舊 JSON 報告仍可顯示原有欄位 |

## 4. AI 輸入、輸出與成本保護

- 統計查詢一次最多 2,000 題、10,000 筆有效期間事件；不截斷後宣稱完整。超過題數時要求縮小單元，不能暗示縮短作答期間會排除舊題。
- AI 使用最多 30 題代表樣本，每題最多帶最近五次有效作答；包含原作答、正解、選項 ID／標示對照、可能錯因與當時判分依據。
- 題文、選項、文字答案與錯因均有長度上限，整體代表題輸入限制 120 KB。不在生成時重掃全部原圖或讀取他人的筆記。
- 模型透過 JSON schema 輸出，伺服器再驗證欄位與引用。相同有效輸入重用報告，過期或失敗可手動重新產生。
- 模型呼叫每次逾時 20 秒、總供應商呼叫最多兩次，SDK 隱藏重試停用；保留基本帳號頻率限制。
- 可在後端設定可選的 `GEMINI_ANALYSIS_MODEL`；空值維持現有預設。沒有加入 Pro 收費或權限判斷。
- 輪詢改為只讀 status／error，完成時才取完整報告；間隔逐步拉長至 8 秒，避免每次搬運題文快照。
- 統計事件改由所選單元與題目走索引探查，避免先掃同帳號所有科目的期間事件。

供應商 schema 實作參考：[Gemini structured outputs](https://ai.google.dev/gemini-api/docs/structured-output)。schema 與引用驗證不能保證解讀內容完全正確，仍使用「可能錯因」並保留原題修正入口。

## 5. 驗證紀錄

- 自動測試涵蓋版本保護、歷史判分、離線事件重送、報告到期／刪除、API 授權及引用驗證。
- 新增模型 API 整合測試：攔截供應商網路，驗證真實 SDK 請求包含輸出 schema，四項解讀可以通過，未知引用被拒絕，相同輸入不重呼叫，失敗可手動重試。
- 另使用既有本地金鑰與純人工合成的集合題實際呼叫 Gemini，成功取得 `gemini-3.1-flash-lite` 的一項有效引用解讀。沒有傳送使用者題庫、筆記或個資。
- 本地 Miniflare 成本回歸：同帳號範圍外事件從 1,000 筆增加至 10,000 筆，所選科目的 metadata＋事件 batch 在同次測試中讀取量相同（多次執行為 41～42 列）。這不包含 taxonomy 查詢、報告讀取或正式環境帳單，也不是全體資料分布的成本保證。
- 瀏覽器以真實 React 元件及模擬 API 驗證：工具列入口、缺漏紅點、彈窗修改確認後移除紅點、50 次連續更新、跨題捲動、既有報告不自動呼叫 AI、手動生成、原題依據及直接開始建議練習。無 React 更新循環。
